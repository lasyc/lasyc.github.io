Java 学习介绍

本系列笔记以 Java 后端开发为主线，内容按以下路径逐步推进，从零基础到能独立完成一个 Web 项目：

  • 基础语法篇：变量与数据类型、运算符、流程控制（分支/循环）、方法、数组
  • 面向对象篇：类与对象、封装、继承、多态、抽象类与接口
  • 常用 API 篇：常用类（String、包装类、日期时间）、集合、异常、IO 流
  • 进阶实战篇：多线程、网络编程、反射与注解，以及 MySQL、JDBC、JavaWeb、SSM/SpringBoot 等后续内容

说明：本篇是入门总览，先建立整体认知即可，具体知识点会在后续各篇笔记中逐一展开。

人机交互-图形化界面的小故事

  1. 最初的计算机并没有图形化的操作界面，人机交互主要依靠命令行：用户在一个只能输入命令的”黑框”（终端）中敲入指令，计算机执行后再把结果显示在屏幕上。
  2. 1973 年，美国施乐公司（Xerox）在帕洛阿尔托研究中心（PARC）研发出了世界上第一款采用图形用户界面（GUI）的计算机 Xerox Alto。它用”窗口 + 图标 + 鼠标”取代了纯命令行交互，这一设计理念后来被 Apple、Microsoft 借鉴，逐渐普及到大众计算机上。
  3. 直到今天，终端（命令行）依然是计算机的重要组成部分，并没有被图形界面完全取代，例如 Windows 中的 CMD（命令提示符）和 PowerShell、Linux 和 macOS 中的 Terminal。在服务器运维、脚本自动化、开发工具链等场景中，命令行的效率往往比鼠标点击更高。

  1. 按 Win + R 打开”运行”对话框
  2. 输入 cmd，按回车（或点击确定）即可打开命令提示符窗口

练习-利用 CMD 打开 QQ 并配置环境变量

利用 CMD 打开 QQ

  1. 找到 QQ 的安装目录，如 C:\\Program Files (x86)\\Tencent\\QQ
  2. 打开 CMD 并进入 QQ 的安装目录，cd C:\\Program Files (x86)\\Tencent\\QQ
  3. 在命令行中输入 QQ.exe 并回车，即可启动 QQ

配置环境变量

在上面的案例中，必须先 cd 进入 QQ 的安装目录才能运行 QQ.exe，否则系统会提示”不是内部或外部命令”。

如果希望在任意目录下都能直接运行 QQ.exe，就需要配置环境变量：把 QQ 的安装目录（如 C:\Program Files (x86)\Tencent\QQ）添加到环境变量 Path 中。原理是：当在命令行中输入一个命令（如 QQ.exe）时，系统会依次到 Path 记录的各个目录中查找该程序，找到后便直接执行。后文 Java 配置 JAVA_HOME 与 Path 用的也正是这个原理。

如何配置环境变量

  1. 右键此电脑 → 选择属性
  2. 选择高级系统设置 → 点击环境变量
  3. 建议在用户变量中找到 Path，点击编辑（修改用户变量无需管理员权限；若选择在系统变量中修改则可能需要管理员权限）
  4. 点击新建，在 Path 中添加 C:\\Program Files (x86)\\Tencent\\QQ，点击确定保存

Java 概述和学习方法

Java 是什么

Java 是一门面向对象、跨平台、可移植的高级编程语言。它被广泛应用于桌面应用、企业级后端系统、Web 开发、Android 应用开发、大数据等领域。

Java 的核心特点包括：

  • 面向对象：通过类和对象来组织代码
  • 跨平台：一次编写，到处运行
  • 安全性：强类型检查、异常处理机制
  • 可扩展性：适合大型项目和团队协作

学习方法建议

  • 先掌握基础语法：变量、运算符、分支、循环
  • 再理解面向对象：类、对象、封装、继承、多态
  • 最后学习常用技术：集合、IO、异常、线程、Web 开发

JDK 下载和安装

安装步骤

JDK 下载（可结合课程内容选择 JDK 8 或更新的长期支持版本）

  1. 双击安装包（Windows 下为 .exe，注意与系统位数一致，现在一般选 64 位）
  2. 按向导点击”下一步”，在”安装到”页面可修改安装路径，建议使用默认路径，路径中不要包含中文和空格，避免后续编译或配置出现编码类问题
  3. 等待安装完成即可（新版安装程序默认会顺手配置好 Path，详见下文”为什么安装 JDK 后不需要配置环境变量”）

提示：不同大版本（如 8、11、17、21）的 JDK 目录结构略有差异，下表以较新版本为例并标注差异。

安装目录

文件夹名 文件描述
bin 存放可执行文件，如 java、javac、jshell 等命令行工具
include 存放本地方法（JNI）开发所需的 C/C++ 头文件

说明：JDK 8 及更早的版本中没有 conf、jmods 目录（当时尚未模块化）；若确实需要精简的运行时，可用 jlink 工具裁剪生成。

HelloWorld 小案例

  1. 用记事本创建一个 HelloWorld.java 文件

  2. 编写代码

  3. 打开 CMD，进入 HelloWorld.java 文件所在目录

  4. 使用 javac HelloWorld.java 编译文件，生成 HelloWorld.class 文件

  5. 使用 java HelloWorld 运行文件

小提示：

  • javac 负责把 .java 源码编译成 JVM 能识别的字节码文件 .class；java 负责启动 JVM 并运行编译好的类，运行时不要加 .class 后缀。
  • 源码文件请按 UTF-8 编码保存，用记事本保存时注意在”另存为”中选择 UTF-8 编码，否则中文注释可能乱码或编译报错。

常见小问题

  1. 代码中的符号（括号、分号、引号、点号等）必须使用英文半角符号，中文全角符号会导致编译报错
  2. Java 严格区分大小写，HelloWorld 与 helloworld 是两个不同的名字
  3. 一个 .java 源文件中最多只能有一个 public 类，且该类的类名必须与文件名完全一致
  4. 程序入口 main 方法的写法是固定的：public static void main(String[] args)，写错程序将无法运行

环境变量

为什么安装 JDK 后不需要配置环境变量

使用安装版（.exe）安装 JDK 时，安装程序默认会把 JDK 的 bin 目录加入 Path，因此安装完成后即可在任意目录下直接使用 java、javac、jshell 等命令，无需手动配置。

如果使用的是免安装压缩包（.zip）方式，或者希望 Maven、Tomcat、IDEA 等软件能自动定位 JDK，则需要手动配置 JAVA_HOME，步骤如下。

手动配置环境变量（以 JDK 8 为例）

  1. 右键此电脑 → 属性 → 高级系统设置 → 环境变量
  2. 新建系统变量：变量名填写 JAVA_HOME（习惯上全大写），变量值填写 JDK 的安装根目录，例如 C:\Program Files\Java\jdk1.8.0_281（不要带上 bin）
  3. 在系统变量中找到 Path，点击编辑 → 新建，追加一行 %JAVA_HOME%\bin，然后一路点击确定保存
  4. 重新打开一个 CMD，输入 java -version 验证是否配置成功

提示：

  • JAVA_HOME 只是一个约定俗成的变量名，系统并不会直接使用它，但 Tomcat、Maven、IDEA 等软件会读取它来定位 JDK，因此建议统一配置。
  • 环境变量修改后，已经打开的命令行窗口不会立即生效，需要重新打开一个新的 CMD 窗口。

Notepad++

Notepad++ 是一款免费开源的文本编辑器，支持语法高亮、多标签页等功能，是初学阶段常用的代码编写工具。用它编写 .java 文件时注意：

  • 通过菜单编码确认文件使用 UTF-8（无 BOM）编码，避免中文乱码
  • 它会自动高亮 Java 关键字与字符串，方便初学者检查语法是否写错

说明：后续学习建议换用 IDEA 或 Eclipse 等集成开发环境（IDE），它们内置编译运行、代码提示、断点调试等功能。不过初学阶段先用编辑器 + 命令行，能更清楚地理解”编译 → 运行”的完整过程。

Java 语言的发展

  • 1991 年，Sun 公司的詹姆斯·高斯林（James Gosling）团队启动代号为 Oak（橡树）的项目，最初为嵌入式消费电子产品设计，后因互联网兴起转向网络应用
  • 1995 年，Oak 正式更名为 Java 并对外发布，口号”一次编写，到处运行”（Write Once, Run Anywhere）从此深入人心
  • 1996 年，发布 JDK 1.0，Java 开始进入企业级应用领域
  • 2004 年，发布 Java 5（内部版本 1.5）：新增泛型、枚举、注解、自动装箱/拆箱、增强 for 循环等特性，是语言发展的重要里程碑
  • 2006 年，Java 6 发布，同年 Sun 将 JDK 开源为 OpenJDK 项目
  • 2009 年，Oracle（甲骨文）收购 Sun 公司，Java 改由 Oracle 主导维护
  • 2014 年，发布 Java 8：新增 Lambda 表达式、Stream 流式 API、全新的日期时间 API（java.time）、接口默认方法等，是目前企业中使用最广的版本之一
  • 2017 年起，Oracle 改为每半年发布一个大版本（9、10、11……），同时大约每三年推出一个长期支持版本（LTS）
  • 2018 年，发布 Java 11（LTS）；2021 年发布 Java 17（LTS）
  • 2024 年，发布 Java 21（LTS），是近几年企业升级的主流目标版本
  • 2025 年，发布 Java 25（LTS）

截至 2026 年，常见的长期支持版本为 8、11、17、21、25。学习建议优先选择 LTS 版本，资料与第三方框架的兼容性都更有保障。

Java 能干什么

  1. Java SE（Standard Edition，标准版）：Java 的核心与基础，包含语法和基础类库（集合、IO、多线程等），也是桌面应用开发的基础。学习 Java 首先从 SE 入手
  2. Java ME（Micro Edition，微型版）：早期用于手机、嵌入式等小型设备。如今随着 Android 采用 Java 技术栈，Java ME 已很少单独使用
  3. Java EE（Enterprise Edition，企业版）：面向企业级 Web 应用，提供 Servlet、JSP、JPA 等规范。2018 年起移交 Eclipse 基金会并更名为 Jakarta EE。后续要学习的 JavaWeb、SSM、SpringBoot 都属于这一方向

Java 为什么这么火

Java 之所以长期受到欢迎，主要有以下几个原因：

  1. 生态成熟：Java 拥有丰富的开源框架和开发工具。
  2. 跨平台能力强：JVM 让 Java 程序具备较好的可移植性。
  3. 企业级应用广泛：很多大型企业、银行、政府系统都在使用 Java。
  4. 语言稳定：Java 版本迭代稳定，社区成熟，学习资源丰富。
  5. 适合长期开发：适合做后端服务、分布式系统和大规模项目。

Java 跨平台的原理

Java 程序并不是直接运行在操作系统上的，而是在 Java 虚拟机（JVM）上运行。Java 虚拟机是一个中间层，它将 Java 程序与操作系统隔离开来。针对不同的操作系统，都有相应的 JVM 实现，它们可以执行相同的 Java 字节码（.class 文件）。因此，同一个 Java 程序可以在不同的操作系统上运行，实现了“一次编写，到处运行”的特性。

注意：”跨平台”指的是 Java 程序（.class 字节码） 可以跨平台运行，而 JVM 本身并不跨平台——Windows 需要安装 Windows 版的 JVM，Linux 需要 Linux 版的 JVM。Java 正是通过”在不同操作系统上提供对应版本的 JVM”来屏蔽底层差异的。

JRE 和 JDK

  • JRE（Java Runtime Environment，Java 运行时环境）：包含 JVM、核心类库等运行 Java 程序所需的全部组件。在 JDK 8 及更早的版本中，JRE 会独立提供给普通用户——只运行 Java 程序、不参与开发的人安装 JRE 即可
  • JDK（Java Development Kit，Java 开发工具包）：面向开发人员，包含早期版本中的 JRE、编译器 javac 以及各种调试与开发工具，可以在 Windows、Linux、macOS 等系统上开发 Java 程序

注意：JDK 9 起官方不再单独发布面向普通用户的 JRE 安装包，运行 Java 程序通常直接安装 JDK 即可。早期版本中三者的包含关系可记为：JDK ⊇ JRE ⊇ JVM。

异常异常是程序运行时出现的错误。当异常发生时，会终止程序的运行，并抛出一个异常对象。异常是不可避免的，我们无法完全消除异常，只能正确地处理异常，让程序在出错时也能友好地提示、或安全地结束。 异常体系Throwable 是 Java 语言中所有异常的父类，子类有：Error、Exception。 Error 是错误，属于系统层面的错误（比如内存溢出），通常不是我们程序员需要处理的。 Exception 才是异常，是程序员需要处理的。异常共分为两大类，分别是：运行时异常和编译时异常。 运行时异常运行时异常：RuntimeException 及其子类，是在运行时（程序执行过程中）才出现的异常，比如：空指针异常、数组越界异常、类型转换异常等等。这类异常在开发中往往是无法预见的（比如数组越界要到运行到那一行才知道），编译器也无法检测到这些异常，所以不会提醒我们处理。 编译时异常编译时异常：Exception 中除 RuntimeException 以外的所有异常类，是在编译时（写代码、编译阶段）就会被编译器检查出来的异常，比如：文件不存在异常、类不存在异常、日期格式不对异常等等。这类异常在...
