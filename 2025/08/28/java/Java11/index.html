API 和 API 文档

API（Application Programming Interface，应用程序编程接口）可以理解成别人已经封装好的一套”功能清单”：它提供了许多现成类和方法，告诉我们每个类/方法能做什么、参数怎么传、返回什么，我们直接调用即可，不必关心内部实现。通过查阅官方 API 文档，可以了解 Java 自带类库的完整功能与用法。

String 概述

String 是引用数据类型，所以 String 对象通常需要通过 new 关键字创建，例如：String str = new String("hello world");。不过我们之前常见的写法是 String str = "hello world";，这是因为 Java 对字符串做了优化处理。

String 对象的值是 不可修改 的。即使执行 str = "abc";，也只是让变量指向了一个新的字符串对象，并没有修改原字符串本身。

直接赋值

当我们用直接赋值的方式创建字符串时，JVM 会先检查字符串常量池中是否已存在相同内容的字符串。如果存在，就直接返回常量池中该字符串的引用（两个变量指向同一个对象）；如果不存在，就在常量池中创建新的字符串对象并返回引用。

补充：在 JDK 7 及以后，字符串常量池位于堆中。使用 new 创建字符串时不会复用常量池中已有的对象，每次 new 都会在堆中新建一个字符串对象。

new 关键字

只要是通过 new 关键字创建的对象，就会在堆中创建一个新的字符串对象。

字符串的比较

== 和 equals

对于 基本数据类型，== 比较的是真实的值；而对于 引用数据类型，== 比较的是地址值。所以 String 类提供了 equals 和 equalsIgnoreCase 方法，用来比较两个字符串的内容是否一致。

StringBuilder 的基本操作

String 的内容一旦创建就不可变，每次用 + 拼接/修改都会产生新的字符串对象，频繁操作时效率较低。StringBuilder 则是一个可变的字符序列：它内部维护一个字符数组，拼接、插入、删除等操作都在原对象上直接修改，效率更高（原理见下文”底层原理”部分）。

注意：StringBuilder 属于 java.lang 包，无需手动 import 即可使用。

字符串相关类的底层原理

字符串存储的内存原理

  • 通过直接赋值创建的字符串会优先检查字符串常量池是否存在该字符串，有则复用，无则创建新的字符串对象
  • 通过 new 关键字创建的字符串对象会在堆内存中分配空间，不会使用字符串常量池

== 号比较的是什么

  • == 对于基本数据类型比较的是值
  • == 对于引用数据类型比较的是地址值，字符串之间比较应使用 equals() 方法

字符串拼接的底层原理

  • 字符串在拼接时会做一些优化，如 String str = "a" + "b" 会被优化为 String str = "ab"
  • 若右侧的字符串拼接有其他变量参与，则会创建新的字符串，不会优化

StringBuilder 扩容原理

  • StringBuilder 内部用一个字符数组存放内容，默认初始容量为 16。当字符数量超过当前容量时自动扩容，新容量 = 旧容量 × 2 + 2，并把原内容复制到新数组。
  • 如果某次要追加的内容特别多、超过”扩容后”的容量，并不会分多次扩容，而是直接以”现有内容长度 + 本次追加长度”为基准，一次扩容到刚好够用。

需求：键盘录入一串数字（如 123），把每一位数字转换成对应的罗马数字并拼接输出（0 不输出、1→Ⅰ、2→Ⅱ……9→Ⅸ）。要求输入必须全是数字，否则提示重新输入。

提示：需要 import java.util.Scanner;。字符 ‘0’ 的 ASCII 码是 48，所以 c - 48 可以把字符 ‘0’‘9’ 转成对应的数字 09。

练习-调整字符串

需求：键盘录入两个字符串，判断第一个字符串能否通过”每次把首位字符移到末尾”的旋转操作变成第二个字符串。例如 abcde 旋转一次变成 bcdea，旋转两次变成 cdeab……只要存在某次旋转结果与目标相同，就返回 true。

提示：需要 import java.util.Scanner;。字符串长度相同才可能相等；旋转 n 次会回到原串，所以最多比较 n 次即可。

练习-打乱字符串

需求：键盘录入一个字符串，把其中的字符随机打乱顺序后输出（每次运行结果都不同）。

提示：需要 import java.util.Scanner; 和 import java.util.Random;。思路：先把字符串转成字符数组，再遍历每个位置，让该位置与数组内一个随机位置（可以是它自己）交换，相当于”洗牌”。
