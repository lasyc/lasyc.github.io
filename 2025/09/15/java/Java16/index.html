对象克隆

克隆

  1. 浅克隆：复制对象时，基本数据类型的属性会复制一份值，但引用数据类型的属性只复制引用地址。这样一来，两个对象的引用类型属性指向同一个对象，其中一个修改了该属性的内容，另一个也会跟着变。
  2. 深克隆：在浅克隆的基础上，对引用数据类型的属性不再复制地址，而是创建一个新对象，把原对象的属性值逐一复制进去。这样两个对象的引用类型属性互不影响，避免了浅克隆的问题。

存储原理

BigInteger 的底层是一个名为 mag 的 int 数组：保存数值时，先把数值转成二进制补码，再按每 32 位一组划分，最后转成十进制存入数组中；同时用一个 signum 字段表示大整数的符号，取值 -1、0、1，分别代表负数、零、正数。理论上 BigInteger 能表示的数值有上限（取决于数组长度和内存），但这个上限非常大，日常使用可以认为是无限的。

存储原理

BigDecimal 的底层是一个 int 数组：存储小数时，把字符串中的每个字符按 ASCII 码转成对应的十进制数存进数组，再用一个 scale 字段表示小数点的位置（即小数位数）。它直接按十进制逐位存储与运算，避免了二进制浮点数的精度问题，所以能精确地表示和计算小数。

Calendar

虽然 Date 类已经提供了不少方法，但要处理”某个时间的前一天/后一天、前一月/后一月”这类需求仍然很繁琐，Calendar 类把这些操作封装成了方法，用起来方便很多。

Calendar 是一个抽象类，不能直接 new，需要通过静态方法 getInstance() 获取它的对象。相比 Date，Calendar 功能更强大：可以按字段（年、月、日、时、分、秒……）分别设置或获取时间，也可以用 add 直接对某个字段做加减。

Duration、Period、ChronoUnit

这三个类都用来计算两个时间点之间的间隔，但侧重点不同：

  • Duration：计算两个”时间”之间的间隔，但只能精确到秒和纳秒，适合算时分秒这种小于一天的间隔；
  • Period：计算两个”日期”之间的间隔，可以按年、月、日统计，适合算年龄；
  • ChronoUnit：时间单位的枚举，可以按年、月、日、时、分、秒、纳秒等任意单位，计算两个时间之间的差值。
