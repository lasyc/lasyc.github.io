异常

异常是程序运行时出现的错误。当异常发生时，会终止程序的运行，并抛出一个异常对象。异常是不可避免的，我们无法完全消除异常，只能正确地处理异常，让程序在出错时也能友好地提示、或安全地结束。

异常体系

Throwable 是 Java 语言中所有异常的父类，子类有：Error、Exception。

Error 是错误，属于系统层面的错误（比如内存溢出），通常不是我们程序员需要处理的。

Exception 才是异常，是程序员需要处理的。异常共分为两大类，分别是：运行时异常和编译时异常。

运行时异常

运行时异常：RuntimeException 及其子类，是在运行时（程序执行过程中）才出现的异常，比如：空指针异常、数组越界异常、类型转换异常等等。这类异常在开发中往往是无法预见的（比如数组越界要到运行到那一行才知道），编译器也无法检测到这些异常，所以不会提醒我们处理。

编译时异常

编译时异常：Exception 中除 RuntimeException 以外的所有异常类，是在编译时（写代码、编译阶段）就会被编译器检查出来的异常，比如：文件不存在异常、类不存在异常、日期格式不对异常等等。这类异常在开发中是可以预见的（能不能出现，从代码就能分析出来），编译器会检查这些异常——如果这些异常可能会出现，编译器会报错，提醒我们处理。

补充：编译时异常也叫”受检异常 / checked exception”，因为编译器会强制检查、要求必须处理；运行时异常也叫”非受检异常 / unchecked exception”。

异常的处理

JVM 默认处理

如果我们什么都不做，那么 JVM 会这样处理异常：将异常信息打印在控制台，并终止程序运行。

try-catch

我们可以使用 try-catch 来自己处理异常。当 try 中的代码发生异常时，会自动将异常对象传递给 catch；此时 catch 中的代码就会执行，且不会终止程序运行，后续代码会继续执行。

注意事项

  1. catch 的参数是一个异常对象，这个异常对象的类型必须和 try 中发生的异常类型一致，或者是它的父类。否则当异常发生时，不会被捕获。
  2. 若 try 中没有异常发生，则 catch 中的代码不会执行。
  3. 若 try 中可能发生多种异常，那么可以写多个 catch 块来处理不同的异常，也可以在一个 catch 块中处理多个异常——多个异常类型之间用 | 分隔开（如第 4 点中的代码）。
  4. 多个 catch 块从上往下匹配，一旦某个 catch 捕获到异常，后面的 catch 块就不会再执行；所以子类异常要写在前面，父类异常写在后面（如果把 Exception 写在第一个，后面的子类异常块就永远没有机会执行）。

抛出异常

先区分两个关键字：

  • throws：写在方法声明上，表示”当前方法可能会抛出指定的异常”。当别人调用该方法时，调用者必须对抛出的异常进行处理（要么 try-catch 捕获，要么继续往上 throws）。
  • throw：写在方法体内部，表示”当前方法主动抛出一个异常对象”。一旦执行了 throw，方法会立即结束，异常会传递给调用者。
