IO 流

IO 流是 Java 中用于处理输入和输出操作的核心概念。Java 提供了丰富的 IO 类库，支持文件操作、网络通信等多种场景。

分类

IO 流可以从两个维度分类：

  • 按照流的方向：输入流和输出流。输入流用于读取数据（从文件等数据源读进来），输出流用于写入数据（写到文件等目标去）。
  • 按照流的数据类型：字节流和字符流。字节流可以处理所有类型的数据，而字符流专门用于处理文本数据。

字节流

字节流是 Java 中用于处理字节数据的流。字节流可以处理所有类型的数据，如图片、音频、视频、文本等（一切数据在计算机底层都是字节），并提供了一系列方法用于读取、写入字节数据。

字节流有两个顶层接口：InputStream 和 OutputStream。InputStream 用于读取字节数据，OutputStream 用于写入字节数据。但是我们不需要直接使用这两个接口，而是使用它们的子类，分别是：FileInputStream（文件字节输入流）和 FileOutputStream（文件字节输出流）。

乱码

在使用字节流去读取文本文件内容时，容易出现乱码的问题，因为字节流只认字节，无法处理字符编码问题。

为什么会乱码？因为有些字符在不同的编码下，占用的字节数不同。比如中文，在 UTF-8 编码下占用 3 个字节，而在 GBK 编码下只占用 2 个字节。如果读取字节时”截断”了（没有一次读够一个完整字符的全部字节），解码就会出错，显示成乱码。

举个例子：假设文件中有一个汉字你，它的 UTF-8 编码对应的三个字节是 228 189 160（十进制）。也就是说，读取时必须把这三个字节一次全部读出来，才能正确解码成你字。如果我们每次只读取 2 个字节（228 189、160），就把一个完整的字符拆散了，系统无法识别，就会出现乱码或显示不正确的字符。

补充：UTF-8 是 Unicode 的一种变长编码，它使用 1~4 个字节来表示一个字符。

字符流

字符流的底层其实就是字节流，但它在此基础上解决了字符编码和解码的问题。字符流专门用于处理文本数据，能够自动完成字符和字节之间的转换。

字符流同样有两个顶层接口：Reader 和 Writer。Reader 用于读取字符数据，Writer 用于写入字符数据。但我们不需要直接使用这两个接口，而是使用它们的子类，分别是：FileReader（文件字符输入流）和 FileWriter（文件字符输出流）。

字符流原理

在创建字符流对象时，底层会创建一个大小约为 8KB 的缓冲区。当我们调用字符流的 read 或 write 方法时，实际上是先将数据读入缓冲区或写入缓冲区，等缓冲区满时，才会真正去操作文件。

读取数据的过程：如果缓冲区为空，会先从文件中读取一批数据到缓冲区，然后依次从缓冲区中取出数据；当缓冲区的数据被读取完后，才会再次从文件读取。新读取的数据会覆盖缓冲区中的旧数据，但如果新数据的长度小于缓冲区大小，缓冲区里就会残留上一次的部分数据，所以在读取时要注意按实际读取的长度来处理。

当文件内容被加载到缓冲区后，即使文件被删除或内容被修改，字符流仍能通过缓冲区获取文件数据（这也是读取时要小心的地方）。

写入数据的过程：调用 write 时，其实是先把内容添加到缓冲区，只有当满足下面三个条件之一时，数据才会真正写入文件：

  1. 缓冲区满了；
  2. 调用了 flush 方法；
  3. 调用了 close 方法。

缓冲流

前边学习了字节流和字符流，一共四个类：FileInputStream、FileOutputStream、FileReader 和 FileWriter。这四个类直接操作文件，读写效率较低、功能也比较欠缺。为了提高读写效率，Java 提供了缓冲流。缓冲流在字节流/字符流的基础上增加了一个缓冲区，读写数据时，先把数据读到缓冲区或写到缓冲区，攒够一批再真正操作文件，从而减少和磁盘的交互次数，提升效率。缓冲流也有四个类：BufferedInputStream、BufferedOutputStream、BufferedReader 和 BufferedWriter。

缓冲流并不是一种新的底层流，而是对已有流的”包装”。使用缓冲流时，需要把已有的基本流对象作为参数传入缓冲流的构造方法中。

补充：虽然字符流内部也带有缓冲区，但缓冲流的缓冲区大小可以自定义，而且缓冲流还额外提供了更方便的读写方式（如 readLine()），综合下来效率还是有提升的。

转换流

转换流属于字符流（继承自 Reader/Writer），作用是在字节流和字符流之间搭一座桥：把字节流包装成字符流，从而可以指定字符集来读写文本。转换流属于高级流，用来包装基本流。转换流有两个类：InputStreamReader（字节输入流转字符输入流）和 OutputStreamWriter（字符输出流转字节输出流）。

补充：JDK 11 之后，FileReader 和 FileWriter 的构造方法里也可以直接指定字符集，所以”读取文件”这种场景不一定要用转换流了；但在其他场景下（比如把一个网络输入流、内存字节流按指定编码转成字符流），转换流依然有它的价值。

序列化流

序列化流是字节流（高级流，用于包装基本流），它是 Java 对象和字节之间的桥梁：把 Java 对象转换成字节（写文件，叫序列化），或者把字节转换成 Java 对象（读回来，叫反序列化）。序列化流有两个类：ObjectOutputStream（写对象）和 ObjectInputStream（读对象）。

使用序列化流操作 Java 对象时，必须保证对象是可序列化的：类必须实现 Serializable 接口。

如果不想让某个属性参与序列化（比如密码、临时数据），可以在该属性声明时加上 transient 关键字，序列化时会跳过它。

打印流

打印流是 Java 内置的、专门用来”输出数据”的流，一般配合文件使用。它只能用于输出数据，不能用于输入数据。打印流有两个类：PrintStream（字节打印流）和 PrintWriter（字符打印流）。

打印流最大的特点是：打印方法不会抛 IOException（内部自己处理了），写起来很方便。

压缩流

压缩流是字节流，用于对数据进行压缩和解压缩，属于高级流，用来包装基本流。压缩流有两个类：ZipOutputStream（把数据压缩成 zip）和 ZipInputStream（把 zip 解压出来）。压缩流只适用于扩展名为 zip 格式的文件。

除了 Zip... 系列流，还有 GZIP... 系列流（如 GZIPInputStream、GZIPOutputStream），用于对数据进行 GZIP 格式的压缩和解压缩。
