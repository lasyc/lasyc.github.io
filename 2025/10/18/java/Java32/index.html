IO 流

IO 流是 Java 中用于处理输入和输出操作的核心概念。Java 提供了丰富的 IO 类库，支持文件操作、网络通信等多种场景。

分类

IO 流可以从两个维度分类：

  • 按照流的方向：输入流和输出流。输入流用于读取数据（从文件等数据源读进来），输出流用于写入数据（写到文件等目标去）。
  • 按照流的数据类型：字节流和字符流。字节流可以处理所有类型的数据，而字符流专门用于处理文本数据。

字节流

字节流是 Java 中用于处理字节数据的流。字节流可以处理所有类型的数据，如图片、音频、视频、文本等（一切数据在计算机底层都是字节），并提供了一系列方法用于读取、写入字节数据。

字节流有两个顶层接口：InputStream 和 OutputStream。InputStream 用于读取字节数据，OutputStream 用于写入字节数据。但是我们不需要直接使用这两个接口，而是使用它们的子类，分别是：FileInputStream（文件字节输入流）和 FileOutputStream（文件字节输出流）。

乱码

在使用字节流去读取文本文件内容时，容易出现乱码的问题，因为字节流只认字节，无法处理字符编码问题。

为什么会乱码？因为有些字符在不同的编码下，占用的字节数不同。比如中文，在 UTF-8 编码下占用 3 个字节，而在 GBK 编码下只占用 2 个字节。如果读取字节时”截断”了（没有一次读够一个完整字符的全部字节），解码就会出错，显示成乱码。

举个例子：假设文件中有一个汉字你，它的 UTF-8 编码对应的三个字节是 228 189 160（十进制）。也就是说，读取时必须把这三个字节一次全部读出来，才能正确解码成你字。如果我们每次只读取 2 个字节（228 189、160），就把一个完整的字符拆散了，系统无法识别，就会出现乱码或显示不正确的字符。

补充：UTF-8 是 Unicode 的一种变长编码，它使用 1~4 个字节来表示一个字符。

字符流

字符流的底层其实就是字节流，但它在此基础上解决了字符编码和解码的问题。字符流专门用于处理文本数据，能够自动完成字符和字节之间的转换。

字符流同样有两个顶层接口：Reader 和 Writer。Reader 用于读取字符数据，Writer 用于写入字符数据。但我们不需要直接使用这两个接口，而是使用它们的子类，分别是：FileReader（文件字符输入流）和 FileWriter（文件字符输出流）。

字符流原理

在创建字符流对象时，底层会创建一个大小约为 8KB 的缓冲区。当我们调用字符流的 read 或 write 方法时，实际上是先将数据读入缓冲区或写入缓冲区，等缓冲区满时，才会真正去操作文件。

读取数据的过程：如果缓冲区为空，会先从文件中读取一批数据到缓冲区，然后依次从缓冲区中取出数据；当缓冲区的数据被读取完后，才会再次从文件读取。新读取的数据会覆盖缓冲区中的旧数据，但如果新数据的长度小于缓冲区大小，缓冲区里就会残留上一次的部分数据，所以在读取时要注意按实际读取的长度来处理。

当文件内容被加载到缓冲区后，即使文件被删除或内容被修改，字符流仍能通过缓冲区获取文件数据（这也是读取时要小心的地方）。

写入数据的过程：调用 write 时，其实是先把内容添加到缓冲区，只有当满足下面三个条件之一时，数据才会真正写入文件：

  1. 缓冲区满了；
  2. 调用了 flush 方法；
  3. 调用了 close 方法。
