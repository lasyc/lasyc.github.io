发表于2025-10-22|更新于2026-09-06

多线程

线程是程序执行的最小单位，是进程中的一条执行路径。Java 语言内置了对多线程编程的支持，使得我们可以轻松地创建和管理线程，从而实现并发执行任务，提高程序的性能和响应能力。

并发和并行

并发：在单个处理器上，通过时间片轮转等方式让多个线程交替执行，看起来像”同时”在运行。
并行：在多处理器（多核）系统上，多个线程真正地同时执行。

实现方式

在 Java 中，创建多线程主要有三种方式：继承 Thread 类、实现 Runnable 接口、实现 Callable 接口，下面分别介绍。

继承 Thread 类

Thread 类是 Java 中用于创建和管理线程的核心类。通过继承 Thread 类，可以创建自定义的线程类，并重写它的 run() 方法来定义线程要执行的任务。

注意：启动线程时，不要直接调用 run() 方法（那样只是在当前线程里执行一段普通方法），而是要调用 start() 方法来启动线程（start() 会开启一条新线程，由新线程去执行 run() 中的代码）。

实现 Runnable 接口

Runnable 接口是另一种创建线程的方式。通过实现 Runnable 接口，可以把”线程任务”和”线程本身”分离开：同一个 Runnable 对象可以被多个线程共享。实现 Runnable 接口需要重写 run() 方法，然后把 Runnable 对象传给 Thread 类的构造函数来创建线程。

实现 Callable 接口

Callable 接口是 Java 5 引入的第三种创建线程的方式。与 Runnable 不同，Callable 的 call() 方法可以返回结果，并且可以抛出异常。用法：实现 Callable 接口并重写 call() 方法，把 Callable 对象交给 FutureTask 类包装，再把 FutureTask 对象交给 Thread 类来创建线程（因为 Thread 只认 Runnable，而 FutureTask 实现了 Runnable）。

提示：Callable、FutureTask 在 java.util.concurrent 包中，需要 import java.util.concurrent.Callable; 和 import java.util.concurrent.FutureTask;。

线程优先级

线程优先级是指线程在 CPU 调度中的优先级别。Java 中的线程优先级范围是 1~10，数值越大优先级越高，默认优先级为 5。可以通过 setPriority() 方法设置线程的优先级，通过 getPriority() 方法获取。

注意：线程优先级只是给操作系统调度器的一个”建议”，并不保证高优先级的线程一定先执行，具体调度行为取决于操作系统的实现。

守护线程

守护线程是一种特殊的线程，它的生命周期依赖于其他非守护线程（用户线程）：当所有非守护线程都结束时，JVM 会自动终止所有守护线程。守护线程通常用于执行后台任务，如垃圾回收、日志记录等。可以通过 setDaemon(true) 方法把线程设置为守护线程（要在 start() 之前设置才有效）。

礼让线程

礼让线程是指在多线程环境中，某个线程主动放弃当前 CPU 的使用权，让其他线程有机会执行。可以通过调用 Thread.yield() 方法来实现。

注意：yield() 只是把线程从”运行中”临时让出来、回到”就绪”状态，并不保证其他线程一定会被调度到，具体行为取决于操作系统的线程调度策略。

插队线程

插队线程（join）是指：某个线程通过调用 Thread.join() 方法，等待另一个线程执行完毕后再继续执行。这样可以协调线程的执行顺序。

线程的生命周期

线程的生命周期包括以下几个状态：

  1. 新建状态（New）：线程对象已经被创建，但还没有调用 start()，此时线程还没有真正开始运行
  2. 就绪状态（Runnable）：已经调用 start()，线程在等待 CPU 调度执行
    • 被 CPU 调度到后，线程进入运行状态
  3. 运行状态（Running）：线程正在执行自己的任务代码
    • 任务执行完毕后，进入终止状态
    • CPU 时间片用完被抢走时，回到就绪状态
    • 运行中调用 sleep()、wait()、join() 等方法时，会暂停下来，进入对应的等待状态（见第 5、6 点）
  4. 阻塞状态（Blocked）：线程想进入 synchronized 代码块，但锁被其他线程占着，只能等待
    • 等到锁被释放、自己拿到锁后，恢复到就绪状态
  5. 等待状态（Waiting）：线程无限期地等待另一个线程的通知
    • 通过 wait()（不带时间）、join()（不带时间）进入
    • 被 notify() / notifyAll() 唤醒、或等待的线程结束后，恢复到就绪状态
  6. 超时等待状态（Timed Waiting）：线程等待指定的一段时间，时间到了会自动恢复
    • 通过 sleep(毫秒)、wait(毫秒)、join(毫秒) 进入
    • 时间一到（或中途被唤醒），恢复到就绪状态
  7. 终止状态（Terminated）：线程执行完毕（run() 正常结束，或中途抛出未捕获异常）

安全问题

在多线程环境中，多个线程可能会同时访问共享资源，导致数据不一致或其他安全问题（比如下面例子中两个窗口把同一张票卖给了两个人）。为了确保线程安全，可以使用同步机制，如 synchronized 关键字、Lock 接口等。

解决线程安全问题

线程安全问题的解决方法有很多种：如 synchronized 关键字、Lock 接口、volatile 关键字、原子类等（本文重点讲前两种，后几种见文末待补充的小节）。

synchronized 关键字

synchronized 关键字可以修饰方法或代码块，用来保证：同一时间只有一个线程能进入被锁住的区域，其他线程想进来必须先等锁被释放。

Lock 接口

Lock 接口提供了比 synchronized 更灵活的控制，可以更精确地控制锁的获取与释放。常用方法：lock()（获取锁，拿不到就阻塞等待）、tryLock()（尝试获取锁，拿不到立即返回 false，不会一直等）、unlock()（释放锁，一般放在 finally 中，保证一定执行）。

死锁

当一个线程的执行需要同时获取多把锁，但只拿到了其中一部分、剩下的锁又被其他线程占着时，就会出现：自己拿不到全部的锁无法继续执行，别的线程也等不到自己释放锁无法执行——两边互相等待，谁也无法推进，这就叫死锁。

死锁产生的根本原因可以概括为：多个线程各自持有一部分锁，同时又在等待对方持有的锁，谁也不肯先释放，从而形成僵局，程序卡死。

等待唤醒机制

等待唤醒机制（也叫等待/通知机制）是多线程协作的一种解决方案，最经典的案例就是生产者-消费者问题：消费者负责获取数据，生产者负责生产数据。当队列已满时，生产者等待；当队列已空时，消费者等待。

它的核心是 Object 类提供的几个方法：消费者发现没数据可消费时，调用 wait() 方法——该方法会释放锁并进入等待状态；生产者生产完数据后，调用 notify()（或 notifyAll()）方法唤醒等待中的消费者线程，被唤醒的线程会重新获取锁，然后继续执行。

消费者

  1. 判断是否存在需要消费的数据
  2. 没有数据，调用 wait() 方法，释放锁，并进入等待状态，等待生产者生产数据
  3. 有数据，消费数据，结束之后，调用 notify() 方法，唤醒等待的生产者线程

生产者

  1. 判断数据是否已经被消费
  2. 还没有被消费，调用 wait() 方法，释放锁，并进入等待状态，等待消费者消费数据
  3. 已经被消费了（队列空了），生产数据，结束之后，调用 notify() 方法，唤醒消费者来消费数据

阻塞队列

阻塞队列是 Java 集合框架中的 BlockingQueue 接口，它继承了 Queue 接口，并额外提供了”阻塞”的能力：队列空时，take() 取数据会阻塞等待，直到有数据；队列满时，put() 放数据会阻塞等待，直到有空位。用它来实现生产者-消费者，连 wait()/notify() 都不用自己写了。

线程池

线程池的核心思想是线程复用：提前创建好一批线程放在池子里，任务来了直接分配给空闲线程执行，任务结束后线程不销毁、继续服务下一个任务。这样可以避免频繁地创建、销毁线程，提高效率。

在 Java 中，获取线程池有两种常见方式：Executors 工具类（简单但不推荐用在生产环境）和 ThreadPoolExecutor（推荐，参数可控）。

ThreadPoolExecutor 类

ThreadPoolExecutor 是线程池最核心的类。相比 Executors 的静态方法，它把各项参数都开放出来，方便按场景精细控制。创建一个线程池，需要指定：核心线程数、最大线程数、空闲线程的存活时间、存活时间单位、任务队列、线程工厂和拒绝策略。

任务来了以后按下面的顺序处理：

  1. 当有任务提交时，核心线程会执行任务
  2. 当核心线程数已满，任务会进入队列等待
  3. 当队列已满，任务会创建非核心线程执行任务，不是去执行队列中的任务，而是执行新提交的任务
  4. 当非核心线程数已满，任务会进入拒绝策略处理

拒绝策略：

  1. AbortPolicy：默认策略，抛出 RejectedExecutionException 异常
  2. DiscardPolicy：忽略新任务，不抛出异常
  3. DiscardOldestPolicy：丢弃队列中靠前的任务，并执行新任务
  4. CallerRunsPolicy：将新任务执行在调用者线程中

线程池多大比较合适：

  1. CPU 密集型：线程数 = CPU 线程数 + 1
  2. IO 密集型：线程数 = CPU 线程数 * CPU 利用率 * (CPU 计算时间 + 等待时间) / CPU 计算时间

Volatile

本节内容待补充：volatile 关键字用于保证变量的可见性（一个线程改了值，其他线程能立刻看到），但不保证原子性。

JMM

本节内容待补充：JMM（Java 内存模型）规定了多线程下共享变量的读写规则，是理解 volatile、原子性等问题的理论基础。

悲观锁、乐观锁、CAS

本节内容待补充：悲观锁默认冲突多、先加锁再操作（如 synchronized、Lock）；乐观锁默认冲突少、先操作再验证（如 CAS、版本号机制）。CAS 即 Compare And Swap（比较并交换）。

原子性

本节内容待补充：原子性指一个操作要么全部执行、要么全不执行，中间不会被其他线程插一脚。常见的原子类在 java.util.concurrent.atomic 包中（如 AtomicInteger）。

并发工具类

本节内容待补充：java.util.concurrent 包中还提供了 CountDownLatch（倒计时门闩）、CyclicBarrier（循环栅栏）、Semaphore（信号量）等并发工具。
