Java 死锁、等待唤醒与阻塞队列

发表于2025-10-23|更新于2026-09-12|后端语言基础Java
|总字数:3.1k|阅读时长:11分钟|浏览量:

死锁

当一个线程的执行需要同时获取多把锁，但只拿到了其中一部分、剩下的锁又被其他线程占着时，就会出现：自己拿不到全部的锁无法继续执行，别的线程也等不到自己释放锁无法执行——两边互相等待，谁也无法推进，这就叫死锁。

死锁产生的根本原因可以概括为：多个线程各自持有一部分锁，同时又在等待对方持有的锁，谁也不肯先释放，从而形成僵局，程序卡死。

等待唤醒机制

等待唤醒机制（也叫等待/通知机制）是多线程协作的一种解决方案，最经典的案例就是生产者-消费者问题：消费者负责获取数据，生产者负责生产数据。当队列已满时，生产者等待；当队列已空时，消费者等待。

它的核心是 Object 类提供的几个方法：消费者发现没数据可消费时，调用 wait() 方法——该方法会释放锁并进入等待状态；生产者生产完数据后，调用 notify()（或 notifyAll()）方法唤醒等待中的消费者线程，被唤醒的线程会重新获取锁，然后继续执行。

消费者

  1. 判断是否存在需要消费的数据
  2. 没有数据，调用 wait() 方法，释放锁，并进入等待状态，等待生产者生产数据
  3. 有数据，消费数据，结束之后，调用 notify() 方法，唤醒等待的生产者线程

生产者

  1. 判断数据是否已经被消费
  2. 还没有被消费，调用 wait() 方法，释放锁，并进入等待状态，等待消费者消费数据
  3. 已经被消费了（队列空了），生产数据，结束之后，调用 notify() 方法，唤醒消费者来消费数据

等待唤醒实现方式

机制 synchronized ReentrantLock
等待方法 obj.wait() condition.await()
唤醒单个线程 obj.notify() condition.signal()
唤醒所有线程 obj.notifyAll() condition.signalAll()
使用位置 必须在 synchronized 块中 必须在 lock.lock() 和 lock.unlock() 之间

Synchronized

用 synchronized 实现生产者-消费者：三个类分别存三个文件——ConsumerQueue（数据状态和锁）、Producer（生产者线程）、Consumer（消费者线程），再写一个测试类创建并启动两个线程。

Lock

用 Lock + Condition 实现同样的效果。Condition 对象由锁创建（lock.newCondition()），它的 await() 相当于 wait()，signal() / signalAll() 相当于 notify() / notifyAll()。

提示：Lock、ReentrantLock、Condition 都在 java.util.concurrent.locks 包中，三个类文件外加测试类，注意补 import。

阻塞队列

阻塞队列是 Java 集合框架中的 BlockingQueue 接口，它继承了 Queue 接口，并额外提供了”阻塞”的能力：队列空时，take() 取数据会阻塞等待，直到有数据；队列满时，put() 放数据会阻塞等待，直到有空位。用它来实现生产者-消费者，连 wait()/notify() 都不用自己写了。

阻塞队列 描述
ArrayBlockingQueue 基于数组的有界阻塞队列，容量固定且 FIFO（先进先出）。适用于需要严格控制资源占用的场景，如固定大小的线程池任务队列，避免内存溢出
LinkedBlockingQueue 基于链表的可选有界阻塞队列（默认容量为 Integer.MAX_VALUE，可设为有界），FIFO 顺序。常用于高吞吐量的生产者-消费者模型，如 Web 服务器请求队列，兼顾性能与灵活性
PriorityBlockingQueue 无界优先级阻塞队列，元素按自然顺序或 Comparator 排序。适用于需要优先级调度的任务，如实时系统中的紧急任务处理（例如告警系统）
DelayQueue 无界延迟阻塞队列，元素必须实现 Delayed 接口，仅当延迟过期后才能被取出。专用于定时任务调度，如缓存过期清理、定时任务触发（类似 Timer 的替代方案）
SynchronousQueue 不存储元素的同步阻塞队列，每个插入操作必须等待移除操作（反之亦然）。适用于直接传递（hand-off）场景，如 Executors.newCachedThreadPool() 中的任务传递，减少中间缓冲开销
LinkedTransferQueue 基于链表的无界阻塞队列，支持 transfer() 方法实现生产者直接移交元素给消费者。用于高性能数据传递场景，如低延迟交易系统，避免额外的队列存储步骤
