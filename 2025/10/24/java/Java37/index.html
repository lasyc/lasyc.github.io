Java 线程池与并发工具类

发表于2025-10-24|更新于2026-09-12|后端语言基础Java
|总字数:3.1k|阅读时长:12分钟|浏览量:

综合练习

下面几个练习综合运用线程、同步、集合等知识。

提示：每个练习里都定义了一个 MyThread（或 MyCallable）类，但一个 .java 文件里只能有一个 public 类，所以每个练习要单独建文件（或自己改类名）。练习中可能用到 Random、List、ArrayList、Collections、Optional（在 java.util 包），以及 Callable、FutureTask（在 java.util.concurrent 包），缺 import 时按提示补上。

模拟卖票

模拟两个窗口同时卖 1000 张票，保证不会把同一张票卖给两个人。ticket 是静态变量，两个窗口各自 new 了一个 MyThread 实例，所以 synchronized 锁的对象要写成 MyThread.class（类对象，整个类只有一份），写 this 会锁不住。

分发礼品

模拟两个人（线程）一起分发 100 份礼品，留 10 份不发：谁能发出去、发多少不固定，但每份礼品只会被送出去一次。

打印奇数

两个线程协作，把 0~100 之间的奇数全部打印出来。num 是两个线程共享的变量，靠 synchronized 保证每个数只被处理一次，不漏打也不重打。

抢红包

模拟 100 元红包被 3 个线程抢到（另外两个线程没抢到），每个人抢到的金额随机、但不会低于 0.01 元。代码用到了 Random，记得 import java.util.Random;（在 java.util 包）。

抽奖

张三、李四两个线程轮流从同一个奖池 list 里随机抽走一个金额，抽一次睡 1 秒。每次抽奖：Collections.shuffle(list) 先打乱，再 list.removeFirst() 取走第一个（removeFirst 是 JDK 21 的方法，JDK 21 以下要改用 remove(0)）。

抽奖结束后打印结果

在”抽奖”练习的基础上加一个功能：每个线程把自己抽到的金额存进自己的 result 列表，奖池空了之后，打印各自抽到的结果。

最大抽奖结果

用 Callable 实现抽奖：两个线程从同一个奖池里抽，各自把自己抽到的最大金额作为返回值。futureTask.get() 会阻塞，直到对应线程跑完才拿到结果；这里两个 FutureTask 包装的是同一个 MyCallable 对象，两个线程共用一个奖池。

线程池

线程池的核心思想是线程复用：提前创建好一批线程放在池子里，任务来了直接分配给空闲线程执行，任务结束后线程不销毁、继续服务下一个任务。这样可以避免频繁地创建、销毁线程，提高效率。

在 Java 中，获取线程池有两种常见方式：Executors 工具类（简单但不推荐用在生产环境）和 ThreadPoolExecutor（推荐，参数可控）。

线程池分类

Executors

线程池 描述
newFixedThreadPool 创建一个定长线程池，可控制线程最大并发数，超出的线程会在队列中等待
newWorkStealingPool 创建一个拥有并行级别为 CPU 核数的线程池，该线程池的线程数会根据 CPU 的核数动态变化
newSingleThreadExecutor 创建一个单线程化的线程池，它只会用唯一的工作线程来执行任务，保证所有任务按照指定顺序执行
newCachedThreadPool 创建一个可缓存线程池，如果线程池长度超过处理需要，可灵活回收空闲线程，若无可回收，则新建线程
newThreadPerTaskExecutor 创建普通线程的执行器：每提交一个任务就新建一条平台线程来执行（Java 21 提供），任务之间不复用线程
newVirtualThreadPerTaskExecutor 创建虚拟线程的执行器：每提交一个任务就新建一条虚拟线程来执行（Java 21 提供），适合大量轻量级任务
newSingleThreadScheduledExecutor() 创建一个单线程的定时执行器，该线程会按照指定的时间间隔重复执行任务
newScheduledThreadPool(int corePoolSize) 创建一个定长线程池，支持定时及周期性任务执行

ThreadPoolExecutor

线程池 描述
ThreadPoolExecutor(int corePoolSize,int maximumPoolSize,long keepAliveTime,TimeUnit unit,BlockingQueue<Runnable> workQueue,ThreadFactory threadFactory,RejectedExecutionHandler handler) 创建一个线程池，指定核心线程数、最大线程数、空闲线程的存活时间、任务队列、线程工厂和拒绝策略

Executors 类

Executors 底层创建的实际都是 ThreadPoolExecutor（或它的子类），只不过 Executors 帮你封装好了参数，用起来更简单。

说明：下面示例都用 try-with-resources 写法（try (...)）关闭线程池，这需要 JDK 19 及以上（ExecutorService 从 JDK 19 开始实现 AutoCloseable）；如果你的 JDK 版本较低，请改用 executorService.shutdown() 来关闭。

ThreadPoolExecutor 类

ThreadPoolExecutor 是线程池最核心的类。相比 Executors 的静态方法，它把各项参数都开放出来，方便按场景精细控制。创建一个线程池，需要指定：核心线程数、最大线程数、空闲线程的存活时间、存活时间单位、任务队列、线程工厂和拒绝策略。

任务来了以后按下面的顺序处理：

  1. 当有任务提交时，核心线程会执行任务
  2. 当核心线程数已满，任务会进入队列等待
  3. 当队列已满，任务会创建非核心线程执行任务，不是去执行队列中的任务，而是执行新提交的任务
  4. 当非核心线程数已满，任务会进入拒绝策略处理

拒绝策略：

  1. AbortPolicy：默认策略，抛出 RejectedExecutionException 异常
  2. DiscardPolicy：忽略新任务，不抛出异常
  3. DiscardOldestPolicy：丢弃队列中靠前的任务，并执行新任务
  4. CallerRunsPolicy：将新任务执行在调用者线程中

线程池多大比较合适：

  1. CPU 密集型：线程数 = CPU 线程数 + 1
  2. IO 密集型：线程数 = CPU 线程数 * CPU 利用率 * (CPU 计算时间 + 等待时间) / CPU 计算时间

Volatile

本节内容待补充：volatile 关键字用于保证变量的可见性（一个线程改了值，其他线程能立刻看到），但不保证原子性。

JMM

本节内容待补充：JMM（Java 内存模型）规定了多线程下共享变量的读写规则，是理解 volatile、原子性等问题的理论基础。

悲观锁、乐观锁、CAS

本节内容待补充：悲观锁默认冲突多、先加锁再操作（如 synchronized、Lock）；乐观锁默认冲突少、先操作再验证（如 CAS、版本号机制）。CAS 即 Compare And Swap（比较并交换）。

原子性

本节内容待补充：原子性指一个操作要么全部执行、要么全不执行，中间不会被其他线程插一脚。常见的原子类在 java.util.concurrent.atomic 包中（如 AtomicInteger）。

并发工具类

本节内容待补充：java.util.concurrent 包中还提供了 CountDownLatch（倒计时门闩）、CyclicBarrier（循环栅栏）、Semaphore（信号量）等并发工具。
