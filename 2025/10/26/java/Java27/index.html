网络编程

网络编程是指通过计算机网络（如因特网 Internet）实现多台计算机之间的数据传输与通信。

常见软件架构：

  1. C/S：客户端/服务端。如 QQ、微信等，需要单独安装客户端程序，由客户端主动连接服务器
  2. B/S：浏览器/服务器。如各类网站，用户不用安装软件，用浏览器访问服务器即可

网络编程三要素

要把数据从一台计算机传到另一台计算机，需要三个要素：

  1. IP 地址：唯一标识网络中的一台设备（计算机），解决”发给哪台机器”的问题
  2. 端口号：标识同一台设备上的不同进程（程序），解决”发给这台机器上的哪个程序”的问题
  3. 通信协议：描述计算机之间如何通信（数据格式、收发规则等），如 TCP、UDP、HTTP、FTP、SMTP、POP3、IMAP 等

IP

IP 地址（Internet Protocol Address）是网络协议栈中的重要概念，用来唯一标识网络中的一台设备。目前 IP 地址主要分为 IPv4 和 IPv6 两种：

  1. IPv4 地址格式为：A.B.C.D，其中 A、B、C、D 是 0~255 之间的数字（32 位，地址快不够用了）
  2. IPv6 地址格式为：ABCD:ABCD:ABCD:ABCD:ABCD:ABCD:ABCD:ABCD，共 8 组，每组是 0~FFFF 的十六进制数（128 位，是 IPv4 的下一代）

在 Windows 上可以用 ipconfig 命令查看本机 IP，但这个 IP 一般是局域网 IP（比如 192.168.x.x），不是外网 IP：当我们切换网络（换个路由器、换个热点）时，它很可能被重新分配。

另外，127.0.0.1 和 localhost 都指向本机，称为”本地回环地址”——它不走网卡也能通，永远指向自己，常用于本机测试。

InetAddress 类

InetAddress 是 Java 中用来表示 IP 地址的类，一个 InetAddress 对象就代表一台计算机（或一个 IP 地址）。通过它可以拿到主机名、IP 地址等信息，它位于 java.net 包中。

端口

端口（Port）是计算机上”进程”的编号，用来标识同一台计算机上的不同程序：IP 负责找到计算机，端口负责找到这台计算机上的具体程序。端口号范围：0~65535。

其中 0~1023 是系统保留的”知名端口”，很多都固定分配给了常用服务（如 80 是 HTTP、443 是 HTTPS、21 是 FTP）；我们自己写程序时一般用 1024 之后的端口，避免冲突。

协议

协议（Protocol）是通信双方共同遵守的规则，它规定了数据怎么传、怎么解析——好比两个人说同一种语言才能交流。在 Java 网络编程中，最常用的是传输层的 TCP 和 UDP。

模型

为了把复杂的网络通信分层理解，人们提出了参考模型（每一层只负责自己那部分工作，上层不用关心下层的细节）：

  1. OSI 七层模型：应用层 –> 表示层 –> 会话层 –> 传输层 –> 网络层 –> 数据链路层 –> 物理层
  2. TCP/IP 四层模型（实际使用）：应用层 –> 传输层 –> 网络层 –> 网络接口层

通信协议

  1. UDP：无连接协议。速度快、开销小，但不保证数据一定送达（可能丢失、乱序），单次发送的数据报大小有限制（最大约 64KB）
  2. TCP：有连接协议。先建立连接再传数据，速度比 UDP 慢一些，但没有大小限制，数据可靠（不丢失、不重复、不乱序）

UDP

UDP（User Datagram Protocol，用户数据报协议）是一种无连接的传输协议：发送数据前不需要建立连接，直接把数据报”扔”出去。它速度快、开销小，但不保证数据一定送达（可能丢失、乱序），适合视频通话、游戏、DNS 查询这类对实时性要求高、能容忍少量丢失的场景。

UDP 有三种通信方式：单播、组播、广播。

  1. 单播：发送方把数据发给一个指定的接收方（一对一）
  2. 组播：发送方把数据发给一组加入了同一组播地址的接收方（一对多）
  3. 广播：发送方把数据发给当前网络内的所有主机（一对所有）

TCP

TCP（Transmission Control Protocol，传输控制协议）是一种面向连接的可靠协议：传输前先建立连接（三次握手），传输过程中保证数据不丢失、不重复、按顺序到达，传输结束再断开连接（四次挥手）。

三次握手、四次挥手

TCP 是面向连接的协议：建立连接、断开连接都有固定的流程，分别叫”三次握手”和”四次挥手”。

三次握手（建立连接）

建立连接前先”握手”三次，目的是确认双方的收发能力都正常：

  1. 客户端发送一个 SYN 包给服务端，表示”我想和你建立连接”
  2. 服务端收到 SYN 包后，发送一个 SYN+ACK 包给客户端，表示”我收到你的请求了，我这边也没问题”
  3. 客户端收到 SYN+ACK 包后，再发送一个 ACK 包给服务端，表示”收到，连接建立”——服务端收到这个 ACK 后，连接就正式建立了

四次挥手（断开连接）

TCP 是全双工的（两边可以同时收发），所以断开时每个方向都要单独”告别”，需要四次挥手（以客户端先发起断开为例）：

  1. 客户端发送一个 FIN 包给服务端，表示”我的数据发完了，我要断开连接”
  2. 服务端收到 FIN 包后，回复一个 ACK 包，表示”收到你的断开请求”；此时服务端可能还有数据要发给客户端，会继续发（半关闭状态）
  3. 服务端数据发完后，发送一个 FIN 包给客户端，表示”我这边也发完了，可以断开了”
  4. 客户端收到 FIN 包后，回复一个 ACK 包，表示”收到”——经过短暂等待，双方正式断开连接
