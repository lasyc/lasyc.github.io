发表于2025-11-06|更新于2026-09-06
|浏览量:

约束

约束作用在表的字段上，用来限制字段中可以存放什么数据，从而保证数据的正确性和完整性。比如：年龄不能是负数、学号不能重复、填写的班级 ID 必须真实存在等。

分类

MySQL 中的常见约束如下（关键字列就是建表时要写的内容）：

约束 作用 关键字
主键 该值必须唯一、不能为 NULL PRIMARY KEY
外键 该值必须在指定表中存在 FOREIGN KEY
唯一 该值必须唯一、不重复 UNIQUE
非空 该值不能为空 NOT NULL
默认值 若未指定该值，则使用默认值 DEFAULT
检查 检查字段的值是否符合条件 CHECK

说明：主键经常搭配 AUTO_INCREMENT（自动增长）；除外键外，约束一般直接写在字段类型后面（列级约束），外键通常写成表级约束放在建表语句的最后。

外键约束

外键约束发生在表与表之间，用来建立关联：我们可以指定某张表的一个字段，它的值必须存在于另一张表的某个字段中。

比如：现在有班级表和学生表，学生表中有一个 class_id 字段，保存学生所属班级的 ID。给 class_id 加上外键约束后，它存的值必须存在于班级表的 id 字段中——如果填了不存在的班级 ID，插入就会报错。

添加、删除外键约束

CONSTRAINT 约束名 中的”约束名”是自己起的，添加和删除时名字要写一致。

  • 建表时添加外键约束（一般写在建表语句的最后）
  • 表已建好，通过修改表结构添加外键约束
  • 删除外键约束

外键约束删除规则

添加外键时，可以用 ON UPDATE 规则 ON DELETE 规则 指定：当父表（被引用的表）中的数据被更新或删除时，子表（含外键的表）该如何处理。

删除规则 作用
NO ACTION 默认值，当删除/修改父表的字段值时，会先检查该字段值是否存在外键，如果有则不允许操作
RESTRICT 同 NO ACTION
CASCADE 当删除/修改父表字段值时，会同步删除/修改子表字段值
SET NULL 当删除/修改父表字段值时，会设置子表字段值为 NULL
SET DEFAULT 当删除/修改父表字段值时，会设置子表字段值为默认值(InnoDB 不支持)
