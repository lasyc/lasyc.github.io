MySQL 存储引擎

发表于2025-11-09|更新于2026-09-12|后端数据库MySQL
|总字数:1.1k|阅读时长:3分钟|浏览量:

MySQL 体系结构图

  1. 客户端连接器：Native C API、JDBC、ODBC、.NET、PHP、Python、Ruby、Cobol 等
  2. MySQL 服务端（从上到下）
    • 连接层：连接池，负责管理客户端连接（校验身份、分配线程等）
    • 服务层：SQL 接口、解析器、查询优化器、缓存（Query Cache 在 MySQL 8.0 中已被移除）
    • 引擎层：可插拔的存储引擎（InnoDB、MyISAM、Memory 等）
    • 存储层：数据文件、索引文件、日志文件，数据最终保存在磁盘上

存储引擎简介

存储引擎是 MySQL 的核心部分，负责数据的存储和检索：它提供了一套机制，把数据存到数据库管理系统中，并支持用各种查询语句把数据检索出来。

存储引擎是基于表的（不是基于库的），所以同一个数据库中的不同表可以使用不同的存储引擎。

  1. 查看数据库支持的存储引擎

    SHOW ENGINES;

  2. 设置存储引擎

    CREATE TABLE table_name (……) ENGINE=[存储引擎名];

存储引擎的特点

InnoDB

InnoDB 是 MySQL 默认的存储引擎，是一种兼顾高可靠性和高性能的通用存储引擎

  1. DML 操作遵循 ACID 原则，支持事务
  2. 锁机制：支持行级锁，也支持表级锁（行锁在无法使用索引等场景下，可能需要对大量行加锁，效果接近锁全表）
  3. 支持外键关系

使用 InnoDB 时，每张表都会对应创建一个 .ibd 文件，里面保存了该表的数据和索引（表结构定义在 MySQL 8.0 中保存在数据字典 / .sdi 中）。

innodb_file_per_table：这个选项默认是开启的——每张表的数据都放在各自的 .ibd 文件中；如果关闭，所有表的数据会集中存放在系统表空间 ibdata1 文件里。

逻辑存储结构

  1. Table Space：表空间，在一个 Table Space 中包含多个 Segment
  2. Segment：段，一个 Segment 包含多个 Extent
  3. Extent：区，一个 Extent 存放 64 个 Page，一个区的大小为 1M
  4. Page：页，一个 Page 存放多个 Row，一个页的大小为 16K
  5. Row：行，一行数据中包含：Trx id（最后一次修改该行的事务 ID）、Roll pointer（回滚指针，指向 undo log 中的旧版本记录）、以及真正的字段数据

MyISAM

MyISAM 是 MySQL 早期的默认存储引擎

  1. 不支持事务和外键
  2. 支持表锁，不支持行锁
  3. 访问速度快

使用 MyISAM 时，每张表都会创建三个文件，分别为：.MYD、.MYI、.sdi

  1. .MYD（MyData）：用于存储数据
  2. .MYI（MyIndex）：用于存储索引
  3. .sdi：用于存储表结构（MySQL 8.0；5.7 及更早版本是 .frm 文件）

Memory

Memory 是一种基于内存的临时存储引擎，用于临时存储数据，不会把数据写入到文件中，因此如果遇到断电，数据将丢失

  1. 不支持事务和外键
  2. 访问速度更快
  3. 支持 Hash 索引

使用 Memory 时，每张表也会创建一个 .sdi 文件，用于保存表结构等信息（数据只存在内存中，所以不会生成数据文件）

存储引擎使用场景

  1. InnoDB：适用于高并发、事务处理频繁、对数据完整性要求高的场景，日常开发中 90% 以上的表都用它（也是默认引擎）
  2. MyISAM：适用于以查询为主、对事务和并发要求不高的场景。它早已被 InnoDB 取代为默认引擎，如今主要用于一些只读的历史/报表数据（”MyISAM 被 MongoDB 替代”的说法不准确，二者并不是同一类东西）
  3. Memory：数据存在内存中，访问速度最快，适合临时表、缓存这类不要求持久化的场景；类似 Redis 这样的内存缓存也能覆盖它的使用场景

MySQL 事务
