事务

事务（Transaction）是一组操作的集合，这一组操作会被当成一个整体：要么全部成功，要么全部失败。如果其中任意一个操作执行失败，事务就会回滚（ROLLBACK），之前做的所有修改全部撤销。

MySQL 默认是自动提交的：每一条 SQL 语句执行完都会自动提交。所以想让一组 SQL 作为一个整体，就需要手动开启事务：用 BEGIN（或 START TRANSACTION）开启事务，全部成功后用 COMMIT 提交，中途失败用 ROLLBACK 回滚。

注意：事务主要和 DML（增、删、改）有关，因为只有修改数据才需要保证”要么全成、要么全没”；SELECT 查询本身不修改数据，但可以放在事务中一起执行。

事务的操作

操作 描述
SELECT @@AUTOCOMMIT; 查看当前数据库是否自动提交，1 表示自动提交，0 表示手动提交
SET AUTOCOMMIT = 0 / 1; 关闭 / 开启自动提交
BEGIN; / START TRANSACTION; 开启事务
COMMIT; 提交事务
ROLLBACK; 回滚事务

事务四大特性 ACID

  1. 原子性（Atomicity）：事务是一个不可分割的工作单位，事务中的操作要么全部完成，要么全部不完成，不会只完成一部分
  2. 一致性（Consistency）：事务执行前后，数据库中的数据都要处于正确、完整的状态。比如转账：不管成功还是失败，两个账户的余额总和不能变，不能出现”只扣了张三的钱、李四却没收到”这种结果
  3. 隔离性（Isolation）：一个事务的执行不能被其他事务干扰，即一个事务内部的操作及使用的数据，对并发的其他事务是隔离的，并发执行的各个事务之间不能互相干扰
  4. 持久性（Durability）：事务提交之后，对数据的修改就会被永久保存下来——即使之后系统断电、崩溃，修改也不会丢失

并发事务

当多个事务并发执行时，会出现并发问题，比如多个事务同时对同一个数据进行修改，那么就会产生数据不一致的情况

问题 描述
脏读 B 事务修改了一条数据，但没有提交，此时 A 事务查询该值，读到了 B 事务未提交的数据，然后 B 事务遇到异常回滚了，那么 A 事务查询到的数据就是脏数据
不可重复读 A 事务两次读取到同一个数据，两次结果不一致
幻读 事务 A 执行同一条查询两次，第二次却查出了第一次没有的行——事务 B 插入并提交了满足条件的新数据，看起来像出现了”幻影”行

隔离级别

隔离级别越高越安全，但是并发性能越差。从上到下，隔离级别越来越高：

隔离级别 描述 可能出现问题
READ UNCOMMITTED 读未提交 脏读、不可重复读、 幻读
READ COMMITTED 读已提交 不可重复读、幻读
REPEATABLE READ（默认） 可重复读 幻读
SERIALIZABLE 串行化

说明：上表按 ANSI 标准列出；MySQL 的 InnoDB 引擎在”可重复读”（默认）下通过 MVCC 快照读基本避免了幻读，所以日常开发用默认级别即可，不必担心上表所说的幻读。

  1. 查询当前数据库的隔离级别

    SELECT @@TRANSACTION_ISOLATION;

  2. 修改隔离级别（会话/全局）

    SET [SESSION|GLOBAL] TRANSACTION ISOLATION LEVEL 隔离级别;

    • SESSION：只对当前会话（当前连接窗口）生效
    • GLOBAL：全局生效，只对之后新建的连接生效，改完需要重新连接才能看到效果
