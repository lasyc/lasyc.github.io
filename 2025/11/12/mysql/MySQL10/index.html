MySQL SQL 性能分析

SQL 性能分析

SQL 性能分析：通过分析 SQL 语句，了解它在数据库中的实际执行情况（是否走了索引、扫描了多少行、耗时多少等），再根据分析结果有针对性地优化 SQL

SQL 执行频率

SHOW [SESSION|GLOBAL] STATUS LIKE ‘Com__‘;

慢查询日志

在慢查询日志中，记录了所有执行时间超过了执行阈值的 SQL 查询语句

  1. 查看慢查询日志开关状态

    SHOW VARIABLES LIKE ‘slow_query_log’;

  2. 开启慢查询日志(临时)

    SET [SESSION|GLOBAL] slow_query_log = ON;

  3. 开启慢查询日志(持久)

    修改配置文件 /etc/my.cnf 或者 /etc/mysql/my.cnf，添加参数：slow_query_log=1 和 long_query_time=2，然后重启 MySQL 服务器

profile 详情

慢查询日志只能记录”超过阈值”的 SQL。如果某条 SQL 本身很简单、执行时间没达到阈值，却明显比平时慢（比如从 1ms 涨到 30ms），慢查询日志就发现不了它。这时可以用 profile 查看每条 SQL 执行时各个阶段的耗时，精确定位慢在哪一步

  1. 查看当前数据库是否支持 profile

    SELECT @@have_profiling;

  2. 查看 profile 是否开启

    SELECT @@profiling;

  3. 开启 profile

    SET profiling = 1;

  4. 查看 profile 详情

    SHOW PROFILES;

  5. 查看指定 profile 详情

    SHOW PROFILE FOR QUERY [QUERY_ID];

性能分析 explain

explain 命令可以查看 SQL 语句的执行计划，根据执行计划可以判断 SQL 语句的性能

EXPLAIN 查询语句;

查询结果

  • id：SELECT 或操作表的顺序。id 越大越先执行；id 相同时从上到下依次执行
  • select_type：SQL 语句的类型，常见的有：SIMPLE（简单查询）、PRIMARY（主查询）、SUBQUERY（子查询）等
  • type：访问类型，常见的有：NULL（不访问任何表，如 SELECT 1）、system（系统表）、const（按主键/唯一索引等值查，最多一行）、eq_ref（联表时按主键/唯一索引各查一行）、ref（按普通索引等值查）、range（范围查询）、index（扫描整棵索引树）、ALL（全表扫描）。从左到右性能依次变差
  • possible_keys：可能用到的索引（优化器评估后不一定真的使用）
  • key：实际使用的索引（NULL 表示没走索引）
  • key_len：本次查询实际用到的索引长度（字节），可以用来判断联合索引用到了哪几列
  • rows：预计扫描的行数（估算值，不是实际返回的行数）
  • filtered：过滤后预计剩余的行数占 rows 的百分比。例如 rows=24、filtered=10.00，表示扫描 24 行后大约只剩 2 行左右符合条件；越接近 100% 说明过滤效果越好

性能分析总结

  1. 查看 SQL 语句的执行频次：SHOW [SESSION|GLOBAL] STATUS LIKE 'Com______';
  2. 查看慢查询日志：SHOW VARIABLES LIKE '%slow_query_log%';、cat /var/log/mysql/mysql-slow.log
  3. 查看 Profile 详情：SHOW PROFILES;、SHOW PROFILE FOR QUERY [QUERY_ID];
  4. 查看 SQL 语句的执行计划：EXPLAIN 查询语句;
