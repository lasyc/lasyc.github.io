MySQL 索引使用与设计

发表于2025-11-13|更新于2026-09-12|后端数据库MySQL
|总字数:5.4k|阅读时长:25分钟|浏览量:

使用索引

示例

最左前缀法则

如果一个索引是由多个列组成的复合索引，那么在查询中，若想使用该索引，则必须满足最左前缀法则：查询条件必须从索引最左侧的列开始、且中间不能断开。

举例：若存在联合索引（A, B, C, D），那么：

  1. 条件包含 (A, B, C, D) → 四列全部生效
  2. 条件包含 (A, B, C) → A、B、C 三列生效
  3. 条件包含 (A, B) → A、B 两列生效
  4. 条件只包含 (A) → 只有 A 生效
  5. 条件包含 (B, C, D)：缺少最左侧的 A，不满足最左前缀，索引完全失效
  6. 条件包含 (A, C, D)：虽然 A 在最左侧，但跳过了中间的 B（不连续），因此只有 A 生效，C、D 都用不上

范围查询

在联合索引中，一旦某列使用了范围查询（>、<），该列右侧的列就无法使用索引（范围条件就像一个”断点”）。而 >=、<= 因为能转化为等值边界，通常不会断开索引

索引列运算

不要在索引列上进行运算，否则会导致索引失效

类型转换

字符串类型字段不加单引号，索引失效

前缀模糊查询

模糊查询时，若通配符 % 出现在字符串开头，则索引失效

OR 查询

使用 OR 连接多个条件时，若其中一个条件未使用索引，则整个查询无法使用索引

数据分布影响

当使用索引时，MySQL 会根据数据的分布情况来决定是否使用索引如果某个条件过滤掉的数据量很小，MySQL 可能会选择全表扫描而不是使用索引，因为全表扫描可能更高效

SQL 提示

在 MySQL 中，可以使用 SQL 提示来强制使用索引或避免使用索引

语法 描述
USE INDEX (index_list) 提示优化器在查询时使用指定的（建议）
IGNORE INDEX (index_list) 提示优化器在查询时忽略指定的索引（建议）
FORCE INDEX (index_list) 强制优化器在查询时使用指定的索引（强制）

覆盖索引

覆盖索引指索引包含查询所使用的列，避免回表

  1. Using index condition：表示使用了索引条件下推（Index Condition Pushdown，ICP），即在索引扫描阶段就过滤掉不符合条件的行，减少回表的行数，从而提高查询效率
  2. Using where; Using index：表示查询使用了索引，并且索引包含了查询所需的所有列，因此不需要回表，直接从索引中获取数据

前缀索引

当数据库中某个字段保存的内容过长，比如一篇文章，在这种情况下，若对该字段建立索引，开销会很大，因此可以使用前缀索引，只对字段的前几个字符建立索引，从而减少索引的大小，提高查询效率

CREATE INDEX idx_xxx ON tb_xxx(column(n));

前缀长度怎么定？

根据索引选择性来定：选择性 = 该字段去重后的取值个数 ÷ 总行数（最大为 1）。选择性越接近 1，说明区分度越高、索引效果越好。实际做法是：分别测试不同前缀长度的选择性，在区分度没有明显下降的前提下，前缀取得越短越好（越省空间）

索引选择

索引的选择，应该遵循以下原则：

  1. 索引数量要克制：只为高频查询、排序、分组涉及的列建索引（每多一个索引，插入/更新时都要额外维护，写性能会下降）
  2. 优先选区分度高（选择性接近 1）的列，过滤效果更好
  3. 字段值很长时，用前缀索引来缩小索引体积
  4. 多个列经常一起作为查询条件时，建联合索引而不是多个单列索引（查询列都能从索引取到时还能避免回表）

索引设计

  1. 当表的数据量较大时，且查询频繁时，应该考虑创建索引
  2. 对于经常作为查询、排序、分组条件的列，应该考虑创建索引
  3. 尽量使用区分度高的列作为索引列
  4. 若字段中的值过长，可以考虑使用前缀索引
  5. 多个列经常组合查询时，尽量用联合索引而不是多个单列索引；查询列都能从索引中取到时还能避免回表
  6. 索引不是越多越好，应该平衡索引和查询性能

索引总结

  1. 索引概述：索引是一种数据结构，用于加速数据查询
  2. 索引结构：B+树索引、哈希索引等
  3. 索引分类：
    • 唯一索引、普通索引、组合索引、全文索引
    • 聚集索引、非聚集索引
  4. 索引语法：
    • 创建索引：CREATE INDEX index_name ON table_name (column_name);
    • 删除索引：DROP INDEX index_name ON table_name;
    • 查看索引：SHOW INDEX FROM table_name;
  5. SQL 性能分析：
    • 执行频次、慢查询日志、profile、explain
  6. 索引使用：
    • 最左前缀法则，不满则不使用索引
    • 范围查询，使用等值查询，而不是范围查询，范围查询后续列索引失效
    • 索引列运算，不使用索引
    • 类型转换，不使用索引
    • 前缀模糊查询，不使用索引
    • OR 查询，若 OR 语句两侧的查询条件中有一个没有索引，则 OR 语句将无法使用索引
    • 数据分布影响，若数据量过小，或者查询条件筛选过少，则放弃索引，扫描全表
    • SQL 提示，当某个字段拥有多个索引时，可以指定使用哪一个索引
    • 覆盖索引，尽量让索引包含查询返回字段，避免回表
    • 前缀索引，当字段值过长时，可以创建前缀索引，取前 N 个字符作为索引
