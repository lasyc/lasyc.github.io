MySQL 视图与存储过程

发表于2025-11-25|更新于2026-09-12|后端数据库MySQL
|总字数:2.6k|阅读时长:10分钟|浏览量:

视图

视图介绍

视图（View）是一种虚拟存在的表，它本身不存储数据，本质上是基于一条 SQL 查询语句的结果集：每次查询视图时，都会动态地从基础表中取最新数据。使用视图可以简化复杂的查询、提高数据安全性（隐藏敏感字段），相当于给数据加了一层抽象

视图基本使用

  1. 创建视图

    CREATE [OR REPLACE] VIEW 视图名 AS 查询语句 [WITH [CASCADED | LOCAL] CHECK OPTION];

  2. 查看全部视图

    SHOW FULL TABLES WHERE Table_type = ‘VIEW’;

  3. 查看指定视图的定义

    SHOW CREATE VIEW 视图名;

  4. 查看视图数据

    SELECT * FROM 视图名;

  5. 修改视图

    CREATE OR REPLACE VIEW 视图名 AS 新的查询语句 [WITH [CASCADED | LOCAL] CHECK OPTION];

    ALTER VIEW 视图名 AS 新的查询语句 [WITH [CASCADED | LOCAL] CHECK OPTION];

  6. 删除视图

    DROP VIEW [IF EXISTS] 视图名;

检查选项

通过视图操作数据，本质上就是在操作视图对应的基础表。向视图中插入或更新数据时，MySQL 可以根据视图定义的查询条件来检查数据是否合规。为了控制这种检查行为，可以在创建视图时使用 WITH [CASCADED | LOCAL] CHECK OPTION：

  1. 如果创建视图时没有使用 WITH CHECK OPTION，那么通过视图插入、更新数据时不做任何检查：不满足视图条件的数据也能成功插入基础表，只是插入后在这个视图中看不到而已（见下方”未开启”演示）；若视图是基于其他视图创建的，也不会检查上层视图的条件
  2. 如果创建视图时使用了 WITH CASCADED CHECK OPTION（级联），那么插入/更新的数据必须满足当前视图的条件；若当前视图是基于其他视图创建的，即使那些上层视图没开检查选项，也必须满足上层视图的查询条件
  3. 如果创建视图时使用了 WITH LOCAL CHECK OPTION（局部），那么插入/更新的数据必须满足当前视图的条件；若基于其他视图创建，则只有那些同样开启了检查选项的上层视图条件需要满足

未开启 WITH [CASCADED | LOCAL] CHECK OPTION

开启 WITH [CASCADED | LOCAL] CHECK OPTION

更新及作用

对视图做更新（INSERT / UPDATE / DELETE）实际上更新的是它对应的基础表。但并不是所有视图都能更新：只有视图与基础表结构基本一致、且视图中没有聚合函数、DISTINCT、GROUP BY、HAVING、子查询等复杂内容时，才能安全更新（带 WITH CHECK OPTION 的视图更新时还会做条件检查）

  1. 简单：用户可以将常用的查询语句封装成视图，简化查询操作
  2. 安全：MySQL 中通过授权只能限制用户访问表，而不能限制用户访问表中的某列，通过将表中的可见列封装成视图，然后再访问视图，这样子用户只能看到可见列，从而提高数据的安全性
  3. 独立：视图对外暴露的结构与基础表相互独立。基础表增加列不会影响视图（新列不会自动出现在视图里）；想调整对外暴露的字段时，只需更新视图定义，无需改动上层应用

存储过程

存储过程介绍

存储过程（Stored Procedure）是一组事先定义好、存储在数据库中的 SQL 语句集合。把频繁使用的复杂操作封装成存储过程，之后只需 CALL 调用，可以简化操作、减少客户端与服务器的交互次数、提升效率

存储过程特点

  1. 封装、复用
  2. 可以接收参数、并返回结果
  3. 减少交互次数，提升效率

存储过程基本使用

  1. 创建存储过程

    CREATE PROCEDURE 存储过程名 ([参数列表]) BEGIN SQL语句; END;

  2. 调用存储过程

    CALL 存储过程名([参数列表]);

  3. 查看存储过程

    SELECT * FROM INFORMATION_SCHEMA.ROUTINES WHERE ROUTINE_TYPE = ‘PROCEDURE’;

  4. 删除存储过程

    DROP PROCEDURE 存储过程名;

变量

在存储过程中，可以使用变量来存储数据、传递结果。变量一共分三类：系统变量、用户变量、局部变量

系统变量

系统变量是 MySQL 提供的变量，用于保存 MySQL 服务器的状态信息，如当前时间、当前用户、当前数据库等，属于服务器层面，系统变量又分为全局变量(GLOBAL)和会话变量(SESSION)两种

  1. 查看系统变量

    SHOW [GLOBAL | SESSION] VARIABLES [LIKE ‘变量名’];

    SELECT @@[GLOBAL | SESSION] 变量名;

  2. 修改系统变量

    SET [@@][GLOBAL | SESSION] 变量名 = 值;

用户变量

用户变量是定义在会话（当前连接）上的变量，用于保存临时数据，当前会话内都可以使用。用户变量以 @ 符号开头，例如 @my_name，可以在 SQL 语句中直接使用

  1. 创建用户变量

    SET @变量名 := 值;

    SELECT 字段名 INTO @变量名 FROM 表名 WHERE 条件;

  2. 使用用户变量

    SELECT @变量名;

局部变量

局部变量是在存储过程内部定义、只在本次调用中生效的变量，用 DECLARE 关键字声明，只能在存储过程（函数）中使用。声明格式为：DECLARE 变量名 数据类型 [DEFAULT 默认值];

  1. 定义局部变量

    DECLARE 变量名 数据类型 [DEFAULT 值];

  2. 赋值

    SET 变量名 := 值;

    SELECT 字段名 INTO 变量名 FROM 表名 WHERE 条件;

  3. 使用局部变量

    SELECT 变量名;
