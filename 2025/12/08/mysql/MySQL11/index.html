锁

介绍

锁是数据库提供的一种并发控制机制，用来协调多个会话对数据的访问，避免并发读写造成数据错乱。锁从粒度上可分为表锁、行锁等，从性质上可分为共享锁、排他锁等。锁的粒度越大，并发能力越差（冲突越多），所以要根据实际场景选择合适的锁

分类

按照锁的粒度（锁定范围从大到小）可以分为三类：

  1. 全局锁：锁定整个数据库实例，加锁期间整个库只读
  2. 表级锁：锁定一张表，加锁期间其他会话无法按需读写这张表
  3. 行级锁：只锁定某一行记录，其他会话仍可操作表中的其他行，并发度最高

全局锁

全局锁会对整个数据库实例加锁：执行 FLUSH TABLES WITH READ LOCK 后，所有库都变成只读，直到释放锁。

典型场景：全库备份。加全局锁能保证备份期间数据不变化，得到一份一致的数据。但日常一般不用手动加锁，mysqldump 配合 --single-transaction（见下文）可以在不停写的情况下拿到一致性快照。

  1. 添加全局锁：

    FLUSH TABLES WITH READ LOCK;

  2. 释放全局锁（直接断开会话也会自动释放）：

    UNLOCK TABLES;

表级锁

表级锁：锁的粒度是整张表。MyISAM、InnoDB 等存储引擎都支持表级锁（InnoDB 的 DML 默认走行锁，只有显式 LOCK TABLES、修改表结构等场景才会用到表锁）。

在表级锁的范畴内，又分为以下三类：

  1. 表锁
  2. 元数据锁
  3. 意向锁

表锁

对于表锁，又分为两类

  1. 表共享读锁（read lock）：所有会话均可读，但不可写
  2. 表独占写锁（write lock）：当前会话可读写，其他会话不可读不可写

表锁的使用

  1. 加锁

    LOCK TABLES 表名 [READ | WRITE];

  2. 解锁

    UNLOCK TABLES;

元数据锁

元数据锁（Meta Data Lock，MDL）：由系统自动控制，无需手动加锁。当我们访问一张表时，系统会自动给它加上元数据锁，防止表还在被读写时结构就被人改了：只要表上还有事务没有结束，就不允许修改表结构（DDL）的操作。

具体来说：对表做增删改查（DML / 查询）时，会自动加 MDL 读锁；修改表结构（ALTER、DROP 等 DDL）时，会自动加 MDL 写锁。读锁与写锁互斥，所以”一边在查表、一边 ALTER”的请求会阻塞，直到查询事务结束

SQL 锁类型 说明
LOCK TABLES XXX READ / WRITE SHARED_READ_ONLY / SHARED_NO_READ_WRITE
SELECT、SELECT … LOCK IN SHARE MODE SHARED_READ 与 SHARED_READ、SHARED_WRITE 兼容，与 EXCLUSIVE 互斥
INSERT、UPDATE、DELETE、SELECT … FOR UPDATE SHARED_WRITE 与 SHARED_READ、SHARED_WRITE 兼容，与 EXCLUSIVE 互斥
ALTER TABLE 等 DDL EXCLUSIVE 与 SHARED_READ、SHARED_WRITE 都互斥

意向锁

当一个事务要给某条记录加行锁时，如果此时另一个事务想给整张表加表锁，它需要先确认这张表里有没有行锁——如果没有标记，就得遍历表中所有记录才能确认，代价很高。于是引入了意向锁：事务在加行锁之前，先给表加一个意向锁作为标记。这样其他事务要加表锁时，只需要看表上有没有意向锁就能快速判断，不需要再遍历整张表

意向锁分两类：

  1. 意向共享锁（IS）：由 SELECT ... LOCK IN SHARE MODE 这类语句创建。IS 与表级共享读锁（READ）兼容，与表级独占写锁（WRITE）互斥
  2. 意向排他锁（IX）：由 INSERT、UPDATE、DELETE、SELECT ... FOR UPDATE 创建。IX 与表级 READ、WRITE 锁都互斥

注意：意向锁之间是互相兼容的（IS 与 IX 可以共存），因为意向锁只是”表里存在行锁”的标记，并不直接阻止别人操作行数据

行级锁

行级锁：针对单行记录加锁，粒度最小、冲突概率最低、并发度最高，由 InnoDB 引擎实现。

要注意的是，行锁本质上是基于索引来加锁的：只有 WHERE 条件走了索引，才能精确锁住少数几行；如果没走索引，InnoDB 只能对大量行（甚至整张表）加锁。

根据加锁范围，行级锁又分为三类：

  1. 记录锁（Record Lock，行锁）：锁定一行记录，其他会话不能对同一行做 UPDATE、DELETE。在 RC 和 RR 隔离级别下都支持
  2. 间隙锁（Gap Lock）：锁定索引记录之间的间隙（开区间，不包含记录本身），防止其他会话向间隙内插入数据从而产生幻读，只在 RR 隔离级别下支持
  3. 临键锁（Next-Key Lock）：记录锁 + 间隙锁，既锁记录、也锁记录前面的间隙，是 InnoDB 在 RR 隔离级别下默认的加锁单位，只在 RR 下支持

行锁

行锁分类：

  1. 共享锁（Shared Lock）：允许一个会话对同一行数据进行读取，阻止其他会话获取排他锁
  2. 排他锁（Exclusive Lock）：只要会话获取了排他锁，就可以更新数据，阻止其他会话获取共享锁和排他锁

不走索引的后果：

  1. 当 UPDATE / DELETE 的 WHERE 条件没有使用索引时，InnoDB 无法精确锁定某几行，只能对表中所有记录逐行加锁（同时锁上间隙），效果等同于锁住整张表，并发性能会急剧下降。所以更新、删除时，WHERE 条件一定要走索引
已存在锁 共享锁 排他锁
已有共享锁 允许 拒绝
已有排他锁 拒绝 拒绝
SQL 锁类型 说明
INSERT 排他锁 插入数据时，会获取排他锁
UPDATE 排他锁 更新数据时，会获取排他锁
DELETE 排他锁 删除数据时，会获取排他锁
SELECT（普通查询） 不加锁 MVCC 快照读，不加锁
SELECT … LOCK IN SHARE MODE 共享锁 手动获取共享锁
SELECT … FOR UPDATE 排他锁 手动获取排他锁

间隙锁/临键锁

  1. 在唯一索引上等值查询（=）且记录不存在时：临键锁会退化为间隙锁，只锁间隙、不锁记录（例如表中已有 id=99、id=101，查询 id=100 不存在，就只锁 (99, 101) 这个开区间，防止其他事务插入 id=100）
  2. 在普通索引（非唯一）上等值查询时：InnoDB 会使用完整的临键锁（记录锁 + 间隙锁），不仅锁住匹配的记录，还锁住该记录之后的间隙，防止幻读
  3. 在任何索引上做范围查询（>、<、BETWEEN 等）时：InnoDB 会对范围内所有记录及其间隙加临键锁，锁定从查询起点到第一个不满足条件的值之间的整个范围

总结

  1. 概述：锁用来协调并发访问、保证数据一致性，按粒度分为：全局锁、表级锁和行级锁
  2. 全局锁：对整个数据库实例加锁，粒度最大、冲突最多、并发性最差
  3. 表级锁：对整张表加锁，粒度中等，主要分为：表锁（LOCK TABLES）、元数据锁（MDL）和意向锁
  4. 行级锁：对单行加锁，粒度最小、并发性最好，主要分为：记录锁、间隙锁和临键锁
