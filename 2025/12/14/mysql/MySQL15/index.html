MySQL 主从复制

发表于2025-12-14|更新于2026-09-06
|浏览量:

概述

主从复制：准备两台（或多台）服务器，分别安装 MySQL，一台作为主数据库（Master），一台作为从数据库（Slave）。当主库上发生数据变更时，主库会把这些操作记录到二进制日志（binlog）中，从库拉取 binlog 并重新执行，从而把主库上的操作同步到从库，保证主从数据一致。

一台主数据库可以挂多台从数据库；而一台从数据库也可以作为更下游数据库的”主库”，形成级联结构。

主从复制的作用：

  1. 高可用：主库宕机时，从库可以顶上，避免服务中断
  2. 读写分离：把查询压力分摊到从库，降低主库的访问压力
  3. 备份安全：在从库上执行备份，不影响主库的读写性能

原理

前面提到，主从复制依赖二进制日志（binlog）实现：主库上所有对数据有影响的操作都会被记录到 binlog。

复制过程可以概括为三步：

  1. 主库把数据变更写入二进制日志
  2. 从库的 I/O 线程（IOThread）连接主库，拉取主库的 binlog，写入从库本地的中继日志（Relay log）
  3. 从库的 SQL 线程（SQLThread）读取中继日志并重新执行，把主库的操作在从库上重放一遍

搭建

  1. 准备两台服务器，分别安装 MySQL，一主一从

  2. 准备主数据库，修改配置文件 /etc/my.cnf，并重启 MySQL 服务器

    注意：binlog-do-db 会限制主库只把指定库的变更写进 binlog（其他库的操作不会同步）。下面”测试”部分在 db01 里建表，如果从库看不到同步过来的数据，多半是这行没注释掉——把该行注释后重启主库即可

  3. 在主库中，创建从库连接的账号，并授予主从复制的权限

  4. 查看二进制日志坐标

  5. 修改从库的配置文件，并重启从库

  6. 设置从库，配置主库的信息

  7. 启动主从复制，并查看状态
