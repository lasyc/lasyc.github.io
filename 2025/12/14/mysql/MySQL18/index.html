错误日志

错误日志是 MySQL 中最重要的一类日志，记录了 MySQL 在启动、运行、停止过程中出现的严重错误信息。当数据库出现异常无法正常使用时，应该第一时间查看这个日志。

错误日志默认开启，默认存放在 /var/log 目录下，文件名为 mysqld.log；也可以通过 log_error 系统变量查看（或指定）日志文件的位置

二进制日志

二进制日志（binlog）中记录了所有会导致数据变化的操作：DDL 和 DML 语句（不记录 DQL 查询）。MySQL 8.0 起二进制日志默认开启。

注意区分：binlog 是 Server 层的逻辑日志（记录已提交的操作），用于数据恢复和主从复制；redo log 是 InnoDB 引擎层的物理日志（记录数据页的修改），用于崩溃恢复。

二进制日志文件的具体位置可以通过 log_bin 等系统变量查看

二进制日志作用：

  1. 灾难时的数据恢复
  2. MySQL 的主从复制

二进制日志在存储时有多种格式，不同格式记录的内容不同，可以通过 binlog_format 系统变量查看或设置

格式 含义
STATEMENT 基于 SQL 语句的日志记录，记录的是 SQL 语句，对数据进行修改的 SQL 都会记录在日志文件中
ROW 基于行的日志记录，记录的是每一行的数据变更（默认）
MIXED 混合了 STATEMENT 和 ROW 两种格式，默认采用 STATEMENT，在特殊情况下会切换为 ROW 模式

二进制日志删除：

指令 作用
reset master 删除全部日志，重置日志编号
purge master logs to ‘binlog.xxxxxx’ 删除 xxxxxx 编号之前的所有日志
purge master logs before ‘yyyy-mm-dd hh24:mi:ss’ 删除指定时间之前的所有日志

另外也可以在 MySQL 配置文件中设置 binlog_expire_logs_seconds（二进制日志过期时间，单位秒），让服务器自动删除过期的日志文件

查询日志

查询日志（general log）记录了发到 MySQL 的所有 SQL 语句（包括查询）。它默认是关闭的（因为记录量大、影响性能），需要时通过 general_log 系统变量开启，用 general_log_file 查看日志文件位置

慢查询日志

慢查询日志记录了所有执行时间超过阈值的 SQL 语句，用于定位性能瓶颈。阈值通过 long_query_time 系统变量设置：默认 10（秒），最小为 0，精度可以到微秒。慢查询日志默认是关闭的，通过 slow_query_log 系统变量开启

默认情况下，慢查询日志不会记录管理语句和未使用索引的查询语句。如果需要记录这两类语句，可以通过 log_slow_admin_statements 和 log_queries_not_using_indexes 系统变量开启
