MySQL 分库分表

发表于2025-12-15|更新于2026-09-03
|浏览量:

介绍

在之前的文章中，所有数据都保存在同一个数据库中。随着数据量增长，SQL 的执行效率会越来越低，单个数据库总有一天会达到瓶颈（任何软件、硬件都有上限）。

分库分表由此诞生：把数据拆分到多个数据库、多张表中，降低单一数据库（表）的数据量和访问压力

拆分策略

拆分策略有两种：垂直拆分和水平拆分；每种策略的拆分对象又分为分库和分表（组合起来就是：垂直分库、垂直分表、水平分库、水平分表）

垂直拆分

垂直分库

垂直分库：以表为单位，把不同业务的表拆分到不同的数据库中（例如把用户表、订单表、商品表分到三个库）。

  1. 每个库的表结构不一致（各存各的业务表）
  2. 每个库的数据不一致
  3. 所有库的表合起来才是全量数据

垂直分表

垂直分表：以**字段（列）**为单位，把一张表里的字段拆分到多张表中（通常把 text 等大字段或低频访问的字段拆到另一张表）。

  1. 每张表的字段结构不一致
  2. 每张表的数据行一一对应（1 对 1 关系），通过相同的主键关联
  3. 所有表的字段合起来才是全量字段

水平拆分

水平分库

水平分库：以行为单位，把同一张表的数据按照某种规则（如按 id 取模、按时间范围）分散到多个库的同名表中。

  1. 每个库的表结构一致（都是同一张表）
  2. 每个库只存一部分数据
  3. 所有库的数据合起来才是全量数据

水平分表

水平分表：以行为单位，把一张表的数据拆到多张结构相同的表里（单表数据量超过上限时使用）。

  1. 每张表结构一致
  2. 每张表只存一部分数据
  3. 所有表的数据合起来才是全量数据

实现技术

采用分库分表后，应用在访问数据库时必须知道目标数据在哪个库、哪张表，路由逻辑会带来额外的开发负担。目前市面上已有比较成熟的技术方案：

  1. ShardingJDBC（ShardingSphere-JDBC）：以 jar 包形式嵌入应用，在 JDBC 层对 SQL 进行拦截、解析、改写、路由，分片规则需要自己编码配置，目前只支持 Java 生态，性能损耗较小
  2. MyCat：独立部署的数据库中间件，对应用透明（不用改代码就能接入），支持多种语言，但多一次网络转发，性能略低于 ShardingJDBC

MyCat 概述

MyCat 是一个开源的、活跃的、基于 Java 语言编写的 MySQL 数据库中间件，可以像使用 MySQL 一样来使用 MyCat，从 Server → MySQL 变成了 Server → MyCat → MySQL

因为 MyCat 是基于 Java 语言开发的，所以想要运行它，必须要安装 Java 虚拟机 JDK
