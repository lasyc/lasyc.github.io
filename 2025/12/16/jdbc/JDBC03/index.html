JDBC Statement 与 PreparedStatement

发表于2025-12-16|更新于2026-09-12|后端数据库JDBC
|总字数:2.1k|阅读时长:9分钟|浏览量:

操作和访问数据库

前面学习了如何连接数据库，拿到数据库连接后就可以操作数据库了。Java 提供了三个接口用于操作数据库：

  1. Statement：用于执行静态 SQL 语句并返回结果
  2. PreparedStatement：SQL 语句被预编译并保存在此对象中，可以使用此对象多次高效的执行该语句
  3. CallableStatement：用于执行 SQL 存储过程

Statement

Statement 只能执行静态 SQL：SQL 语句在执行前就已经确定。如果想把用户输入拼进去，只能通过字符串拼接，而这样做很容易产生 SQL 注入的问题

SQL 注入：攻击者利用输入控件，在程序没有对输入内容做充分校验的情况下，向输入中注入非法的 SQL 片段，从而操纵 SQL 引擎执行恶意操作的做法

因此 PreparedStatement 诞生了：它提供了对应的方法来设置 SQL 参数（占位符），参数与 SQL 结构分离，从而有效避免了因字符串拼接产生的 SQL 注入问题

PreparedStatement

前面了解到 Statement 可以执行 SQL 语句，但它有两个弊端：

  1. SQL 一旦带参数，就只能通过字符串拼接
  2. 拼接的方式存在 SQL 注入问题

PreparedStatement 就是为了解决这两个问题而生的：它是 Statement 的子接口，SQL 会先被预编译（语法结构固定），参数通过 ? 占位符 + setXxx() 单独设置，之后作为纯数据传入，无法再改变 SQL 结构，因此注入会失效

SQL 注入

为什么这次注入失效了？因为使用 ? 占位符后，SQL 的语法结构在预编译阶段就已固定：即使用户输入 a' OR 1 = 1 --，它也只会被当作 username = ? 里的一个普通字符串值（驱动会做转义处理），不会参与 SQL 语法解析，自然也就无法注释掉后面的条件。

JDBCUtils 获取连接/释放资源

每次执行 SQL 时都要获取连接和释放资源，为了避免重复编写代码，可以将该操作封装成工具类
