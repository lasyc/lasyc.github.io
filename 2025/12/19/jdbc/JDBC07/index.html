批量插入

在增删改操作中：DELETE、UPDATE 天然就支持”批量”——一条 SQL 通过 WHERE 条件就能影响多行；而 INSERT 一次只能插入一行（除多值语法外），所以要插入大量数据时，只能一条一条地执行

优化

上面的写法虽然用了 PreparedStatement（比 Statement 拼接 SQL 快），但本质上还是一条一条地插入。可以先把 SQL 攒进 Batch，凑够一批后一次性发给 MySQL 执行，减少与 MySQL 的交互次数，以此提升效率，建议每组 1000 条。

需要掌握三个方法：addBatch() 把当前 SQL 加入批；executeBatch() 执行批中所有 SQL；clearBatch() 清空批。

MySQL 驱动默认不会合并发送批量语句：即使调用了 addBatch()，攒下的 SQL 仍是一条一条发给 MySQL，收益有限。需要在该连接的 url 末尾追加参数 rewriteBatchedStatements=true，驱动才会把同一条 INSERT 的多批参数重写成一条多值 INSERT 一次发送，批量插入的效率才能真正提升

再优化

可以看到，通过 Batch 操作，批量插入的耗时已经大幅下降（示例中约 21072ms → 456ms）。不过还可以再优化：把多条 SQL 放进同一个事务里提交，减少反复开启、提交事务的开销。为了让优化效果更明显，下面把插入条数增大到 1000000 条

在 MySQL 中，事务默认是自动提交的：每执行一条 SQL 都相当于一次”开启事务 + 提交事务”，当 SQL 条数非常多时，频繁提交也会带来不小的性能损耗。因此可以关闭事务自动提交（setAutoCommit(false)），等 100 万条 SQL 全部执行完毕后，再手动 commit() 一次，从而减少频繁提交事务的性能损耗

注意：关闭自动提交后，如果中途抛出异常，需要执行 connection.rollback()（或依赖连接关闭时未提交事务自动回滚），避免留下半截数据。
