Java Web HTTP 协议与请求响应

发表于2026-03-23|更新于2026-09-12|后端语言基础Java Web

HTTP 协议

什么是 HTTP

HTTP（Hyper Text Transfer Protocol，超文本传输协议）是互联网上应用最广泛的协议之一，是万维网（World Wide Web，WWW）数据通信的基础。另外注意：W3C 指的是 World Wide Web Consortium（万维网联盟），它是制定 Web 相关标准的组织，不要与 WWW 混淆。

HTTP 是一个请求-响应协议，即浏览器向服务器请求数据，服务器返回数据给浏览器

HTTP 协议格式

根据不同的请求方式，协议格式如下：

GET 请求

请求行

  1. 请求方式：GET
  2. 请求资源路径：/servlet_study/api/context
  3. HTTP 协议版本：HTTP/1.1

请求头

  1. Accept：表示浏览器可以接收的 MIME 类型
  2. Accept-Encoding：表示浏览器可以接收的压缩编码
  3. Accept-Language：表示浏览器可以接收的语言
  4. Connection：表示浏览器是否保持连接
  5. Cookie：表示浏览器发送给服务器的 Cookie
  6. Host：表示请求的域名和端口号
  7. Sec-Fetch-Dest：表示浏览器的请求目的
  8. Sec-Fetch-Mode：表示浏览器的请求模式
  9. Sec-Fetch-Site：表示浏览器的请求来源
  10. Sec-Fetch-User：表示浏览器的请求用户
  11. Upgrade-Insecure-Requests：表示浏览器是否允许不安全的请求
  12. User-Agent：表示浏览器信息
  13. sec-ch-ua：表示浏览器的品牌和版本信息
  14. sec-ch-ua-mobile：表示浏览器是否运行在移动设备上
  15. sec-ch-ua-platform：表示浏览器运行的操作系统平台

POST 请求

请求行

  1. 请求方式：POST
  2. 请求资源路径：/servlet_study/api/context
  3. HTTP 协议版本：HTTP/1.1

请求头：与 GET 请求相比，POST 请求多了请求体，因此请求头中包含 Content-Type、Content-Length 等与请求体相关的字段；在请求头与请求体之间，用一个空行分隔

  1. Cache-Control：表示缓存控制
  2. Content-Length：表示请求体的长度
  3. Content-Type：表示请求体的 MIME 类型
  4. Origin：表示请求的来源
  5. Referer：表示请求的来源

请求体：发送给服务器的数据

常用请求头

  1. Accept：表示浏览器可以接收的 MIME 类型
  2. Accept-Encoding：表示浏览器可以接收的压缩编码
  3. Accept-Language：表示浏览器可以接收的语言
  4. User-Agent：表示浏览器信息
  5. Host：表示请求的域名和端口号
  6. Referer：表示请求的来源
  7. Cookie：表示浏览器发送给服务器的 Cookie

HTTP 响应格式

响应行

  1. HTTP 协议版本：HTTP/1.1
  2. 状态码：表示响应的状态码

响应头

  1. Content-Type：表示响应体的 MIME 类型
  2. Content-Length：表示响应体的长度
  3. Date：表示响应的时间
  4. Keep-Alive：表示浏览器是否保持连接
  5. Connection：表示浏览器是否保持连接

响应体

状态码

  1. 200：表示请求成功
  2. 404：表示请求的资源不存在
  3. 500：表示服务器内部错误
  4. 302：表示重定向
  5. 403：表示请求被禁止
  6. 400：表示请求错误

MIME 类型

MIME（Multipurpose Internet Mail Extensions，多用途因特网邮件扩展）是一种用于描述互联网资源类型的标准。

常见 MIME 类型

类型 描述
application/json JSON 数据
application/xml XML 数据
application/octet-stream 二进制数据
application/x-www-form-urlencoded 表单数据
text/html HTML 数据
text/plain 文本数据
image/jpeg JPEG 图片
image/png PNG 图片
audio/mpeg MP3 音频
video/mp4 MP4 视频
application/pdf PDF 文件
application/zip ZIP 文件

HttpServletRequest 类

HttpServletRequest 类封装了客户端的请求，提供了一系列方法，用于获取请求参数、请求头、请求体、请求方法、请求路径等信息。

方法 描述
Cookie[] getCookies() 返回一个数组，包含客户端发送该请求的所有的 Cookie 对象
Enumeration getAttributeNames() 返回一个枚举，包含提供给该请求可用的属性名称
Enumeration getHeaderNames() 返回一个枚举，包含在该请求中包含的所有的头名
Enumeration getParameterNames() 返回一个 String 对象的枚举，包含在该请求中包含的参数的名称
HttpSession getSession() 返回与该请求关联的当前 session 会话，或者如果请求没有 session 会话，则创建一个
HttpSession getSession(boolean create) 返回与该请求关联的当前 HttpSession，或者如果没有当前会话，且创建是真的，则返回一个新的 session 会话
Locale getLocale() 基于 Accept-Language 头，返回客户端接受内容的首选的区域设置
Object getAttribute(String name) 以对象形式返回已命名属性的值，如果没有给定名称的属性存在，则返回 null
ServletInputStream getInputStream() 使用 ServletInputStream，以二进制数据形式检索请求的主体
String getAuthType() 返回用于保护 Servlet 的身份验证方案的名称，例如 “BASIC” 或 “SSL”，如果 JSP 没有受到保护则返回 null
String getCharacterEncoding() 返回请求主体中使用的字符编码的名称
String getContentType() 返回请求主体的 MIME 类型，如果不知道类型则返回 null
String getContextPath() 返回指示请求上下文的请求 URI 部分
String getHeader(String name) 以字符串形式返回指定的请求头的值
String getMethod() 返回请求的 HTTP 方法的名称，例如，GET、POST 或 PUT
String getParameter(String name) 以字符串形式返回请求参数的值，或者如果参数不存在则返回 null
String getPathInfo() 当请求发出时，返回与客户端发送的 URL 相关的任何额外的路径信息
String getProtocol() 返回请求协议的名称和版本
String getQueryString() 返回包含在路径后的请求 URL 中的查询字符串
String getRemoteAddr() 返回发送请求的客户端的互联网协议（IP）地址
String getRemoteHost() 返回发送请求的客户端的完全限定名称
String getRemoteUser() 如果用户已通过身份验证，则返回发出请求的登录用户，或者如果用户未通过身份验证，则返回 null
String getRequestURI() 从协议名称直到 HTTP 请求的第一行的查询字符串中，返回该请求的 URL 的一部分
String getRequestedSessionId() 返回由客户端指定的 session 会话 ID
String getServletPath() 返回调用 JSP 的请求的 URL 的一部分
String[] getParameterValues(String name) 返回一个字符串对象的数组，包含所有给定的请求参数的值，如果参数不存在则返回 null
boolean isSecure() 返回一个布尔值，指示请求是否使用安全通道，如 HTTPS
int getContentLength() 以字节为单位返回请求主体的长度，并提供输入流，或者如果长度未知则返回 -1
int getIntHeader(String name) 返回指定的请求头的值为一个 int 值
int getServerPort() 返回接收到这个请求的端口号
getParameterMap() 以 Map<String, String[]> 形式返回请求的所有参数

请求转发

请求转发是指服务器在接收到客户端请求后，将请求转发给服务器内部的另一个资源来处理，再把处理结果返回给客户端。

使用 getRequestDispatcher() 方法获取 RequestDispatcher 对象，然后调用 forward() 方法即可完成转发。请求转发具有以下特点：

  1. 地址栏 URL 不会发生变化，整个过程被视为一次请求
  2. 转发前后的资源共享同一个 request 对象，因此可以获取到请求参数，也可以在 request 域中存取数据
  3. 只能转发到当前应用内部的资源，不能转发到外部网站

base 标签

当我们使用相对路径进行页面跳转时，如果参照的基准路径发生了变化，那么就会导致相对路径解析错误，以至于找不到页面。

我们可以使用 base 标签来解决这个问题。base 标签可以设置一个默认的基础 URL，当页面中使用相对路径时，会自动以这个基础 URL 为基准进行拼接。

  1. 采用直接跳转的方式时，URL 为 http://localhost:8080/servlet_study/a/b/c/c.html，因此通过相对路径可以得到转换后的路径是 http://localhost:8080/servlet_study/index.jsp
  2. 但是采用重定向跳转的方式时，URL 为 http://localhost:8080/servlet_study/api/servlet1，相对路径的基准变成了 http://localhost:8080/servlet_study/api/，因此通过相对路径转换后可能得到错误的路径，这才导致无法找到页面

路径

  1. 相对路径：从当前页面出发，按照路径找到目标页面
  2. 绝对路径：从根目录出发，按照路径找到目标页面

在 Java Web 工程中，当相对路径由浏览器（客户端）解析时，/ 会被解析成服务器根路径 http://localhost:8080/；而当相对路径由服务器端解析时（如转发、重定向），/ 会被解析成当前工程根路径 http://localhost:8080/servlet_study/。

HttpServletResponse 类

HttpServletResponse 类用于向客户端发送响应，可以通过一系列方法来设置响应头、响应体、响应状态码等信息。

头信息 描述
Allow 这个头信息指定服务器支持的请求方法（GET、POST 等）
Cache-Control 这个头信息指定响应文档在何种情况下可以安全地缓存，其取值有 public、private、no-cache 等。public 表示文档可以被缓存；private 表示文档仅供单个用户使用，只能存储在私有（非共享）缓存中；no-cache 表示文档不应被缓存
Connection 这个头信息指示浏览器是否使用持久 HTTP 连接。值 close 表示不使用持久连接，值 keep-alive 表示使用持久连接
Content-Disposition 这个头信息可以让您请求浏览器要求用户以给定名称的文件把响应保存到磁盘
Content-Encoding 在传输过程中，这个头信息指定页面的编码方式
Content-Language 这个头信息表示文档编写所使用的语言，例如 en、en-us、ru 等
Content-Length 这个头信息指示响应体的字节数。当浏览器使用持久（keep-alive）HTTP 连接时，需要通过它来判断响应是否接收完毕
Content-Type 这个头信息提供了响应文档的 MIME（Multipurpose Internet Mail Extension）类型
Expires 这个头信息指定内容过期的时间，在这之后内容不再被缓存
Last-Modified 这个头信息指示文档的最后修改时间。之后客户端可以缓存该文件，并在后续请求中通过 If-Modified-Since 请求头携带该时间，用于判断资源是否被修改过
Location 这个头信息应包含在 3xx 重定向类响应中，用于通知浏览器新的文档地址。浏览器会自动向该地址发起新的请求并获取新的文档
Refresh 这个头信息指定浏览器在多长时间后刷新页面，您可以指定刷新的秒数
Retry-After 这个头信息可以与 503（Service Unavailable 服务不可用）响应配合使用，这会告诉客户端多久就可以重复它的请求
Set-Cookie 这个头信息指定一个与页面关联的 cookie

方法 描述
String encodeRedirectURL(String url) 为 sendRedirect 方法中使用的指定的 URL 进行编码，或者如果编码不是必需的，则返回 URL 未改变
String encodeURL(String url) 对包含 session 会话 ID 的指定 URL 进行编码，或者如果编码不是必需的，则返回 URL 未改变
boolean containsHeader(String name) 返回一个布尔值，指示是否已经设置已命名的响应报头
boolean isCommitted() 返回一个布尔值，指示响应是否已经提交
void addCookie(Cookie cookie) 把指定的 cookie 添加到响应
void addDateHeader(String name, long date) 添加一个带有给定的名称和日期值的响应报头
void addHeader(String name, String value) 添加一个带有给定的名称和值的响应报头
void addIntHeader(String name, int value) 添加一个带有给定的名称和整数值的响应报头
void flushBuffer() 强制任何在缓冲区中的内容被写入到客户端
void reset() 清除缓冲区中存在的任何数据，包括状态码和头
void resetBuffer() 清除响应中基础缓冲区的内容，不清除状态码和头
void sendError(int sc) 使用指定的状态码发送错误响应到客户端，并清除缓冲区
void sendError(int sc, String msg) 使用指定的状态发送错误响应到客户端
void sendRedirect(String location) 使用指定的重定向位置 URL 发送临时重定向响应到客户端
void setBufferSize(int size) 为响应主体设置首选的缓冲区大小
void setCharacterEncoding(String charset) 设置被发送到客户端的响应的字符编码（MIME 字符集），例如 UTF-8
void setContentLength(int len) 设置在 HTTP Servlet 响应中的内容主体的长度，该方法设置 HTTP Content-Length 头
void setContentType(String type) 如果响应还未被提交，设置被发送到客户端的响应的内容类型
void setDateHeader(String name, long date) 设置一个带有给定的名称和日期值的响应报头
void setHeader(String name, String value) 设置一个带有给定的名称和值的响应报头
void setIntHeader(String name, int value) 设置一个带有给定的名称和整数值的响应报头
void setLocale(Locale loc) 如果响应还未被提交，设置响应的区域
void setStatus(int sc) 为该响应设置状态码

响应流

如果想要向客户端发送数据，则需要使用流，流分为字节流和字符流两种。

  1. 字节流：getOutputStream()，用于文件下载等二进制数据
  2. 字符流：getWriter()，用于字符串或文本信息

请求重定向

请求重定向是指：服务器在接收到请求后，由于种种原因无法直接提供服务，于是在响应中告诉客户端一个新的请求地址，客户端接收到该地址后，再重新发送一次请求。

  1. 地址栏 URL 会变为重定向后的新 URL，整个过程被视为两次请求
  2. 重定向后无法获取第一次请求中的请求参数（request 域不共享）
  3. 可以自定义状态码（重定向通常使用 3xx 状态码）
  4. 可以重定向到外部网站

方式一

使用 setStatus() 和 setHeader() 方法，可以手动控制跳转

方式二

使用 sendRedirect() 方法

三层架构

Java EE 三层架构分别是：

  1. 视图展示层（表现层）：接收客户端的请求和参数，调用业务逻辑层处理业务，并把结果返回给客户端进行展示
  2. 业务逻辑层：接收视图展示层的调用，负责具体的业务逻辑处理，再调用数据访问层来存取数据
  3. 数据访问层（DAO 层）：直接与数据库交互，执行 SQL 语句，完成数据的增删改查
