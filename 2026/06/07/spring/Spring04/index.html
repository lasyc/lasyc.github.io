Spring Bean 作用域与生命周期

发表于2026-06-07|更新于2026-09-12|后端框架Spring
|总字数:2.6k|阅读时长:13分钟|浏览量:

Bean 配置进阶

P 命名空间注入

和前面通过 <util:xxx> 标签封装的方式类似，P 命名空间本质上也是一种语法糖，可以简化 XML 中属性注入的写法。

引入外部配置文件

将一些常量或者固定值（比如数据库配置）写入外部配置文件，然后在 XML 文件中引入。

  • 将 XML 文件中的硬编码改为从配置文件引入

注意：使用 ${} 占位符前，需要先通过 <context:property-placeholder> 加载属性文件，否则占位符不会被解析。例如在 XML 中配置：
<context:property-placeholder location="classpath:database.properties"/>

Bean 的作用域

在 XML 文件中，通过配置 Bean 标签的 scope 属性来指定 Bean 的作用域范围。

值 含义 何时创建
singleton（默认） 单例对象 IoC 容器初始化时
prototype 多例对象 获取 Bean 时

此外，在 Web 环境（WebApplicationContext）下还有两个额外的作用域：

值 含义
request 一个请求中
session 一个会话中
  • 单实例演示
  • 多实例演示

Bean 的生命周期

  1. 对象创建（无参构造方法）
  2. 依赖注入
  3. 后置处理器（初始化之前）
  4. 对象初始化（指定初始化方法）
  5. 后置处理器（初始化之后）
  6. 创建完成（可以使用了）
  7. 对象销毁（指定销毁方法）
  8. IoC 容器关闭
  • 添加后置处理器

FactoryBean

FactoryBean 是 Spring 提供的一种用于整合第三方框架的常用机制。与普通 Bean 不同，通过 FactoryBean 获取对象时，实际拿到的是其 getObject() 方法返回的对象。

XML 自动装配

在 XML 中配置 Bean 时，可以在 bean 标签上添加 autowire 属性实现自动装配。下面演示的是根据类型（byType）自动装配，因此同一类型只能有一个 Bean；如果是根据 id（byName）自动装配，则可以存在多个，但需要保证被注入的属性名与注入的 Bean 的 id一致。
