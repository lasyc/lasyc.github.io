Spring 基于注解的 Bean 管理

发表于2026-06-07|更新于2026-09-12|后端框架Spring
|总字数:1.3k|阅读时长:6分钟|浏览量:

基于注解进行 Bean 管理

除了 @Component 注解，还有其他注解也可以将类标记为 Spring Bean 交给 IoC 容器管理，只不过注解的名字不同，标注的位置也不同。

注解 作用
@Controller Controller 类，控制器层
@Service Service 类，业务层
@Repository Mapper 类，持久层
@Component 普通 Bean

@Autowired 属性注入

@Autowired 默认按照类型自动注入，该注解可以标注在：构造方法、方法、形参、属性上。不过 Spring 官方并不建议使用字段注入，而是推荐通过构造器注入。

@Autowired setter 注入

将 @Autowired 注解标注到 setter 方法上

@Autowired 构造方法注入

  • 如果该类中只有一个有参的构造方法，即使不添加 @Autowired 注解，也可以完成自动注入

@Autowired 形参注入

@Autowired 和 @Qualifier

@Autowired 默认根据类型注入，因此当一个接口存在多个实现类时，会因为无法确定注入哪一个而报错。此时可以再加一个 @Qualifier 注解，通过指定 Bean 的 id 来精确匹配。

@Resource

@Resource 注解并不是 Spring 框架中的注解，而是 JDK 自带的标准注解（JDK 8 及以下版本位于 javax.annotation 包中），所以该注解有更好的通用性。

@Resource 注解默认根据 ID 注入：未指定 ID 时，会使用属性名作为 ID 去查找；如果通过 ID 找不到对应的 Bean，则会改为通过类型注入。

  • 指定名字

全注解开发

舍弃 XML 配置文件，完全通过注解来进行组件扫描。
