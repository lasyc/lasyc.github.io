从上面的例子可以看出，直接在业务代码中编写日志存在两个问题：

  1. 代码冗余

所以需要把日志代码从业务代码中抽离出来，这时就引出了代理模式的思想。

静态代理

动态代理

AOP

AOP 是 Aspect Oriented Programming 的缩写，中文意思是面向切面编程。

横切关注点

横切关注点是指那些与业务逻辑无关，但又需要在多个地方重复出现的功能，比如日志记录、性能监控、事务管理等。在 AOP 中，这些横切关注点可以被独立出来，通过切面的方式应用到业务逻辑中。

通知（增强）

通知是指在特定的连接点上执行的动作。AOP 中有几种常见的通知类型：

  1. 前置通知（Before）：在目标方法执行之前执行的通知
  2. 后置通知（After）：在目标方法执行之后执行的通知，无论方法是否成功完成
  3. 返回通知（After Returning）：在目标方法成功执行之后执行的通知
  4. 异常通知（After Throwing）：在目标方法抛出异常之后执行的通知
  5. 环绕通知（Around）：在目标方法执行前后都可以执行的通知，可以控制目标方法是否执行

切面

切面是通知和切点的结合体，它定义了横切关注点的具体实现。切面可以包含多个通知，并且可以指定这些通知应用到哪些连接点上。

连接点

连接点是指程序执行过程中的一个点，比如方法的调用、异常的抛出等。在 AOP 中，连接点是通知可以插入的地方。

切入点

切入点是指一组连接点的集合，它定义了通知应用的范围。通过切入点表达式，可以指定哪些方法或类需要被增强。

基于注解

JDK 动态代理

JDK 动态代理是 Java 自带的动态代理机制，它通过反射和接口实现动态代理。JDK 动态代理只能对实现了接口的类进行代理。

CGLIB动态代理

CGLIB 动态代理是 Java 中常用的动态代理机制，它通过字节码生成和类继承实现动态代理。CGLIB 动态代理可以对没有实现接口的类进行代理，但不能对 final 类和 final 方法进行代理。

切面表达式

切面表达式是用于指定通知应用到哪些连接点上的表达式，它通常使用 AspectJ 的语法来编写。

格式：execution(访问修饰符 返回值类型 全类名.方法名(参数类型...))

例：execution(public int com.example.CalculatorImpl.sum(int, int))

  • 任意位置都可以使用*来替换，意为匹配任意内容
  • 使用*XXX、XXX*、*XXX*来匹配方法名
  • 使用..来匹配任意数量的参数

JoinPoint（连接点）

在每个通知方法中都可以通过 JoinPoint 对象获取当前连接点的信息。JoinPoint 提供了以下常用方法：

方法 说明
getArgs() 获取方法参数
getSignature() 获取方法签名
getTarget() 获取目标对象
getThis() 获取代理对象
getKind() 获取连接点类型
getSourceLocation() 获取源代码位置
getStaticPart() 获取静态部分

Returning（返回通知）

返回通知是在目标方法成功执行后触发的通知，它可以获取目标方法的返回值，并在返回值上进行处理。

注意：注解中的 returning 属性值必须与通知方法的参数名一致，否则会报错。

AfterThrowing（异常通知）

异常通知是在目标方法中发生异常后触发的通知，它可以获取目标方法的异常。

注意：注解中的 throwing 属性值必须与通知方法的参数名一致，否则会报错。

Around（环绕通知）

环绕通知是指在方法执行前后都会触发的通知。如果配置了环绕通知，目标方法就不会自动执行，需要调用 pjp.proceed() 方法手动执行目标方法，而该方法的返回值就是目标方法的返回值。

当目标方法上存在多个切面时，按照嵌套顺序由外到内依次执行。也可以通过 @Order 注解来声明优先级，数值越小优先级越高。
