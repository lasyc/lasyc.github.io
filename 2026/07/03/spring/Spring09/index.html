Spring 事务注解与传播机制

发表于2026-07-03|更新于2026-09-12|后端框架Spring
|总字数:2.4k|阅读时长:10分钟|浏览量:

@Transactional

@Transactional 注解是 Spring 框架中用于声明式事务管理的重要工具。它可以标注在类或方法上，指示 Spring 在调用该方法时启动一个新的事务，或在现有事务中执行操作。

常用属性 值 描述
readOnly true、false true 的时候，只能执行查询操作
timeout -1、具体数值 超时控制，默认为 -1，即永不超时，也可指定具体时间，单位秒
rollbackFor 异常类型 回滚策略，发生指定异常回滚
rollbackForClassName 异常类型名 回滚策略，发生指定异常回滚
noRollbackFor 异常类型 回滚策略，发生指定异常不回滚
noRollbackForClassName 异常类型名 回滚策略，发生指定异常不回滚
isolation 隔离级别 事务隔离级别
propagation 传播行为 传播行为

rollbackFor

rollbackFor 和 rollbackForClassName 可以设置发生指定异常后回滚，相反 noRollbackFor 和
noRollbackForClassName 可以设置发生指定异常后不回滚

isolation

isolation 用于设置事务的隔离级别，详情查看 MySQL 篇

值 隔离级别 问题
Isolation.DEFAULT(-1) 默认 使用数据库默认的隔离级别，MySQL 默认为可重复读
Isolation.READ_UNCOMMITTED(1) 读未提交 会发生脏读、不可重复读、幻读
Isolation.READ_COMMITTED(2) 读已提交 解决脏读问题，但会发生不可重复读、幻读
Isolation.REPEATABLE_READ(4) 可重复读 解决脏读、不可重复读问题，但会发生幻读
Isolation.SERIALIZABLE(8) 串行化 解决全部问题，不会发生任何问题，但效率最低

propagation

propagation 用于控制事务的传播行为。当两个 Service 方法都带有事务、且其中一个调用了另一个时，需要决定事务该如何传递：是加入调用者的事务？还是各自独立？还是挂起当前事务另开一个？

传播行为 描述
REQUIRED 有就加入，没有就新建
SUPPORTS 有就加入，没有就没有
MANDATORY 有就加入，没有就抛异常
REQUIRES_NEW 不管有没有，开一个新的事务，之前的事务被挂起
NOT_SUPPORTED 不使用事务，如果存在事务，就把事务挂起
NEVER 不使用事务，如果存在事务，就抛异常
NESTED 如果有事务，就在当前事务中开启一个子事务，子事务独立于外部事务
如果没有事务，和 REQUIRED 一样

REQUIRED

REQUIRED 是默认的传播行为

把余额改成小于书本价格后执行代码，会抛出异常提示余额不足。查看数据可以发现，库存并没有减少，因为 REQUIRED 会让后者使用前者的事务，当发生异常时一起回滚。

REQUIRES_NEW

REQUIRES_NEW：不论前者是否有事务，都新开一个事务

修改事务传播行为后再次执行，会发现库存依旧不变。按理说 REQUIRES_NEW 会新开一个事务，当前事务（updateBalance）抛出异常后回滚，为什么调用方（updateStock）也回滚了？原因在于：userService.updateBalance 抛出的异常没有被处理，会继续向上传播，updateStock 接收到异常后自然也会回滚。因此想要看到差异，需要先处理一下异常，确保异常不会向上传播。

现在再次执行代码可以发现，库存减少了

注意：被 catch 捕获的异常不会导致事务回滚！事务回滚依赖异常抛出并传播到事务边界（代理方法）才能被感知；异常一旦被 catch 住、没有继续向上抛，Spring 会认为方法正常结束，事务正常提交。这也正是阿里巴巴开发手册建议统一使用 rollbackFor = Exception.class 的原因——它能让受检异常（Exception）在抛出时也触发回滚。
