AOT

JIT 和 AOT

  1. JIT 是 just in time 的缩写，意为即时编译。程序运行时，JVM 把热点代码编译成机器码，即编译发生在运行过程中，特点是第一次执行慢，后续快。
  2. AOT 是 ahead of time 的缩写，意为提前编译。程序运行前，就把代码编译成机器码，即编译发生在构建阶段，特点是启动速度极快，但优化能力不如 JIT。
区别 JIT AOT
编译时机 运行时 构建时
启动速度 慢（需要预热） 快（直接执行机器码）
峰值性能 高（可以动态优化） 稍低（缺少运行时信息）
内存占用 高（JVM + 编译器本身） 低（不需要 JVM）
包体积 小（只需分发字节码） 大（包含编译后的机器码）
动态特性 完整支持（反射、动态代理） 有限制（需要提前声明）
典型代表 HotSpot JVM GraalVM、Go
跨平台 支持 不支持（需要重新编译）

GraalVM

Spring Framework 6 及以上的版本支持 AOT 技术，而 GraalVM 就是底层的技术支持。

GraalVM Native Image

GraalVM Native Image 是 GraalVM 提供的 AOT 编译技术，可以将 Java 应用（连同其依赖）直接编译成一个不依赖 JVM 的原生可执行文件。它的优势是启动速度快、内存占用低，适合 Serverless、命令行工具等场景；代价是构建时间较长，并且反射、动态代理等动态特性无法在运行时随意使用，需要提前通过配置文件（如 reflect-config.json）声明。
