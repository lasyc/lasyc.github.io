Spring MVC 获取请求参数

通过 Servlet API

参考 Servlet

使用 HttpServletRequest 获取请求参数。

通过控制器方法的形参

直接声明对应的参数即可，但要求接收参数名必须与请求参数名一致。如果参数名不一致，Spring MVC 就取不到值（会报 500），这里不细究原因，了解即可。

@RequestParam

上面的那种方式，有一个弊端就是要求接收参数名必须与请求参数名一致，此时如果不一致的情况下，就需要使用 @RequestParam 注解来进行绑定，比如：@RequestParam("username") String name，就会将请求参数 username 的值注入到 name 中。

@RequestParam 注解还有一个属性 required 用来控制该形参是否必须，默认值为 true。如果请求参数中没有该参数，或者该参数的值为空，则会报错（设置 defaultValue 不会报错）；如果改为 false，则可以不传递，还可以使用 defaultValue 来设置默认值。

属性 描述
value 将指定字段的请求参数与形参绑定，默认属性
required 该参数是否必须传递，值不能为空，默认为 true
defaultValue 当参数没有传递时，或者值为空，使用该默认值

@RequestHeader

@RequestParam 是将请求参数与形参进行绑定，而 @RequestHeader 则是将请求头参数与形参进行绑定，用法、属性同 @RequestParam 一致

@CookieValue

@CookieValue 是将 Cookie 参数与形参进行绑定，用法、属性同 @RequestParam 一致

通过 POJO 类

上面的方法只适合接收少量的参数。当参数数量过多时，我们就需要使用实体类来接收参数，同样要求实体类的成员变量名和请求参数名一致。

乱码

当编码不一致时，如果请求参数中存在汉字，则会出现乱码问题。在 Java Web 阶段，我们可以通过在 BaseServlet 中调用 HttpServletRequest 的 setCharacterEncoding 方法来设置编码格式，这样在实际的 Servlet 中再去获取参数就可以正常使用了。但是在 Spring MVC 中，请求的分发是由 DispatcherServlet 来控制的，我们在 Controller 拿到的参数是已经设置好的，即使我们再使用 setCharacterEncoding 也是没有任何效果的。

GET

GET 请求参数是放在 URL 中的，因此如果 GET 请求乱码，则需要在 Tomcat 的 server.xml 配置文件中添加 URIEncoding="UTF-8"。但 Tomcat 8 及以上版本默认就是 UTF-8，一般不需要额外配置。
