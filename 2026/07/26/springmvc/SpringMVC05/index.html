域对象

在 Java Web 阶段，我们学习过，共有四个域对象，分别是：request、session、application、pageContext。但是这里没有 JSP，所以不考虑 pageContext。

作用范围：

对象 作用范围
request 一次请求，发送请求到接收响应
session 一次会话，打开浏览器直至关闭
application 一次应用，项目启动直至关闭
pageContext 一次页面，当前 JSP 页面

向 Request 域中共享数据

使用 Servlet API 向 request 域中共享数据

  • 本质：直接操作 Servlet API，把数据放进 request 作用域
  • 层次：最底层，跟 Spring 无关
  • 视图取值：${username}

使用 ModelAndView 向 request 域中共享数据

  • 本质：ModelAndView 内部维护了一个 ModelMap 对象，addObject() 委托给内部的 modelMap 存储，最终 DispatcherServlet 把 modelMap 的数据全部写入 request attribute。

  • 特殊之处：同时掌控”数据”和”视图”，是唯一能手动指定视图的方式，其他方式的视图名由方法返回值决定。

使用 Model 向 request 域中共享数据

  • 本质：Model 是一个接口，Spring 注入的实际实现类就是 ModelMap，所以 model.addAttribute() 等价于 modelMap.addAttribute()。
  • 最终：数据进入 request attribute。

使用 Map 向 request 域中共享数据

  • 本质：Spring 注入的这个 Map 参数，实际类型就是 ModelMap，map.put() 等价于调用 modelMap.put()。
  • 最终：数据进入 request attribute。

使用 ModelMap API 向 request 域中共享数据

  • 本质：ModelMap 继承自 LinkedHashMap<String, Object>
    put() 和 addAttribute() 最终效果完全一样

  • 区别（极其微小）：
    addAttribute()：会检查 value 是否为 null，为 null 时抛异常
    put()：不检查，null 也照存不误

Model、Map、ModelMap 关系

Model、Map、ModelMap 的底层实现类其实是同一个对象 BindingAwareModelMap，但是不管使用哪一种方式，到最后都会被封装为 ModelAndView。

向 Session 域中共享数据

使用 Servlet API 向 Session 域中共享数据

使用 @SessionAttributes 向 Session 域中共享数据

@SessionAttributes 可以把 Model 中的属性暂存到 Session 中，让数据在多次请求之间共享。

@SessionAttributes 的本质就是：在 Controller 类级别声明哪些 Model 属性需要同步到 Session，实现跨请求共享。

注意事项：

要点 说明
只在 Controller 类上声明 不能放在方法上
必须配合 Model 使用 不通过 Model.addAttribute() 设置的属性不会存入 Session
用完必须清除 否则 Session 中会残留数据，造成混乱
序列化 存入 Session 的对象最好实现 Serializable

  2. 指定类型

  3. 配合 @ModelAttribute 取值

  4. 清除 Session 属性
