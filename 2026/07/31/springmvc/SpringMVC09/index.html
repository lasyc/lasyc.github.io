HttpMessageConverter

HttpMessageConverter 是 Spring MVC 中用于将 HTTP 请求和响应的消息体进行转换的接口。它可以将请求体中的数据转换为 Java 对象，也可以将 Java 对象转换为响应体中的数据。

Spring MVC 提供了两个注解用于处理请求和响应的消息体：@RequestBody 和 @ResponseBody。也提供了两个实体类用于接收和返回数据：RequestEntity 和 ResponseEntity。

请求报文

@RequestBody

@RequestBody 注解用于将 请求体中的数据绑定到方法指定参数上。它通常用于处理 POST 请求中的 JSON、XML 或其他格式的数据。

RequestEntity

RequestEntity 是 Spring MVC 提供的一个实体类，用于封装 HTTP 请求的相关信息，包括请求头、请求体和请求方法等。它可以用于接收请求体中的数据，并提供了更多的功能和灵活性。

响应报文

在 Java Web 阶段学习中，响应报文是通过 HttpServletResponse 对象来返回数据的。而 Spring MVC 中，默认的返回值会被解析为视图名称，返回给客户端的是视图页面。如果想要返回数据而不是视图页面，可以使用 @ResponseBody 注解。

@ResponseBody

@ResponseBody 注解用于将方法的返回值作为响应体返回给客户端。在 Spring MVC 中，如果使用该注解，那么返回值就不会再作为视图名称进行解析，而是作为数据返回给客户端。

发送请求后，页面并没有进行跳转，而是在空白页面上显示 success 文字

既然如此，那么直接返回对象，Spring MVC 会将对象转换为 JSON 格式的数据返回给客户端。但是这样会报错，需要引入 json 转换的依赖包。

无需任何配置，只需要添加依赖即可，再次发送请求，页面会显示 {"id":null,"name":"Tom","age":20}，说明 Spring MVC 已经将对象转换为 JSON 格式的数据返回给客户端。

如果还未生效的话看一下 springmvc-config.xml 中是否配置了 <mvc:annotation-driven />，如果没有配置的话，需要添加该配置。

@RestController

在实际开发中，包括各服务之间的数据交互，都是以 JSON 为主，因此 @ResponseBody 注解在实际开发中，经常会用到，但是如果给每个方法都添加该注解，很浪费时间，因此，Spring MVC 将 @Controller 和 @ResponseBody 连个注解结合为 @RestController，在 Controller 上使用该注解，则所有方法的返回值都会被转为 JSON

ResponseEntity

ResponseEntity 用于控制器方法的返回值类型，可以将 ResponseEntity 作为返回值返回给客户端

以往情况下，我们只能控制响应的响应体，也就是返回的数据，而 ResponseEntity 中提供了一系列的方法来设置状态码、响应头、响应体。
