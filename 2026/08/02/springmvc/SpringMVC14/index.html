初始化类 代替 web.xml

  1. 最初的 web.xml 每次都要配置一堆 xml，很繁琐

  2. Servlet 3.0 允许使用 Java 代码来代替 web.xml，但是要实现 ServletContainerInitializer 接口

  3. Spring Framework 中提供了 SpringServletContainerInitializer 实现类，帮我们进一步的做了封装

  4. 在 SpringServletContainerInitializer 中，会去寻找 WebApplicationInitializer 接口的实现类并调用

  5. 如果我们手动实现 WebApplicationInitializer 接口，那么还需要手动完成容器的注册

  6. Spring Framework 中又提供了 AbstractDispatcherServletInitializer 实现类将上述代码封装为了模板代码，我们只需要提供配置方式即可，不过因为最初都是采用 xml 配置，因此这里延续了下来，仍是 xml 配置

  7. 而后，才是 AbstractAnnotationConfigDispatcherServletInitializer 实现类，将 xml 配置改为了 Java 配置

  8. 因此，我们只需要自定义子类，继承 AbstractAnnotationConfigDispatcherServletInitializer，重写其中的方法

解释一下为什么要两个配置类分别扫描不同包

因为 DispatcherServlet 启动时会创建两个容器：Root WebApplicationContext（父容器） 和 Servlet WebApplicationContext（子容器）

如果只用一个容器（全部放在一起），这样做看似简单，但在 Spring MVC 环境下会出问题——因为 DispatcherServlet 会启动一个子容器，如果没有单独配置子容器的扫描，Controller 就不会被子容器管理，导致 RequestMapping 映射失败（请求找不到 Controller）。

如果两个配置类都扫描同一个包，同一个 Bean 会被创建两次——父容器一份，子容器一份。这会造成：

  1. 浪费内存
  2. 注入混乱（你以为注入的是 A，实际上是子容器创建的另一个 A）
  3. 事务失效（Service 被子容器重新创建，没有被父容器的事务管理器代理）

正确做法：各扫各的

并且，子容器可以"看到"父容器中的 Bean，反过来不行，因此在子容器中拥有全部的 Bean。
