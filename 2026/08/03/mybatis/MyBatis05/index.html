MyBatis 获取参数

在 MyBatis 中，获取参数的方式有多种，主要包括以下几种：${}、#{}

  1. ${}：直接将参数拼接到 SQL 语句中，适用于动态表名、列名等场景，但容易引发 SQL 注入问题。
  2. #{}：使用占位符的方式传递参数，MyBatis 会将参数值进行预编译处理，防止 SQL 注入问题，适用于大多数场景。

单个参数

使用 #{username} 的方式来获取参数，参数名不要求一致，因为只有一个参数，不存在歧义，即使叫 aaa 也可以，但是建议使用有意义的参数名

使用 ${} 来获取参数，此时会报错，因为 ${} 是直接拼接参数到 SQL 语句中，而 username 是一个字符串类型的参数，需要加上单引号 '，否则会报错。

多个参数

在多个参数的情况下，MyBatis 会将参数封装成一个 Map，并且会为每个参数生成一个默认的参数名，默认的参数名为 param1、param2、param3 等，或者 arg0、arg1、arg2 等，具体取决于 MyBatis 的版本和配置。

使用 Map 传递参数

因为 Map 是我们自己定义的，我们可以决定 key 的名称，所以在 Mapper 映射文件中，我们可以直接使用我们定义的 key 来获取参数。

使用对象传递参数

通过 #{} 的方式来获取参数，参数名必须和对象的属性名一致。

注意：这里有一个坑，MyBaits 在获取参数时，是通过 getter 方法来获取的，比如 #{username} 对应 user.getUsername()，所以即使在 User 中并不存在 username 属性，只要有 getUsername() 方法，也可以获取返回值来作为参数值。那么即使在 User 中存在 username 属性，但是没有 getUsername() 方法，也无法获取到参数值。或者如果属性名为 username，但是 getter 方法为 getUserName()，也无法获取到参数值，因为 MyBatis 是通过 getUsername() 方法来获取参数值的。

使用 @Param 注解传递参数

多个参数的情况下，MyBatis 会将参数封装成一个 Map，并且会为每个参数生成一个默认的参数名，默认的参数名为 param1、param2、param3 等，或者 arg0、arg1、arg2 等，具体取决于 MyBatis 的版本和配置。

但是这样在 Mapper 映射文件中，参数名不够直观，所以 MyBatis 提供了 @Param 注解来指定参数名，这样在 Mapper 映射文件中就可以直接使用我们指定的参数名来获取参数。

通过 @Param 注解指定参数名后，在 Mapper 映射文件中就可以直接使用我们指定的参数名来获取参数。尽管如此，我们仍可以使用默认的参数名 param1、param2 等来获取参数。

@Param 源码

getNamedParams 方法是将实际传入的参数数组 args 与前面解析出的参数名映射 names 进行绑定，最终返回一个可直接用于 SQL 取值的参数对象。
