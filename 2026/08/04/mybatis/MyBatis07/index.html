MyBatis 特殊 SQL

发表于2026-08-04|更新于2026-09-12|后端框架MyBatis
|总字数:1.2k|阅读时长:5分钟|浏览量:

模糊查询

在模糊查询中，如果直接使用 #{} 来获取参数，将会报错，因为在模糊查询的 SQL 中需要写引号，当占位符处于引号中时就无法生效。

既然 #{} 的占位符在引号内无法生效，那么我们此时就可以改用 ${} 来设置参数，因为它是直接将参数拼接到 SQL 中。

亦或者使用 SQL 中的拼接函数，总之只要让占位符不要被引号包围，就可以正常设置参数。

再或者这样拼接也可以。

批量删除

老师的案例虽然没有成功删除，但是也没有报异常，而我这里报错了：Cause: com.mysql.cj.jdbc.exceptions.MysqlDataTruncation: Data truncation: Truncated incorrect DOUBLE value: '1,2,3,4'

原因是因为 #{} 会自动添加 '，因此 SQL 会变成 IN ('1, 2, 3, 4')，导致无法删除，此时就可以改用 ${}。

动态设置表名

在学习 MySQL 的时候，我们学习过 分库分表。当不同的数据分散保存到不同的表中时，例如查询 username 要到表 1 中，查询 email 又要到表 2 中，此时 SQL 中的表名就无法写死，我们就需要动态地设置表名。

不出意外，使用 #{} 依旧会报错，还是因为 #{} 会自动添加 ' 导致的，因此这里依旧使用 ${}。

总结

根据上面的案例我们可以知道：只要在 SQL 中涉及引号的问题，#{} 都会出问题，此时只能使用 ${}，或者用拼接函数等办法，让 #{} 不被引号所影响。

添加时返回主键

当我们在添加一条记录后，如果后续的操作需要用到该条记录的 ID，那么此时就需要在添加数据时获取被添加记录的主键。

在原生的 JDBC 中，就提供了对应的方法。

而在 MyBatis 中，也提供了对应的方法，只需要在 <insert> 标签中声明 useGeneratedKeys="true" 和 keyProperty="id"。
