延迟加载

在上面的多对一中，我们通过分步执行解决了多对一的查询问题，使用这种方式，还可以解决 SQL 之间的耦合问题，而且将一个 SQL 拆分为两个，提高了 SQL 的复用性，两个 SQL 都可以独立执行，既可以查询员工信息，还可以查询部门信息，又可以查询部门加员工信息

但是，前提是必须要在 MyBaits 中开始延迟加载的配置，开启延迟加载后，当我们执行查询员工信息的 SQL 时，只会查询员工信息，但是当我们在代码中调用了 emp.getDept() 来获取部门信息时，就会触发延迟加载，此时才会去查询部门信息

设置名 描述 有效值 默认值
lazyLoadingEnabled 延迟加载的全局开关。当开启时，所有关联对象都会延迟加载。 特定关联关系中可通过设置 fetchType 属性来覆盖该项的开关状态。 true | false false
aggressiveLazyLoading 开启时，任一方法的调用都会加载该对象的所有延迟加载属性。 否则，每个延迟加载属性会按需加载（参考 lazyLoadTriggerMethods)。 true | false false （在 3.4.1 及之前的版本中默认为 true）
lazyLoadTriggerMethods 指定对象的哪些方法触发一次延迟加载。 用逗号分隔的方法列表。 equals,clone,hashCode,toString

再次执行查询语句，但是获取查询结果后我们只使用 emp 对象的信息，可以发现只查询了员工信息，而后我们再获取 dept 对象，才查询了部门信息

如果开启了全局的延迟加载，那么所有的 SQL 都会延迟加载，但是如果某个 SQL 不需要呢？可以使用 fetchType 来设置加载时机

值 加载时机
eager 立即加载
lazy 延迟加载
