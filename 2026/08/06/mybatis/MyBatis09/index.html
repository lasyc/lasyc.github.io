MyBatis 动态 SQL

动态 SQL

参考文档

在实际开发中，我们的 SQL 有时并不是固定的，而是动态的，比如字段，存在则作为查询条件，不存在则不作为条件，在 JDBC 阶段，我们可以通过分支判断、循环等语法来动态的生成 SQL 语句，而在 MyBatis 中，也为我们提供了对应的标签来实现这些功能

if 标签

if 标签同 Java 中的 if 语句逻辑一样，在 test 属性中编写表达式，表达式结果为 true 则会拼接标签内的 SQL，反之不拼接

创建一个查询员工信息的 SQL 语句，根据传入的参数动态拼接 SQL

通过测试我们可以发先，当我们传入了 empName 这个字段的时候，SQL 中就拼接了对应的条件，反之其他字段没有拼接

但是，当我们把 empName 设置为空时，使用其他条件查询，就会报错，可以看到 SQL 语句很奇怪，WHERE 后边拼接了 AND，这正是因为 empName 为空，导致跳过了第一个条件，WHREE 直接和后边的 SQL 拼接了

解决办法也很简单，只需要在 WHERE 后边添加 1 = 1 即可，这样即使 empName 为 null，拼接后的 SQL 也会是 WHERE 1 = 1 AND age = '男'

where 标签

上述案例虽然可以实现多条件的动态拼接，但是还是比较鸡肋的，为了防止拼接 SQL 出现问题，还需要额外写上 WHRERE 1 = 1，MyBatis 为我们提供了 where 标签，搭配 if 标签使用，即可解决该问题，在 where 标签中拼接 SQL 时，如果发现我们有多余的 AND 或者 OR 会帮我们删除，就不会再出现 WHERE AND age = '男' 的情况了

trim 标签

如果 where 标签还不能满足动态 SQL 的拼接，那么可以使用 trim 标签，它的自由度更高，允许我们更加自由的拼接 SQL

trim 标签提供了四个属性：

属性 值 作用
prefix 前缀 在整体内容前面添加的字符串
suffix 后缀 在整体内容后面添加的字符串
prefixOverrides 覆盖掉的前缀 如果内容以指定字符串开头，删掉它
suffixOverrides 覆盖掉的后缀 如果内容以指定字符串结尾，删掉它

这样我们便可以写出等价于 where 标签的 SQL 拼接方式，当然 trim 标签的功能不仅于此

choose、when、otherwise

choose、when、otherwise 这三个标签需要一起使用，相当于 Java 中的 switch...case...default，所以，当我们编写多个条件时，当有一个条件满足时，那么其余的条件都不会再进行判断，也就是说，如果 empName 和 age 都设置了值，但是一个 when 标签中的表达式成立了，那么后续的 when 标签都不在判断，如果所有的 when 标签都不满足，则使用 otherwise

foreach

foreach 标签相当于 Java 中的 for 语句，可以根据传入的 list 循环拼接 SQL 语句

属性 值 描述
collection 集合| 数组 需要遍历的集合 | 数组
item 对象 集合 | 数组中的每一项
index 下标 集合 | 数组中每一项的下标
open 字符 以指定字符开头
close 字符 以指定字符结尾
separator 字符 循环时以指定字符作为分隔符

sql、include

sql 标签可以将我们常用的 SQL 语句定义为 SQL 片段，当我们编写 SQL 时可以通过 include 标签来引用该片段，减少工作量
