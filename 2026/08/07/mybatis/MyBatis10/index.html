MyBatis 一级缓存

发表于2026-08-07|更新于2026-09-06
|浏览量:

缓存

MyBatis 为我们提供了缓存功能，也就是把查询出来的数据缓存起来，下次查询时直接读取缓存，不会再次访问数据库。

MyBatis 中的缓存分为一级缓存和二级缓存，两者的作用范围不同。

缓存 作用范围
一级缓存 同一个 SqlSession
二级缓存 同一个 SqlSessionFactory

一级缓存

一级缓存是 SqlSession 级别的，在同一个 SqlSession 下查询出来的数据会被缓存，一级缓存默认是开启的。

缓存并不是一直生效的，下面四种情况会让一级缓存失效：

  1. 不同的 SqlSession
  2. 同一个 SqlSession，但是查询条件改变了
  3. 同一个 SqlSession，两次查询之间执行了增删改操作
  4. 同一个 SqlSession，手动清空了缓存

Mapper 映射文件的编写这里省略。在测试代码中执行两次查询（同一个 SqlSession），可以看到 MyBatis 只执行了一次 SQL。

只要在同一个 SqlSession 下即可，即使两次使用的是不同的 Mapper 对象也没问题（namespace 必须一致，即同一个 Mapper 接口），因为缓存中是以 namespace 作为 key 的一部分。

二级缓存

二级缓存是 SqlSessionFactory 级别的，在同一个 SqlSessionFactory 下查询出来的数据会被缓存，二级缓存默认是关闭的。

开启二级缓存

  1. 在配置文件中设置全局配置 cacheEnabled（该配置默认就是 true，不写也可以）

  2. 在映射文件中设置 <cache />

  3. 二级缓存的数据必须在 SqlSession 关闭或提交后才会保存。

  4. 查询结果对应的实体类必须可被序列化，即实现 Serializable 接口。

Cache 标签配置

上面的代码示例只是在映射文件中添加了 cache 标签，其实该标签还有一些属性用于配置

  1. type：用于设置缓存的实现类，默认为 PerpetualCache，也可以自定义实现

  2. eviction：用于设置缓存的回收策略，默认为 LRU

    • LRU（LruCache，最近最少使用）：移除最长时间未被使用的对象
    • FIFO（FifoCache，先进先出）：按对象进入缓存的顺序移除
    • SOFT（SoftCache，软引用）：基于垃圾回收状态移除，内存不足时回收
    • WEAK（WeakCache，弱引用）：更积极地回收，下次 GC 就可能被清除

  3. flushInterval：用于设置缓存的刷新间隔，默认没有间隔，仅在执行 commit、close 时刷新，单位为 ms，指定时间后清空缓存

  4. size：用于设置缓存对象数量的上限，默认为 1024，即最多存储 1024 个对象，当达到上限后，根据 eviction 设置的回收策略回收对象

  5. readOnly：用于设置是否只读，默认为 false。设置为 true 时，多次查询从缓存中获取的都是同一个对象引用，速度快但不允许修改；设置为 false 时，获取的对象是经过深拷贝的，互不影响，更安全

  6. blocking：用于设置是否阻塞，默认为 false。设置为 true 时，如果多个线程同时查询同一个 key 而缓存未命中，只有一个线程去查数据库，其余线程会阻塞等待，等第一个线程查询完成后再从缓存中获取结果，避免缓存穿透。

缓存查询顺序

  1. 先查询二级缓存。
  2. 二级缓存不存在，再查询一级缓存。
  3. 一级缓存不存在，则查询数据库。
