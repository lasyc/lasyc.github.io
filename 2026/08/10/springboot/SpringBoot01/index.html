Spring 与 SpringBoot

发表于2026-08-10|更新于2026-08-10
|浏览量:

Spring 能做什么

Spring 是一个开源框架，它为简化 Java 企业级开发而生。Spring 框架的诞生解决了传统 JavaEE 开发中存在的诸多痛点，如代码耦合度高、配置繁琐、可测试性差等问题。

Spring 的能力

Spring 提供了丰富的功能，其主要能力包括：

  1. IOC 容器：控制反转（Inversion of Control），将对象的创建和依赖关系的管理交给 Spring 容器，实现代码的松耦合
  2. AOP 切面：面向切面编程（Aspect-Oriented Programming），将日志、事务、权限等横切关注点从业务逻辑中剥离，提高代码的模块化程度
  3. 事务管理：提供声明式事务和编程式事务两种方式，屏蔽底层数据库事务的差异
  4. 数据访问：对 JDBC、MyBatis、Hibernate、JPA 等数据访问技术进行整合与封装，简化持久层开发
  5. Web 开发：提供 Spring MVC 框架，帮助开发者快速构建 Web 应用程序
  6. 消息服务：支持 JMS、AMQP 等消息中间件，实现应用间的异步通信
  7. 测试支持：提供完善的单元测试和集成测试支持，如 Spring TestContext Framework

Spring 的生态

Spring 早已不再是一个单一的框架，而是一个庞大的生态系统，覆盖了 Java 开发的方方面面：

  • Spring Framework：Spring 生态的核心基础，提供 IOC、AOP、事务、MVC 等基础能力
  • Spring Boot：简化 Spring 应用的搭建与配置，实现”约定大于配置”，快速构建独立运行的微服务
  • Spring Cloud：基于 Spring Boot 的微服务解决方案，提供服务注册与发现、配置中心、网关、熔断等能力
  • Spring Data：统一数据访问层的开发，支持关系型数据库（JPA、JDBC）和非关系型数据库（Redis、MongoDB、Elasticsearch 等）
  • Spring Security：提供认证与授权等安全能力，是 Java Web 应用安全的标准选择
  • Spring Batch：面向批处理场景的解决方案，支持大数据量的定时批量处理
  • Spring Integration：基于企业集成模式（EIP）的集成解决方案
  • Spring Cloud Alibaba：阿里巴巴开源微服务解决方案，提供了 Nacos、Sentinel、Seata 等组件

在整个生态中，Spring Boot 是当今 Java 后端开发的事实标准，它让 Spring 应用的开发变得前所未有的简单。

Spring5 重大升级

Spring 5 于 2017 年 9 月正式发布，是 Spring Framework 的重要里程碑版本，主要带来了以下重大升级：

  1. JDK 版本要求提升：Spring 5 要求 JDK 8 及以上版本，全面拥抱 Java 8 新特性（Lambda 表达式、Stream API 等）
  2. 响应式编程：引入全新的 WebFlux 响应式 Web 框架
  3. Kotlin 支持：为 Kotlin 提供了语言级别的支持，可以使用 Kotlin 编写 Spring 应用
  4. 函数式编程：支持函数式风格的 Bean 注册和 Web 路由配置
  5. JUnit 5 支持：Spring Test 全面支持 JUnit 5
  6. Null 安全检查：通过 @Nullable、@NonNull 等注解提供空指针安全检查
  7. 日志框架改造：不再依赖 JCL（commons-logging），改用 spring-jcl 自带日志封装

响应式编程

  • 什么是响应式编程：响应式编程是一种面向数据流和变化传播的编程范式，核心思想是”异步非阻塞”，当数据流发生变化时自动将变化传播给订阅者
  • Reactive Streams 规范：Spring 5 遵循 Reactive Streams 规范，提供了 Publisher（发布者）、Subscriber（订阅者）、Subscription（订阅关系）、Processor（处理器）四大核心接口
  • Reactor 框架：Spring 5 默认使用 Reactor 作为响应式编程的基础库，提供了 Mono（0 或 1 个元素）和 Flux（0 到 N 个元素）两种响应式类型
  • WebFlux 框架：基于响应式编程的全新 Web 框架，与传统的 Spring MVC（基于 Servlet，同步阻塞）相比，WebFlux 使用少量线程即可支撑高并发场景

注意：响应式编程的学习曲线较陡，在本系列课程中只做了解，重点掌握 Spring Boot 的常规用法即可。

内部源码设计

Spring 5 在内部源码设计上也做了大量优化与重构：

  1. 全面基于 Java 8：源码中大量使用 Lambda 表达式、Stream API、Optional、接口默认方法等 Java 8 新特性，代码更简洁、更易读
  2. 响应式核心支持：spring-core 模块新增了对响应式编程的支持，如 ReactiveAdapterRegistry（响应式适配器注册表）用于统一不同类型响应式库之间的转换
  3. 组件扫描优化：改进了注解驱动的配置方式，@ComponentScan 支持 @Indexed 注解，通过编译期生成索引文件（META-INF/spring.components）来加速启动时的组件扫描
  4. 可观察性：引入 spring-jcl 取代 commons-logging，日志系统更加统一；同时提供了对监控指标的支持
  5. 并发改进：优化了内部锁与缓存机制，如 SimpleAliasRegistry、DefaultSingletonBeanRegistry 等核心类的高并发性能
  6. 函数式 Bean 注册：新增 GenericApplicationContext#registerBean 函数式注册方式，可以不用注解和 XML 就能注册 Bean

Spring 5 的源码设计为后续 Spring Boot 2.x 的快速启动、自动配置等能力奠定了坚实基础。

为什么用 SpringBoot

Spring Boot 是 Spring 官方推出的用于简化 Spring 应用初始搭建以及开发过程的全新框架，它的核心理念是”约定大于配置“，目标是让开发者快速创建出生产级别的 Spring 应用。

在 Spring Boot 出现之前，传统 Spring 项目的开发存在诸多痛点：

  • 需要编写大量的 XML 配置（数据源、事务、组件扫描等）
  • 依赖版本由开发者自己管理，经常出现版本冲突
  • 需要手动安装并配置外部 Web 服务器（如 Tomcat），部署繁琐
  • 缺乏开箱即用的监控、健康检查等生产级能力

Spring Boot 的出现彻底改变了这一局面，让 Spring 应用的开发变得简单、高效、可靠。

SpringBoot 优点

  1. 创建独立的 Spring 应用：可以打成一个可执行的 jar 包，通过 java -jar 命令独立运行，无需外部容器
  2. 内嵌 Web 服务器：内嵌 Tomcat、Jetty、Undertow 等服务器，无需部署 war 包，开箱即用
  3. 自动 starter 依赖，简化构建配置：引入一个 starter 即可获得一组功能相关的依赖，版本由 Spring Boot 统一管理，不再担心版本冲突
  4. 自动配置 Spring 以及第三方功能：根据项目中的依赖自动配置数据源、MyBatis、Redis、消息队列等，开发者只需关注少量自定义配置
  5. 提供生产级别的监控、健康检查及外部化配置：集成 Spring Boot Actuator，开箱即用地提供健康检查、指标监控等功能；通过 application.yml 即可实现不同环境的外部化配置
  6. 无代码生成，无需编写 xml：不生成任何代码，也不需要编写 XML 配置，全部基于注解和 Java 配置

SpringBoot 缺点

  1. 迭代快：Spring Boot 版本更新频繁，新特性层出不穷，开发者需要持续跟进版本变化，学习成本较高
  2. 封装深：自动配置封装程度深，相当于一个”黑盒”，当出现问题时排查难度大，需要深入理解其底层原理才能”救火”

正因如此，学习 Spring Boot 之前必须先打好 Spring Framework 的基础，知其然更要知其所以然。

时代背景

为什么 Spring Boot 会成为 Java 后端开发的事实标准？这背后是互联网技术架构演进的时代背景——从单体应用走向微服务、分布式、云原生。

微服务

  • 什么是微服务：微服务是一种架构风格，将一个大型的单一应用程序拆分为一组小型、独立的服务，每个服务围绕具体业务能力构建，可独立开发、独立部署、独立扩展
  • 与单体架构的对比：单体架构将所有功能打包在一个应用中，开发简单但后期维护困难、部署成本高；微服务架构将功能拆分后，各团队可独立迭代，系统整体可用性更高
对比项 单体架构 微服务架构
部署 整体部署，牵一发动全身 按服务独立部署
扩展 只能整体扩展 按需扩展单个服务
技术栈 单一技术栈 每个服务可选择合适的技术栈
维护 代码臃肿，维护困难 服务职责单一，易于维护
通信 进程内方法调用 跨进程网络调用（REST、RPC）
  • 微服务的落地：Spring Boot 让单个微服务的开发变得简单，而 Spring Cloud 则提供了一整套微服务治理方案（服务注册与发现、配置中心、网关、熔断等）

分布式

分布式系统是指多个节点（计算机）通过网络协同工作，对外表现为一个整体系统的架构模式。微服务架构本质上就是一种分布式系统。

分布式的困难

分布式系统虽然强大，但也带来了单体架构中不曾遇到的难题：

  1. 网络不可靠：网络延迟、丢包、分区（Partition）随时可能发生，调用远程服务可能超时或失败
  2. 数据一致性：数据分散在多个节点上，保证数据一致非常困难，由此引出著名的 CAP 定理（一致性、可用性、分区容错性三者不可兼得）
  3. 分布式事务：一次业务操作可能跨多个服务、多个数据库，传统本地事务无法保证全局一致性
  4. 服务发现与负载均衡：服务实例的地址是动态变化的，如何找到可用的服务实例、如何分配请求压力
  5. 故障排查困难：一次请求可能经过多个服务，出现问题后难以定位故障点（需要链路追踪）
  6. 时钟问题：分布式环境下各节点时钟不同步，导致事件排序困难

分布式的解决

针对上述困难，业界发展出了一系列成熟的解决方案：

  • 网络不可靠：引入超时重试、熔断降级（如 Sentinel、Hystrix）、幂等设计等机制
  • 数据一致性：通过最终一致性方案（如消息队列异步补偿、Seata 分布式事务框架）在一致性与可用性之间取得平衡
  • 服务发现与负载均衡：使用注册中心（Nacos、Eureka、Zookeeper）+ 负载均衡组件（Ribbon、LoadBalancer）解决
  • 故障排查：使用链路追踪（Sleuth + Zipkin）和集中式日志系统定位问题
  • 配置管理：使用配置中心（Nacos Config、Spring Cloud Config）统一管理各服务的配置

云原生

云原生（Cloud Native）是一种充分利用云计算优势构建和运行应用程序的方法论，它以容器、微服务、服务网格、不可变基础设施和声明式 API 为代表。

上云的困难

将传统应用迁移到云上并非简单地把应用”搬”上去，而是面临诸多挑战：

  1. 应用改造：传统单体应用难以直接享受云的弹性伸缩能力，需要拆分为可水平扩展的微服务
  2. 环境不一致：开发、测试、生产环境不一致，导致”在我电脑上能跑”的问题频发
  3. 运维复杂度上升：服务数量增多后，部署、升级、监控、故障恢复等运维工作成倍增长
  4. 资源利用率低：传统部署方式资源利用率低、成本高，缺乏弹性

上云的解决

  • 容器化：使用 Docker 将应用及其依赖环境打包成镜像，彻底解决环境不一致问题，实现”一次构建，到处运行”
  • 容器编排：使用 Kubernetes（K8s）实现容器的自动部署、弹性伸缩、负载均衡与自愈
  • DevOps：通过持续集成/持续部署（CI/CD）流水线，实现应用的快速、自动化交付
  • 云原生基础设施：使用不可变基础设施、声明式 API 管理应用，让运维从”手工操作”变为”声明期望状态”

云原生是当前技术发展的大趋势，而 Spring Boot 正是构建云原生 Java 应用的基础——快速启动、内嵌容器、Actuator 健康检查等特性，使其天然适配容器化和 Kubernetes 环境。

如何学习 SpringBoot

Spring Boot 内容庞杂、封装深入，建议按照以下路径循序渐进地学习：

  1. 夯实 Spring 基础：先掌握 Spring Framework 的 IOC、AOP、事务管理等核心知识，这是理解 Spring Boot 自动配置的前提
  2. 掌握核心用法：从创建一个 Hello World 项目开始，逐步掌握自动配置原理、配置文件（application.yml）、常用注解（@Configuration、@Bean、@Conditional 等）
  3. 熟悉 Web 开发：掌握 Spring Boot 集成 Spring MVC 开发 RESTful 接口，以及参数校验、异常处理、拦截器、过滤器等
  4. 掌握数据访问：学习 Spring Boot 整合 MyBatis、JPA、Redis、MySQL，理解数据源自动配置与事务管理
  5. 学习整合第三方技术：如 RabbitMQ、Elasticsearch、定时任务（Quartz）、邮件发送等，体会 starter 自动配置的威力
  6. 深入原理：阅读 Spring Boot 源码，理解自动配置的实现机制（@EnableAutoConfiguration、条件注解、spring.factories）
  7. 进阶生产级能力：学习 Actuator 监控、日志、多环境配置、部署发布（打 jar 包、容器化部署）
