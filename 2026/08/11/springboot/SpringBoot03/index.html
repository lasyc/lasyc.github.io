发表于2026-08-11|更新于2026-08-12
|浏览量:

SpringBoot 特点

依赖管理

父项目做依赖管理

在之前开发的时候，我们经常通过创建父子项目，在父项目的 pom.xml 文件定义各个依赖的版本号，子项目只需要引入依赖即可

同理 SpringBoot 也为我们提供了绝大部分依赖的版本号，当我们使用 spring-boot-starter-parent 作为父工程时，只需要引入依赖即可

这是 spring-boot-starter-parent 的父工程，版本号都是在这里定义的

点进去就可以看到

当让，如果我们不想使用 SpringBoot 为我们提供的版本，只需要编写新的版本将其覆盖即可，当让，标签必须一致

开发导入 starter 场景启动器

参考文档

starter 可以理解为是 SpringBoot 为我们提供的工具整合包，我们无需导入繁琐的各种依赖,只需要导入与之对应的 spring-boot-starter-xxxx 即可

在此之外，个别场景下，SpringBoot 没有为我们提供对应的 starter，但是会有第三方的 starter，或者我们也可以自己创建自己的 starter，但是明明要作出区分，使用 xxxx-spring-boot-starter

自动配置

内嵌 Tomcat

在 spring-boot-starter-web 依赖中，就包含了 Tomcat，并且 SpringBoot 还为我们做了默认的配置

SpringMVC

在 spring-boot-starter-web 依赖中，还包含了 spring-boot-webmvc 依赖

我们可以在启动类中获取一下 SprinBoot 都为我们装配了哪些组件，可以看到很多我们似曾相识的组件

扫包

以往开发的时候我们需要自己声明扫描包的路径，而 SpringBoot 有默认的扫描规则，那就是和主程序同级及以下的所有包都会被扫描

如果想要指定扫包路径，则可以使用 @SpringBootApplication 注解的 scanBasePackages 属性

或者使用 @ComponentScan 注解也可以

容器功能

组件添加

在初学 Spring 阶段，想要将 Bean 交给 IOC 管理，我们需要编写 xml 配置文件

@Configuration

而后，我们学习了 @Bean 注解，但是要在配置类中，即被 @Configuration 声明的类

在 SpringBoot2 中，@Configuration 注解中新增了一个属性 proxyBeanMethods 默认为 true

它是来确保，在我们不通过 IOC 容器来获取 Bean 对象时，对象是单例的

设置 @Configuration(proxyBeanMethods = false)

因此，为了确保，当一个实例被多出引用时，引用的都是用一个实例，proxyBeanMethods 必须是 true，反之则 false 更好，可以减少 SpringBoot 的启动速度

@Bean、@Component、@Controller、@Service、@Repository

再之后，根据实例的不同类型，我们将 Bean 分为了 JavaBean 和业务 Bean，又将业务 Bean 细分为 Controller、Service、Mapper，分别对应这些注解

@ComponentScan、@Import

定义了各种各样的 Bean 之后，则需要通过 @ComponentScan 来扫描它们，将其交给 IOC 容器管理，但是 SpringBoot 提供了默认的扫包规则，除非特殊情况，我们也很少使用

而 @Import 注解，则用于导入组件，被 @Import 导入的组件，会被调用默认的无参构造方法创建一个实例交给 IOC 容器管理

在 IOC 容器中我们可以找到 com.laysc.boot.entity.User

@Conditional

@Conditional 用于条件装配，当满足指定条件时，才会进行组件注入，但是我们并不是直接使用 @Conditional 注解，而是它的派生注解

但是如果我们注入 Pet，再次执行，结果就是 true

原生配置文件引入

@ImportResource

@ImportResource 用于导入 xml 配置文件，让配置文件中的 Bean 也能被 IOC 容器管理

在 SpringBoot 中已经完全舍弃了 xml 配置文件，但是如果想将就项目升级为 SpringBoot 的话，需要将配置文件中的 <bean> 挨个转为 @Bean，此时使用 @ImportResource 就可以避免

配置绑定

在实际开发中，经常会有很多的 properties 配置文件，比如 application.properties，我们希望将配置文件中的值注入到 JavaBean 中，在需要时可以直接获取

如果使用 Java 来做这个操作，还是比较麻烦的，需要记载 properties 然后遍历所有字段，挨个 get、set

而 SpringBoot 为我们提供了如下注解简化操作

@ConfigurationProperties

@ConfigurationProperties 注解，用于将 properties 文件中的值注入到 Bean 中

@Component、@ConfigurationProperties

获取 Bean 并打印

@EnableConfigurationProperties、@ConfigurationProperties

除上述方式之外，我们还可以在配置类中通过 EnableConfigurationProperties 开启配置并指定需要配置的 Bean

自动配置原理入门

在编写主程序时，我们添加了一个注解 @SpringBootApplication，深入查看该注解我们可以看到是由另外三个注解组成的：

  1. @SpringBootConfiguration
  2. @EnableAutoConfiguration
  3. @ComponentScan

SpringBootConfiguration

SpringBootConfiguration 本质就是一个 Configuration

ComponentScan

ComponentScan 用于扫包

EnableAutoConfiguration

EnableAutoConfiguration 则是 SpringBoot 能够实现自动装配的关键

该注解也是又另外两个注解组成的：

  1. AutoConfigurationPackage
  2. @Import({AutoConfigurationImportSelector.class})

AutoConfigurationPackage

可以看到 AutoConfigurationPackage 注解上通过 @Import 导入了一个组件，名为 AutoConfigurationPackages.Registrar

然后利用 Registrar 向容器内批量导入组件

@Import({AutoConfigurationImportSelector.class})
