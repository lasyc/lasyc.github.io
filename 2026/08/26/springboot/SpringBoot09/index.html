Spring Boot 参数校验与处理原理

发表于2026-08-26|更新于2026-09-12|后端框架Spring Boot
|总字数:2.3k|阅读时长:10分钟|浏览量:

数据校验

实际的开发中，我们经常需要对请求参数进行校验（非空、长度、范围等），如果手动在业务代码里一个个 if 判断，代码会非常臃肿。Spring 提供了基于 Bean Validation（JSR-303） 规范的注解校验，Spring Boot 中只需引入 spring-boot-starter-validation

在实体类上声明校验规则

在 Controller 参数上启用校验

全局处理校验异常

校验失败时 Spring 会抛出异常，默认返回 400 页面，不够友好。我们可以通过 @RestControllerAdvice 统一捕获并返回 JSON

常用校验注解

注解 作用
@NotBlank 字符串不能为 null 且去除空格后长度必须大于 0
@NotNull 不能为 null（可用于包装类型）
@NotEmpty 不能为 null 且长度必须大于 0（可用于集合、字符串）
@Size(min, max) 长度必须在指定范围内（可用于字符串、集合、数组）
@Min / @Max 数值必须大于等于 / 小于等于指定值
@Pattern(regexp) 必须匹配指定的正则表达式
@Email 必须是合法的邮箱格式
@Past / @Future 必须是过去 / 未来的时间

文件上传

Spring Boot 默认使用 StandardServletMultipartResolver 处理文件上传，无需任何额外配置（对比 SpringMVC 需要配置解析器，Spring Boot 已经自动配置好了）

多文件上传时，只需将参数类型改为 MultipartFile[] 或 List<MultipartFile>，前端表单中多个 name="file" 的 input 即可

参数处理原理

  1. 从 HandlerMapping 中找到对应的 Handler
  2. 为当前 Handler 找到对应的 HandlerAdapter（适配器）
  3. HandlerAdapter 执行对应的 Handler
  4. 调用 setHandlerMethodArgumentResolvers 设置参数解析器

我们知道 Spring 通过各种的参数解析器来解析参数，那么对于 Servlet 原生的一些参数，也有对应的解析器 ServletRequestMethodArgumentResolver

因此，我们可以直接在 handler 方法中，使用对应的参数，不需要任何注解，Spring 会帮我们自动注入

参数解析器一览

RequestMappingHandlerAdapter 中通过 getDefaultArgumentResolvers() 注册了一系列参数解析器，按照顺序依次匹配，支持则解析，不支持则交给下一个解析器

解析器 解析的参数
RequestParamMethodArgumentResolver @RequestParam
RequestParamMapMethodArgumentResolver @RequestParam + Map
PathVariableMethodArgumentResolver @PathVariable
PathVariableMapMethodArgumentResolver @PathVariable + Map
MatrixVariableMethodArgumentResolver @MatrixVariable
MatrixVariableMapMethodArgumentResolver @MatrixVariable + Map
ServletModelAttributeMethodProcessor 自定义对象参数
RequestResponseBodyMethodProcessor @RequestBody
RequestPartMethodArgumentResolver @RequestPart
RequestHeaderMethodArgumentResolver @RequestHeader
RequestHeaderMapMethodArgumentResolver @RequestHeader + Map
ServletCookieValueMethodArgumentResolver @CookieValue
ExpressionValueMethodArgumentResolver @Value
SessionAttributeMethodArgumentResolver @SessionAttribute
RequestAttributeMethodArgumentResolver @RequestAttribute
ServletRequestMethodArgumentResolver Servlet API 原生参数
ServletResponseMethodArgumentResolver ServletResponse
HttpEntityMethodProcessor HttpEntity / RequestEntity
RedirectAttributesMethodArgumentResolver RedirectAttributes
ModelMethodProcessor Model
MapMethodProcessor Map
ErrorsMethodArgumentResolver Errors / BindingResult
SessionStatusMethodArgumentResolver SessionStatus
UriComponentsBuilderMethodArgumentResolver UriComponentsBuilder
PrincipalMethodArgumentResolver Principal
RequestParamMethodArgumentResolver 简单类型（兜底）
ServletModelAttributeMethodProcessor 复杂类型（兜底）

最后两个是兜底解析器：简单类型（String、Integer 等）交给 RequestParamMethodArgumentResolver，复杂类型（POJO 等）交给 ServletModelAttributeMethodProcessor

自定义对象参数绑定原理

自定义对象参数由 ServletModelAttributeMethodProcessor 解析（它继承自 ModelAttributeMethodProcessor）

绑定过程大致如下：

  1. 反射创建目标对象（BeanUtils.createInstance）
  2. 通过 ServletRequestDataBinder（继承自 WebDataBinder）绑定请求参数
  3. 绑定过程中使用 ConversionService 做类型转换（String → Integer、String → Date 等），也支持级联属性（address.province）
  4. 若参数上标注了 @Validated，绑定后还会执行数据校验（后续章节会讲到）

类型转换

默认的 ConversionService（ApplicationConversionService）已经内置了大量常用转换器，但自定义的转换规则需要我们实现 Converter、Formatter 或 GenericConverter 接口

自定义参数解析器

除了使用 Spring 提供的解析器，我们也可以实现 HandlerMethodArgumentResolver 接口来自定义解析规则

通过 addArgumentResolvers 添加的自定义解析器会排在默认解析器之前，优先匹配；如果 supportsParameter 返回 false，才会继续匹配默认解析器
