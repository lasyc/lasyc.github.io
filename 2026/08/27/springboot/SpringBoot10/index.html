注解小结

注解 作用 使用场景
@PathVariable 从 URL 路径中提取参数 /user/{id}
@RequestParam 从查询参数或表单字段中取值 ?username=admin
@RequestHeader 从请求头中取值 获取 User-Agent 等
@CookieValue 从 Cookie 中取值 获取 JSESSIONID 等
@RequestBody 从请求体中取值（JSON/XML） 前后端分离、POST JSON
@RequestAttribute 从 request 域中取值 配合拦截器、过滤器传值
@ModelAttribute 绑定请求参数到对象 / 往 Model 中放值 表单绑定 POJO
@MatrixVariable 从矩阵变量中取值 /cars/shell;color=red
@RequestPart 获取 multipart 请求中的文件/参数 文件上传
@Validated 启用参数校验 配合校验注解使用

简单类型参数（String、Integer 等）走 @RequestParam 逻辑，复杂对象参数（POJO）走 @ModelAttribute 逻辑，这是 Spring 的兜底解析规则

数据响应与协商

响应 JSON

@ResponseBody 用于将方法的返回值作为响应体返回，当返回的是对象时，Spring 会通过 HttpMessageConverter 将其序列化为 JSON。在 Spring Boot 中，spring-boot-starter-web 已内置 Jackson，无需额外添加依赖（下面是最新 Jackson 3.x 的坐标，仅作了解）

@RestController = @Controller + @ResponseBody，开发中直接使用 @RestController 即可，所有方法的返回值都会尝试转为 JSON

响应 XML

@ResponseBody 除了能返回 JSON，也能返回 XML，不过需要额外做两件事：

  1. 引入 JAXB 相关依赖（Spring Boot 3.x 起已不再默认携带 JAXB）

  2. 在实体类上标注 @XmlRootElement

  3. 控制器方法通过 produces 限定产出 XML（也可以不指定，由内容协商自动决定）

原理：当客户端 Accept 头为 application/xml 时，Spring 会找到 Jaxb2RootElementHttpMessageConverter（基于 JAXB 的消息转换器）来完成对象到 XML 的序列化。引入 JAXB 依赖后，同一个接口可能既返回 JSON 又返回 XML，具体返回哪种由下边的内容协商机制决定

协商

通过获取请求头中 Accept 字段可以知道浏览器支持哪些数据格式，再根据服务器可以响应哪些数据格式，两者进行匹配，根据权重优先使用匹配的方式进行响应

三种协商方式

Spring 支持三种内容协商方式，优先级从高到低：

  1. 路径后缀：/user.json、/user.xml（Spring Boot 默认关闭，避免后缀伪装攻击）
  2. 请求参数：/user?format=xml（默认关闭，需要手动开启）
  3. Accept 请求头：Accept: application/xml（默认方式）

返回值解析器

Spring MVC 处理返回值时，同样是通过一系列 HandlerMethodReturnValueHandler（返回值处理器）来决定的。RequestMappingHandlerAdapter 中通过 getDefaultReturnValueHandlers() 注册了默认的返回值处理器

返回值处理器 处理场景
ModelAndViewMethodReturnValueHandler 返回 ModelAndView
ModelMethodProcessor 返回 Model
ViewMethodReturnValueHandler 返回 View
ResponseBodyEmitterReturnValueHandler 返回 ResponseBodyEmitter（异步）
StreamingResponseBodyReturnValueHandler 返回 StreamingResponseBody（异步）
HttpEntityMethodProcessor 返回 HttpEntity / ResponseEntity
HttpHeadersReturnValueHandler 返回 HttpHeaders
CallableMethodReturnValueHandler 返回 Callable（异步）
DeferredResultMethodReturnValueHandler 返回 DeferredResult（异步）
AsyncTaskMethodReturnValueHandler 返回 WebAsyncTask（异步）
ModelAttributeMethodProcessor @ModelAttribute 相关
RequestResponseBodyMethodProcessor @ResponseBody 相关
ViewNameMethodReturnValueHandler 返回字符串视图名
MapMethodProcessor 返回 Map

只要方法上标注了 @ResponseBody，返回值就会交给 RequestResponseBodyMethodProcessor 处理，通过 HttpMessageConverter 转为 JSON 响应

返回值解析器原理

处理流程大致如下：

  1. 目标方法执行完毕，拿到返回值（如 User 对象）
  2. RequestResponseBodyMethodProcessor 判断方法上是否有 @ResponseBody 注解，有则处理
  3. 遍历 HttpMessageConverter 列表，找到支持该类型转换的转换器（如 MappingJackson2HttpMessageConverter）
  4. 通过转换器将对象序列化为 JSON，写入响应体，同时设置 Content-Type: application/json

该处理器与请求参数中的 @RequestBody 是同一个 RequestResponseBodyMethodProcessor，只是处理方向相反：一个是”读”（请求体 → 对象），一个是”写”（对象 → 响应体）

自定义 HttpMessageConverter

注意：前面”类型转换”章节的 Converter 处理的是单个参数（如 String → Date、String → 枚举），而 HttpMessageConverter 处理的是整个消息体（@RequestBody / @ResponseBody 的序列化与反序列化），两者是不同层面的东西，别混淆。

如果默认的 JSON/XML 转换器不满足需求，我们可以实现 HttpMessageConverter 接口来自定义消息转换规则
