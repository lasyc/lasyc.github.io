视图解析

在 Spring MVC 中，控制器方法执行完毕后，返回的并不一定是最终的 HTML 页面，而是一个逻辑视图名，例如：index、login。之后由 DispatcherServlet 调用 ViewResolver 去解析成真正的页面模板。

视图解析器是怎么工作的

执行流程大致如下：

  1. Controller 方法返回字符串、ModelAndView 或 View
  2. DispatcherServlet 调用 doDispatch()
  3. 解析器根据返回值找到对应的 View
  4. View 对象负责渲染最终页面

默认情况下，Spring MVC 会使用 InternalResourceViewResolver 或 BeanNameViewResolver 等解析器来解析视图。Spring Boot 集成 Thymeleaf 后，会自动配置一个 ThymeleafViewResolver，其默认前缀和后缀分别是：

ViewResolver 与 View

  • ViewResolver：负责解析视图名称
  • View：负责真正渲染页面

例如：Thymeleaf 的 ThymeleafViewResolver 会把 "index" 解析为 Thymeleaf 模板视图，然后交给模板引擎渲染页面。

模板引擎

模板引擎的核心作用，是把后端的数据和页面模板结合起来，生成最终的 HTML。它就像前端页面和后端 Java 数据之间的桥梁。

常见模板引擎：

  • Thymeleaf
  • Freemarker
  • Velocity
  • JSP（传统 Java Web）

其中，Thymeleaf 是 Spring Boot 官方更推荐使用的模板引擎。

Thymeleaf

Thymeleaf 是一款现代的服务器端 Java 模板引擎，适用于 Web 应用和独立环境。它最大的特点是：

  • 语法天然适合 HTML
  • 与 Spring MVC 集成度高
  • 可直接在 HTML 中通过属性实现动态渲染
  • 支持页面片段复用与模板布局

3. th:insert 与 th:replace / th:include 的区别

  • th:insert：将指定片段插入到宿主标签体中
  • th:replace：用指定片段替换宿主标签本身
  • th:include：只把片段内容插入到宿主标签中

这三种写法在页面结构组织上略有差异，实际开发中常用 th:replace 和 th:insert。

提示：从 Thymeleaf 3.0 开始，官方已不推荐使用 th:include，建议统一使用 th:insert 或 th:replace。

注意事项

  1. 模板文件必须放在 src/main/resources/templates 目录下
  2. 访问模板时，使用 Controller 返回逻辑视图名，不要直接写页面路径
  3. 当页面需要动态数据时，必须通过 Model 或 HttpSession 传入
  4. 避免把模板文件与静态资源混在一起，静态资源建议放在 static 目录
  5. 开发阶段建议关闭缓存，避免页面修改后看不到效果

视图解析原理

在 Spring MVC 的完整执行链路中，控制器返回值并不直接等于最终的页面，而是先形成一个视图模型，再交给解析器和渲染器处理。整体过程可以概括为：

  1. Controller 直接返回字符串，字符串内容为视图名称
  2. Spring MVC 会根据返回值的类型，寻找对应的 HandlerMethodReturnValueHandler 处理器
  3. 不论返回值是 String、Model、View、ModelAndView，最终都会被封装成 ModelAndView
  4. ModelAndView 中保存了视图名称和模型数据，随后由 DispatcherServlet 交给 ViewResolver 解析
  5. 解析器根据逻辑视图名找到真实的模板文件，例如 index -> classpath:/templates/index.html
  6. 最后由模板引擎（如 Thymeleaf）把模型数据渲染到页面中，生成最终 HTML

总结

Thymeleaf 是 Spring Boot 中最常见的模板引擎之一，核心能力在于：

  • 把后端数据渲染到页面中
  • 支持结构化数据展示、循环和判断
  • 支持模板复用和公共片段抽取
  • 与 Spring MVC 的 ViewResolver、Controller 体系无缝集成

如果我们想把页面做得更清晰、更易维护，Thymeleaf 的 th: 语法和 fragment 机制是非常重要的基础知识。

  • 国际化 #{}
