拦截器

参考文档

拦截器 是 SpringMVC 提供的一种机制，它可以在请求到达 Controller 之前和响应返回客户端之前进行处理。

HandlerInterceptor

想要自定义拦截器，就需要实现 HandlerInterceptor 接口，该接口有三个方法：

  • preHandle(request, response, handler)：在请求到达 Controller 之前调用，返回 true 表示继续执行后续流程（如调用下一个拦截器或处理器），返回 false 表示流程中断，本次请求到此为止。
  • postHandle(request, response, handler, modelAndView)：在 Controller 方法执行之后、视图渲染之前调用，可以对 ModelAndView 做补充修改。
  • afterCompletion(request, response, handler, ex)：在视图渲染完成、整个请求结束之后调用，常用于资源清理或记录日志，也可以通过 ex 感知是否发生了异常。

拦截器原理

拦截器是怎么被调用的

拦截器并不像过滤器那样由 Servlet 容器直接调度，它是在 DispatcherServlet 分发请求时，通过 HandlerExecutionChain（处理器执行链）被逐个调用的。

也就是说：

  1. getHandler() 不仅会找到 Controller 方法，还会把匹配的拦截器打包成 HandlerExecutionChain
  2. preHandle 全部放行后才会调用 Controller 方法
  3. 视图渲染完成之后才执行 afterCompletion

所以当 preHandle 返回 false 时：

  • 不会调用 Controller 方法
  • 不会调用任何拦截器的 postHandle
  • 只会触发已经执行过 preHandle 的拦截器的 afterCompletion

多个拦截器的执行顺序

当注册了多个拦截器时，执行顺序是：

  • preHandle：按照注册顺序执行
  • postHandle：按照注册的逆序执行
  • afterCompletion：按照注册的逆序执行

注意事项

  1. 拦截器作用于 Spring MVC 的请求分发过程，只能拦截经过 DispatcherServlet 的请求
  2. 静态资源也可能被拦截，记得通过 excludePathPatterns 放行
  3. preHandle 返回 false 后，postHandle 不会再执行
  4. 多个拦截器的 postHandle / afterCompletion 是逆序执行的
  5. 登录、权限等校验建议放在 preHandle 中完成

总结

  • 拦截器通过实现 HandlerInterceptor 接口定义，核心方法是 preHandle、postHandle、afterCompletion
  • 通过 WebMvcConfigurer#addInterceptors 注册，用 addPathPatterns / excludePathPatterns 控制拦截范围
  • 拦截器的本质是 DispatcherServlet 在调用 Controller 前后预留的处理时机，调用链由 HandlerExecutionChain 维护

后续我们还会接触到过滤器（Filter）。两者的区别在于：过滤器由 Servlet 容器管理，能拦截所有请求；拦截器由 Spring MVC 管理，只能拦截进入 DispatcherServlet 的请求。
