错误处理

发表于2026-09-02|更新于2026-09-03
|浏览量:

默认规则

SpringBoot 默认为我们提供了一个 /error 的处理器，所有的错误都会被转发到这个处理器中进行处理。

因此，我们只需要在 templates 目录下创建一个 /error 文件夹，在其中创建对应的错误页面即可。比如：404.html、500.html 等。

/error 文件夹下的页面会被 SpringBoot 自动识别并渲染。会自动根据错误码显示对应的页面。

并且在发生错误时，SpringBoot 会自动将错误信息保存到 request 域中，页面可以通过 ${} 语法获取这些信息。

属性名 说明
status 错误码
error 错误信息
errors 错误列表
message 错误描述
timestamp 错误发生时间
path 请求路径
exception 异常类名
trace 异常堆栈信息

原理

SpringBoot 提供了一个自动配置类 ErrorMvcAutoConfiguration，在配置类中通过 @Bean 注解向 IoC 中添加了一个控制器 BasicErrorController，该控制器继承了 AbstractErrorController，并实现了 ErrorController 接口。

在 BasicErrorController 中定义了两个方法，分别用于处理 HTML 页面和 JSON 数据的请求。

自定义错误处理

自定义错误页面

通过 spring.web.error.path 配置错误处理路径，默认是 /error，可以修改为其他路径。

自定义错误处理器

使用 @ControllerAdvice 注解定义一个全局异常处理器，使用 @ExceptionHandler 注解定义异常处理方法。

@ResponseStatus 注解

@ResponseStatus 注解可以用来标注异常类，指定异常对应的 HTTP 状态码和错误信息。

定义好的异常可以直接使用，返回值就是定义好的状态码和错误信息。

自定义异常解析器

创建自定义异常解析器，实现 HandlerExceptionResolver 接口，重写 resolveException 方法。

但是按默认顺序，自定义的解析器会排在所有内置解析器之后执行，因此需要通过 @Order(Ordered.HIGHEST_PRECEDENCE) 注解提升优先级，确保自定义解析器优先执行。
