Spring Boot 原生组件注入

发表于2026-09-02|更新于2026-09-12|后端框架Spring Boot
|总字数:1k|阅读时长:4分钟|浏览量:

原生组件

我们知道 Spring 是基于 Servlet 的，因此 Spring Boot 也继承了 Servlet 的特性。Spring Boot 中的原生组件主要包括：

  1. Servlet
  2. Filter
  3. Listener

Spring Boot 提供了原生组件的注入方式：使用 @ServletComponentScan 注解开启扫描，然后通过 @WebServlet、@WebFilter、@WebListener 注解标注对应的原生组件，把它们注册到内嵌的 Servlet 容器中。

Servlet

创建 Servlet 需要继承 HttpServlet 类，并重写其中的 doGet()、doPost()、doDelete()、doPut() 等方法来处理不同的 HTTP 请求。

需要使用 @WebServlet 注解来指定 Servlet 的访问路径。

但是这个 Servlet 并不会被 Spring Boot 扫描到，因此需要在启动类上使用 @ServletComponentScan 注解来开启扫描（参数指定了要扫描的包）。

在浏览器中访问 /servlet，可以看到控制台打印了 doGet，说明 Servlet 已经被成功注册。但你可能注意到：此时 Spring MVC 的拦截器并没有生效，至于原因，文末的「原理」部分会解释。

Filter

创建一个自定义的过滤器，并且实现 Filter 接口，重写其中的 doFilter() 方法。

使用 @WebFilter 注解来指定过滤器的访问路径。

注意：@WebFilter 的 urlPatterns 遵循 Servlet 规范，用 /* 表示匹配所有请求；而 /** 是 Spring MVC 中 Ant 风格的路径写法（常用于拦截器、请求映射的路径匹配）。两种写法属于不同体系，不要混淆。

Listener

创建一个自定义的监听器，并且实现 ServletContextListener 接口，重写其中的 contextInitialized()、contextDestroyed() 方法。

XxxxRegistrationBean

Spring Boot 还提供了 ServletRegistrationBean、FilterRegistrationBean、ServletListenerRegistrationBean 来注册原生组件。

原理

前面学习过，Spring Boot 的请求派发是基于 DispatcherServlet 的，在我们添加了新的 Servlet 之后，就存在了两个 Servlet。

Spring Boot 通过 DispatcherServletAutoConfiguration 来完成 DispatcherServlet 的自动配置，内部包含两个嵌套的配置类：

  • DispatcherServletConfiguration：负责创建默认的 DispatcherServlet Bean（前提是用户没有自定义）
  • DispatcherServletRegistrationConfiguration：负责把 DispatcherServlet 注册到内嵌的 Servlet 容器中；注册时会做判断，如果用户已经通过其他方式注册过，就不会重复注册

可以看到，DispatcherServlet 的映射路径为 /，而我们自定义的 Servlet 映射路径为 /servlet，映射更具体。因此请求 /servlet 时，Servlet 容器会直接把它路由给自定义的 CustomServlet，请求根本不会进入 DispatcherServlet。

既然请求没有经过 DispatcherServlet，自然也就不会经过 Spring MVC 的拦截器，所以拦截器失效了。
