嵌入式 Servlet 容器

Spring Boot 启动时会创建一个 ServletWebServerApplicationContext（Web 应用上下文），由它负责创建并管理内嵌的 Web 服务器——也就是我们所说的嵌入式 Servlet 容器（默认是 Tomcat）。

版本说明：在 Spring Boot 2.0 之前，这个上下文叫 EmbeddedWebApplicationContext，内嵌的容器叫 EmbeddedServletContainer；从 Spring Boot 2.0 起，这两个类分别更名为 ServletWebServerApplicationContext 和 WebServer。老资料里看到的旧类名，指的就是这里的对应物。

启动时，Spring Boot 会根据 classpath 上的容器实现（Tomcat、Jetty、Undertow），找到对应的 ServletWebServerFactory（如 TomcatServletWebServerFactory），调用它的工厂方法创建出具体的 WebServer 实例，并交给应用上下文统一管理，供 DispatcherServlet 使用。

切换服务器

Spring Boot 内置了多种可选的 Web 服务器，如 Tomcat、Jetty、Undertow 等，默认使用 Tomcat。原因很简单：spring-boot-starter-web 中已经包含了 spring-boot-starter-tomcat，默认就引入了 Tomcat。

ConfigurableServletWebServerFactory

ConfigurableServletWebServerFactory 是所有内嵌容器工厂的公共接口，TomcatServletWebServerFactory、JettyServletWebServerFactory、UndertowServletWebServerFactory 都实现了它，通过它可以统一配置端口、上下文路径等。

不过该接口方法比较多，实际开发中一般不直接实现它，而是继承具体的工厂类（如 TomcatServletWebServerFactory）来做定制，或者使用下面更简洁的 WebServerFactoryCustomizer 方式。

WebServerFactoryCustomizer

这是官方推荐的定制方式：Spring Boot 在创建容器之前，会先收集容器中所有 WebServerFactoryCustomizer Bean，依次调用它们并把对应的工厂对象传进去，由我们修改工厂的配置。它和上面的方式效果等价，但写法更简洁：
