Spring Security 6

发表于2026-09-07|更新于2026-09-12|后端框架Spring Security
|总字数:874|阅读时长:2分钟|浏览量:

学习目标

  1. 了解常见的权限解决方案，理解认证与授权的概念。
  2. 能够说出 Spring Security 的基本原理。
  3. 掌握 Spring Security 认证的基本配置方式。
  4. 掌握 Spring Security 授权的基本配置方式。
  5. 掌握 Spring Security + JWT 解决前后端分离情况下的权限认证。

简介

中文文档

Spring Security 是一个 Java 框架，用于保护应用程序的安全性。它提供了一套全面的安全解决方案，包括身份验证、授权、防止攻击等功能。Spring Security 基于过滤器链的概念，可以轻松地集成到任何基于 Spring 的应用程序中。它支持多种身份验证选项和授权策略，开发人员可以根据需要选择适合的方式。此外，Spring Security 还提供了一些附加功能，如集成第三方身份验证提供商和单点登录，以及会话管理和密码编码等。总之，Spring Security 是一个强大且易于使用的框架，可以帮助开发人员提高应用程序的安全性和可靠性。

认证授权

什么是用户认证

  • 认证：Authentication

Spring Security 提供了对认证（authentication）的全面支持。认证是指我们如何验证试图访问特定资源的人的身份。一个常见的验证用户的方法是要求用户输入用户名和密码。一旦进行了认证，我们就知道了身份并可以执行授权。

什么是用户授权

  • 授权：Authorization

在用户通过认证后，只能代表该用户有访问系统的权限，并不代表可以访问全部资源，因此还需要判断当前用户是否有访问资源的权限。

在一个系统中，不同的用户拥有不同的角色，不同的角色拥有不同的权限，比如管理员可以查看所有用户的基本信息，而用户只能查看自己的基本信息。

因此，授权就是在用户登录后，根据用户的角色和权限，授予其对应的权限。

常见的认证方式

Http Basic 认证

Http Basic 认证就是通过 RESTFUL 风格的请求方式，每次发送请求时都携带用户名和密码，这种方式非常不安全，因此使用的越来越少

Session 认证

Session 认证就是在登录时，在服务端创建一个 Session 存储当前用户信息，并把 Cookie 保存到浏览器，后续每次请求都携带 Cookie，后端根据 Cookie 从 Session 获取用户信息

Token 认证

Token 认证就是在登录时，通过用户名和密码对用户进行认证，之后通过用户信息生成一个字符串，称之为 Token，再将 Token 返回给前端保存，之后每次发送请求携带 Token，后端会解析 Token 获取用户信息

OAuth2 认证

OAuth2 认证其实是一种第三方登录方式，如：微信扫码，Github 登录等
