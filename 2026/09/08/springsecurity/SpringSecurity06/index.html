创建登录页面

虽然 Spring Security 为我们提供了登录页，但是太简陋了，所以实际开发时并不会使用，而是使用我们自己的登录页，而且仅限于前后端不分离的情况下。

此时可以发现 login 页面能打开了，但其他请求也都能访问——这不是 Security 失效了，而是 Security 6 里只要你自己定义了 SecurityFilterChain，Boot 自动装配的那条默认过滤链就不再生效，安全规则完全由你这儿写的这条链说了算，空配置就相当于裸奔

通过 authorizeHttpRequests 方法，将 /login 请求路径放行，并要求其他请求路径需要认证

此时仍可以访问 /login 路径，但访问其他路径会返回 403 Forbidden。注意这里不是 401：401 是“未认证”，403 才是“禁止访问”。没配登录页时 Security 的默认入口点会把未认证请求直接拒成 403；等配了 formLogin，未认证请求才会变成重定向到 /login（302）

通过 formLogin 方法，设置默认的登录页，在未授权的情况下访问其他路径，都会自动跳转至 /login 路径下

并且设置了 /auth/login 作为登录的请求路径，此时需要修改 HTML 页面 form 表单的 action 属性为 th:action=@{/auth/login}

再次访问页面，点击登录，发现可以正常访问资源了

注意：这里还涉及到一种叫 CSRF 的知识，Spring Security 默认是开启 CSRF 的，当 CSRF 开启时，Spring Security 会拦截所有 POST 请求，检查是否携带了有效的 CSRF Token。如果没有，直接返回 403 Forbidden，不会执行认证逻辑，表现就是一直停留在登录页面。因为这里使用了 Thymeleaf 技术，Security 与 Thymeleaf 集成后，用 th:action 渲染表单会自动插入隐藏的 _csrf 字段，因此不会出现上述问题，但是如果使用的是 HTML 静态页面则需要关闭 CSRF

除此之外我们还可以设置登录后的处理方法

新建 success.html 页面和 error.html 页面，并为之提供控制器，/error 不需要我们设置，Spring Boot 有默认的控制器

此时再次登录，登录成功后会跳转至 success.html 页面；失败则又会回到 login 页面，原因是我用了 failureForwardUrl("/error")，请求被转发到 /error，但授权规则里没有放行 /error，转发过去的请求又被 Security 拦下，重新打回 /login，看起来就像“登录失败没反应”，解决方式：把 /error 一起放行：.requestMatchers("/login", "/error").permitAll()
