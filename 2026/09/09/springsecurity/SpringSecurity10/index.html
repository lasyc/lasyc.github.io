授权

授权（Authorization）是指在用户通过登录进行身份认证后，系统根据用户的身份或者权限，判断该用户是否具有访问指定资源的权限

RBAC

RBAC（Role-Based Access Control）是目前主流的权限管理模型，即用户本身并不具备访问资源的权限，通过赋予用户对应的身份，以身份为桥梁，来让用户具有访问资源的权限，比如：管理员（Admin）可以登录后台管理系统，而普通用户（User）只能查看，现在有两个用户张三和李四，通过赋予张三管理员的身份，张三便可以登录后台管理系统

主体 含义
User 用户
Role 身份
Permission 权限

这三个主体分别对应一张表，除此之外还需要两个表 user_role 和 role_permission，用来表达用户、角色、权限之间多对多的关系，因此，需要五张表

  1. user
  2. role
  3. permission
  4. user_role
  5. role_permission

权限标识符

权限标识符 其实就是一个字符串，只不过有特定的格式，如：user:add、user:delete 分别表示当前用户具有新增、删除用户的权限，Spring Security 中是基于权限标识符来判断该用户是否拥有对应的权限

修改代码

之前我们在编写自定义认证逻辑时，我们实现了 UserDetailService 接口并重写了 loadUserByUsername 方法，在构建 User 信息时，我们只设置了 username 和 password，其中还有一个字段是 Set<GrantedAuthority> authorities，这个就是权限的集合，此次我们只需要向其中设置值即可

GrantedAuthority 是一个接口，其中有几个实现类，这里使用 SimpleGrantedAuthority

实现类 你需要手动创建？ 使用频率 核心价值
SimpleGrantedAuthority ✅ 常用 ⭐⭐⭐⭐⭐ 简单直接的权限字符串
SwitchUserGrantedAuthority ❌ 框架内部创建 ⭐ 保存切换前的原始身份
JaasGrantedAuthority ❌ 框架内部创建 ⭐ 对接 Java EE JAAS
FactorGrantedAuthority ❌ 框架内部创建（MFA） ⭐ 标记用户通过了哪个认证因子，如 JSON 里的 FACTOR_PASSWORD

登录后再次获取用户认证信息，可以看到权限标识符已经设置成功了

添加配置

在 SecurityConfig 中添加配置，将权限标识符和对应的请求路径进行绑定

使用 requestMatchers 匹配请求路径，然后通过 hasAuthority 判断当前用户是否拥有该权限标识符，除此之外还有其他方法

  1. hasAuthority：判断用户是否拥有该权限标识符
  2. hasAnyAuthority：判断用户是否拥有众多权限标识符中其中一个
  3. hasAllAuthorities：判断用户是否拥有所有权限标识符
  4. hasRole：判断用户是否拥有该角色
  5. hasAnyRole：略
  6. hasAllRoles：略
