自定义 403 处理

在之前的学习中，我们只是创建了一个 Error 页面，但是实际开发中，对于 400、500、403 等具有特殊含义的状态码都有其对应的 HTML 页面，用于向用户显示错误信息

在 Spring Security 中，可以通过配置来设置发生 401、403 时对应的处理方法

  1. AuthenticationEntryPoint：用来处理 401 异常
  2. AccessDeniedHandler：用来处理 403 异常

我们只需要实现这两个接口并添加配置即可

代码实现

访问没有权限的请求路径，页面会显示

这里有个坑：第一次用账号密码登录时，认证信息的类型是 UsernamePasswordAuthenticationToken，此时访问没有权限的资源会返回 403；但重启后端之后，因为 Remember Me 的存在，前端不用重新登录也能继续访问，此时认证信息的类型变成了 RememberMeAuthenticationToken，再访问没有权限的资源却返回 401

是因为 Spring Security 认为 Remember Me 是一种不完全认证，即不是通过账号密码登录的认证方式，因此在处理 403 异常时，如果发现是通过 Remember Me 认证的信息，则会转为 401 异常

自定义页面

上述做法是直接返回 JSON 数据，适合前后端分离的场景；而在前后端不分离的场景中，返回 JSON 就不太合适，其实可以直接跳转到 403 页面

在之前学习 Spring Boot 的时候，我们知道 Spring Boot 为我们提供了默认的错误处理器，会把对应的状态码转发到 /error 路径下对应的 HTML 文件中

因此我们只需要在 /static/error 目录下新建 403.html 文件即可，当发生 403 异常时，会自动转发到该页面

注意：容器里如果还注册着前面那个 CustomAccessDeniedHandler，403 会被它先接管、直接写出 JSON，根本轮不到 403.html。想用页面提示，要么去掉自定义的 AccessDeniedHandler，要么用 defaultAccessDeniedHandlerFor(handler, requestMatcher) 把 JSON 处理限定到具体的请求路径上
