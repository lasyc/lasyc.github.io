Spring AI 工具调用

发表于2026-09-29|更新于2026-09-29|后端框架Spring AI
|总字数:2.2k|阅读时长:7分钟|浏览量:

概述

工具调用——即 AI 模型调用应用定义的函数并根据其结果行动的能力——是智能人工智能系统的核心构建模块。只能生成文本的模型是聊天机器人；能够发现信息、采取行动并循环直到达成目标的模型称为代理（Agent）。

工具调用的执行流程：模型根据对话决定调用某个工具 → 框架执行对应方法并拿到返回值 → 返回值作为消息回传给模型 → 模型结合结果继续生成回复（循环进行直到不再需要调用工具）。

工具有两大用途：

  1. 信息检索——通过数据库、网络服务、文件系统或搜索引擎的数据来补充模型的知识。举例：获取当前天气、查询客户记录、查找最新新闻。

  2. 采取行动——在系统中执行操作。例如：发送邮件、预订机票、更新记录、触发工作流程。

三者的共同点（先记住这些，就不用死记区别了）：

  • 最终都产出 ToolCallback——这是”工具”在 Spring AI 里的统一抽象：ToolDefinition（name + description + inputSchema，即模型看到的部分）+ 执行逻辑（call(...)）。三种方式可以自由混用。
  • 注册方式完全相同：defaultTools(...) / tools(...) 既接受 @Tool 的普通对象，也接受 ToolCallback、ToolCallbackProvider 对象，可以混着传。
  • 模型侧无感知：模型只拿到一份 JSON Schema，不关心你背后是注解、反射还是 lambda。

三者的区别只有一件事：工具定义（name、description、参数 schema）从哪来——是注解和方法签名替你自动生成，还是你在代码里手动指定。

@Tool

注解方式，样板代码最少，也是最常用的方式。

工作方式：框架在运行时读取方法上的注解和方法签名，自动生成 ToolDefinition（name 默认取方法名、参数 schema 由参数类型推导），再包装成可执行的工具——你只管写方法。

该注解提供了四个属性：

  1. name：为该方法起别名，全局唯一，默认为方法名，如：getCurrentDateTime
  2. description：工具描述，尽可能详细——AI 完全依赖它决定什么场景调用哪个工具，务必认真写
  3. returnDirect：工具执行结果是直接返回给用户（true），还是交回模型继续推理（false，默认）
  4. resultConverter：结果转换器，把方法返回值转换成回传给模型的字符串

要点与适用场景：

  • 方法可以是 public / 包私有 / private，也可以是 static 或实例方法；工具类不必须是 Spring Bean，new 出来直接传给 tools(...) 就行。
  • 参数默认全部必填，可选用 @ToolParam(required = false) 或 @Nullable 标记可选——必填标得不准、模型又拿不到值时，它会自己”编”一个，这是常见幻觉来源之一。
  • 打 GraalVM native 镜像（AOT 编译）时，所在类需要是 Spring Bean 或加 @RegisterReflection。
  • 适用场景：方法在你自己拥有的类里——绝大多数情况选它就对了。

MethodToolCallback

手动包装一个已存在的方法（java.lang.reflect.Method + 目标对象），全程不依赖注解。

适用场景（什么时候非它不可）：

  1. 方法存在、但你改不了它的源码——第三方 SDK、遗留代码、JDK 方法，没法在上面加 @Tool；
  2. 工具定义需要运行时动态生成——name / description 从配置文件、数据库里读取，按需查找方法拼装出工具。

要点：

  • toolObject：实例方法必填，static 方法可省略；
  • 没有注解可用，name 按方法名生成，description 要像示例那样手动写进 ToolDefinitions.builder(method)；
  • 和 @Tool 的关系：@Tool 在运行时本质上走的就是这条路径，两者执行行为一致，区别只在”定义从哪来”（注解自动 vs 手动指定）；
  • 限制：方法的参数和返回值不能是 Optional、CompletableFuture 等异步类型、Mono/Flux 等响应式类型、Function 等函数类型——这些生成不了模型能理解的 schema（@Tool 同理）。

FunctionToolCallback

包装一个函数式对象：Function、Supplier、Consumer、BiFunction——包括 lambda 和方法引用。

要点：

  • 关键区别：参数 schema **不看方法签名，看 inputType**——指定一个 record/POJO 类，框架按它的字段生成 JSON Schema，调用时把模型返回的 JSON 反序列化成该对象再交给函数；
  • 函数只有一个入参（即 inputType 对象）；需要 ToolContext（租户 ID、用户 ID 等不给模型看的数据）时，可用 BiFunction 形式接收上下文。

适用场景：

  1. 工具逻辑本来就是 lambda、方法引用或现成的 Function（如示例的 weatherService::getWeather）；
  2. 想用一个 record 集中描述入参（配合 @JsonClassDescription / @JsonPropertyDescription 写字段说明）；
  3. 想把工具注册成 @Bean 全局复用——Spring AI 自动发现容器中的 ToolCallback Bean，注入后直接传给 tools(...)。

选择建议（决策树）

  1. 方法是你自己写的类，且不想折腾 → @Tool（默认首选，能覆盖九成场景）
  2. 方法在别人的类里 / 改不了源码，或 name、description 要从配置、数据库动态生成 → MethodToolCallback
  3. 逻辑是 lambda、方法引用或现成的 Function，或想用 record 定义入参 → FunctionToolCallback
  4. 同一个工具想在多处复用 → 注册成 ToolCallback Bean（@Bean 返回上面任意一种），Spring AI 自动发现

拿不准时不用纠结：三者可以混着传，先用 @Tool，遇到它覆盖不了的场景再换成对应方式。
