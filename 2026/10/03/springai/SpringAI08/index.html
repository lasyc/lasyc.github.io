结构化输出

在前面的示例中，AI 大模型的返回值永远都是一段字符串，但是如果我们需要的是一个 Boolean、JSON 等等指定类型的结果呢？此时就需要给大模型指定返回值的结构

通过 entity 方法可以设置返回值的类型结构，以此来让 AI 大模型实现结构化输出

访问 http://localhost:8080/chat?message=学完 Java 可以直接学习 Spring 么&conversationId=123

或者使用 POJO 实体类

因为要返回 JSON 结构，记得改一下 produces 或者删掉

访问 http://localhost:8080/chat?message=“张三12345678901北京市朝阳区”解析这段信息&conversationId=123

原理

如果开启了日志，可以看到，在发送请求时会有这么一段

AI 大模型就会根据要求返回对应的 JSON 字符串，再将 JSON 字符串转为对应的实体类即可

整体来看，结构化输出分为两个阶段：请求阶段生成格式指令，响应阶段解析转换

请求阶段：生成格式指令

调用 entity 方法时，框架内部会为指定的类型创建一个 BeanOutputConverter 转换器，并完成两件事：

  1. 反射目标类型生成 JSON Schema，上面 log 中的 Schema 就是根据 User 类生成的，属性、类型、必填字段都与实体类一一对应（属性按字母序排列，与字段声明顺序无关）
  2. 根据 Schema 生成格式指令（即 log 中 spring.ai.chat.client.output.format 对应的内容），追加到 Prompt 中一起发送给大模型，要求其只返回符合 Schema 的 JSON，不要携带解释和 markdown 代码块

响应阶段：解析转换

大模型返回内容后，由转换器的 convert 方法完成解析：

  1. 先清洗返回内容：即使大模型没有严格遵守要求、把 JSON 用 markdown 代码块包裹了起来，也会先剥离代码块格式再提取 JSON
  2. 再将 JSON 反序列化为实体类（基于 Jackson），这也是前边要求 POJO 提供构造函数和 Getter/Setter 的原因

转换器也可以脱离 entity 方法单独使用：

注意事项

  1. entity 不仅支持 Boolean、POJO，还支持复杂类型：嵌套对象、List<User> 等集合类型都可以，通过 ParameterizedTypeReference 指定泛型即可
  2. 格式指令本质上只是提示词，大模型并不能保证 100% 遵守，偶尔会夹带解释文字或漏掉字段，导致转换失败抛出异常，此时可以搭配前边提到的 StructuredOutputValidationAdvisor，对输出做 Schema 校验并携带错误信息让大模型重试
  3. 流式调用下同样可以使用 entity，但由于 JSON 必须完整才能反序列化，实际是等响应聚合完成后再整体转换的
