Spring AI RAG

发表于2026-10-06|更新于2026-10-08
|总字数:2.4k|阅读时长:9分钟|浏览量:

RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种”先检索、再生成”的大模型应用框架：先通过向量检索从外部知识库中获取与问题相关的内容，再将其注入提示词，让大模型基于真实资料生成更准确的回答。它主要解决大模型知识过时、产生幻觉、缺乏私有知识等问题。

向量数据库

前面提到，RAG 其实就是在向 AI 大模型发送请求之前，先在本地检索一些与问题相关的内容，连同问题一起发送给大模型，让它基于上下文给出更准确的回答。

因此，既然提到了 检索，那就需要用到数据库。不过区别于传统的关系型数据库，这里需要使用 向量数据库。

向量数据库 是一类专门用于存储、索引和检索高维向量（Embedding）的数据库系统，常用于语义搜索、RAG、推荐系统等 AI 场景，依赖 ANN（Approximate Nearest Neighbor，近似最近邻）算法以及 HNSW、IVF 等索引实现毫秒级相似度检索。

两者的检索方式对比：

  1. 传统数据库基于内容本身做精确 / 模糊匹配，比如通过 %景区% 进行 LIKE 模糊查询，只能查出内容中包含 景区 这两个字的记录
  2. 向量数据库基于语义相似度检索，比如用 景区 作为查询条件，可以检索出 故宫、天安门 等语义上相关的内容（前提是这些文本已经过 Embedding 模型向量化并写入了向量库）

Milvus

Milvus 是一个为 GenAI 应用构建的开源向量数据库，支持高速向量检索，并能在性能损失很小的情况下横向扩展到数十亿级别的向量。官方提供多种部署形态：Milvus Lite（pip 安装即可，适合学习与原型验证）、Milvus Standalone（单机版，适合百万级向量的生产或测试环境）、Milvus Distributed（分布式版，可横向扩展到数十亿向量），以及全托管的 Zilliz Cloud。

安装

使用 Docker 部署 Milvus Standalone 即可（官方提供了单机 docker-compose 部署方式，参见 官方安装文档），具体步骤略。

Embedding 模型

既然已经有了数据库，那么接下来要考虑的就是如何向数据库写入和检索数据。向量数据库不同于传统数据库，它不使用 SQL 进行增删改查，而是通过 SDK / API（例如 Spring AI 中的 VectorStore 接口）来完成数据的增删改查；而文本与向量之间的转换，则由 Embedding 模型 来完成。

Embedding 模型（嵌入模型）是一种将离散的高维数据（如文本、图像、音频）转换为低维连续（稠密）向量表示的机器学习模型。通过这种转换，语义相似的内容在向量空间中的距离更近，从而可以支撑：

  1. 语义搜索：理解查询意图，而非简单的关键词匹配
  2. 文本分类：快速归类海量文档
  3. 语义相似度计算：判断两段文本的相似程度
  4. RAG 检索增强：为大语言模型提供精准的外部知识

工作原理

原始文本 → 分词（Tokenization）→ 编码（Encoding）→ 向量嵌入（Vector Embedding）

  1. 分词：将文本拆分为 Token（单词或子词单元）
  2. 编码：通过神经网络（如 Transformer）提取语义特征
  3. 嵌入：经过池化（Pooling）等操作，生成固定维度的稠密向量（如 768 维、1024 维、3072 维、4096 维）

向量相似度计算

Embedding 模型生成的向量通常使用余弦相似度（Cosine Similarity）或欧氏距离（Euclidean Distance）来衡量语义相似性：

相似度算法 适用场景 特点
余弦相似度 语义搜索、推荐系统 不受向量长度影响，只关注方向，值越大越相似
欧氏距离 聚类分析、异常检测 考虑绝对距离，值越小越相似
点积相似度 大规模检索 计算效率高，向量归一化后与余弦相似度等价

注意：距离与相似度的”方向”是相反的——余弦相似度、点积越大越相似，欧氏距离越小越相似。设置相似度阈值时，要与向量库实际使用的度量方式（Metric Type）保持一致。

整体流程

  1. 离线入库：文件上传 → Tika 解析为纯文本 → TokenTextSplitter 分块 → Embedding 向量化 → 写入 Milvus
  2. 在线问答：用户提问 → 检索 TopK 相关片段 → 与问题、对话历史一起组装提示词 → 大模型生成回答
