概述主从复制：准备两台（或多台）服务器，分别安装 MySQL，一台作为主数据库（Master），一台作为从数据库（Slave）。当主库上发生数据变更时，主库会把这些操作记录到二进制日志（binlog）中，从库拉取 binlog 并重新执行，从而把主库上的操作同步到从库，保证主从数据一致。 一台主数据库可以挂多台从数据库；而一台从数据库也可以作为更下游数据库的”主库”，形成级联结构。 主从复制的作用： 高可用：主库宕机时，从库可以顶上，避免服务中断 读写分离：把查询压力分摊到从库，降低主库的访问压力 备份安全：在从库上执行备份，不影响主库的读写性能 原理前面提到，主从复制依赖二进制日志（binlog）实现：主库上所有对数据有影响的操作都会被记录到 binlog。 复制过程可以概括为三步： 主库把数据变更写入二进制日志 从库的 I/O 线程（IOThread）连接主库，拉取主库的 binlog，写入从库本地的中继日志（Relay log） 从库的 SQL 线程（SQLThread）读取中继日志并重新执行，把主库的操作在从库上重放一遍 搭建 准备两台服务器，分别安装 MySQL...

错误日志错误日志是 MySQL 中最重要的一类日志，记录了 MySQL 在启动、运行、停止过程中出现的严重错误信息。当数据库出现异常无法正常使用时，应该第一时间查看这个日志。 错误日志默认开启，默认存放在 /var/log 目录下，文件名为 mysqld.log；也可以通过 log_error 系统变量查看（或指定）日志文件的位置 二进制日志二进制日志（binlog）中记录了所有会导致数据变化的操作：DDL 和 DML 语句（不记录 DQL 查询）。MySQL 8.0 起二进制日志默认开启。 注意区分：binlog 是 Server 层的逻辑日志（记录已提交的操作），用于数据恢复和主从复制；redo log 是 InnoDB 引擎层的物理日志（记录数据页的修改），用于崩溃恢复。 二进制日志文件的具体位置可以通过 log_bin 等系统变量查看 123456789101112mysql> SHOW VARIABLES LIKE '%log_bin%';+---------------------------------+----------------...
